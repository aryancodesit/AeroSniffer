# V2.6 Memory Layer V1 — Architecture

## Overview

Memory Layer V1 is a local-only, LittleFS-backed, deterministic memory system for AeroSniffer OS. It records experiential data about the creature's interactions and environment, stores it across power cycles, and influences the creature's behavior through parameter modulation — all without LLMs, cloud AI, or new hardware.

**Design principle:** Memory Layer is a *side-channel observer*. It reads the V2.5 state (g_creature, event bus) and produces a `MemorySummary` consumed by the frozen Behavior Layer V1. It never writes to g_creature. If it fails, the creature continues with V2.5 default behavior.

## Data Structures

- **MemoryRecord** (48 bytes fixed): `id`, `formed_at_ms`, `category` (episodic/familiarity/significant), `domain` (touch/security/aviation/mood/attention), `subtype`, `salience`, `strength`, `recall_count`, context snapshot, 16-byte domain union payload
- **MemorySummary** (16 bytes): output of `recall()` — domain_strength[5], counts, `ms_since_last_touch`
- **Ring buffer**: 256 × MemoryRecord = 12,288 bytes on BSS (no heap fragmentation)
- **File**: `/memories.bin` on LittleFS — 64-byte header + 12,288 bytes records + 4-byte CRC = 12,356 bytes

---

## Storage

- **Partition:** SPIFFS @ 0x00670000, 1536 KB (0.8% used = ~12 KB)
- **Format:** Fixed-size binary, CRC32-protected, double-buffered write (`.bak` → `.bin`)
- **Boot load:** Try `.bin` → fallback `.bak` → empty memory (graceful)
- **Session boundary:** -25% strength on all loaded records

## Three Memory Types

| Type | Enum | Purpose | Examples | Decay | Pruning |
|------|------|---------|---------|-------|---------|
| Episodic | MEM_CAT_EPISODIC | Specific events with timestamp/context | "tap at 14:32, mood was playful" | Half-life 3–12h per domain | Removed at strength=0 |
| Familiarity | MEM_CAT_FAMILIARITY | Frequency-weighted exposure | "taps have been frequent today" | Faster (4h half-life) | Removed at strength=0 |
| Significant | MEM_CAT_SIGNIFICANT | High-impact events (salience >= 70) | "evil twin attack" | Same as episodic | Immune to routine eviction |

---

## Memory Lifecycle

```
Formation → Dedup check → Ring buffer append → Decay (every 60s) → Prune (strength=0)
     │                                                        │
     └─── context multiplier applied ─────────────────────────┘
                    │
                    ▼
          Auto-promote to SIGNIFICANT if salience >= 70
```

- **Formation:** Per-domain conditions evaluated each tick against g_creature state
- **Deduplication:** Same (domain, subtype, <60s) boosts existing record +10 instead of creating new
- **Decay:** Exponential approximation, half-life varies per domain (3–12 hours)
- **Pruning:** Zero-strength records removed from ring buffer
- **Eviction:** When buffer full (256), evict zero-strength → oldest familiarity → lowest-strength episodic

## Behavior Modulation

Memory recall output (`MemorySummary`) is consumed by `FaceEngineClass::updateAnimations()` to modulate existing V2.5 parameters within their original min/max bounds:

| Condition | Modulation | Bound |
|-----------|-----------|-------|
| Recent touch (<30min) | engagement_drive decay × 0.80 | Float, always ≥ 0 |
| Prolonged absence (>30min, strength<10) | engagement floor +5 | Floor ≤ max engagement |
| Recent ANXIOUS mood | Saccade max reduced to 20s | [18, 30] original range |
| Recent PLAYFUL mood | Deep blink threshold lowered | [1500, 4000] original range |
| High SECURITY strength (>60) | engagement base +10 | [0, 100] original range |
| Low ALL strength (<5) | engagement decay × 1.15 (boredom) | Float, always ≥ 0 |

## Risk Register

| Risk | P | I | Mitigation |
|------|---|---|------------|
| LittleFS corruption on power loss | M | H | Double-buffered write, CRC32 fallback |
| millis() rollover breaks decay timing | L | M | Compare with subtraction, not absolute values |
| Memory bloat beyond 256 records | L | M | Fixed-size ring buffer with LRU eviction |
| Behavior modulation exceeds V2.5 bounds | L | H | All modulations clamped; no new behavior domains |
| Boot latency from LittleFS read | M | L | 12 KB read = ~5ms on ESP32-S3 SPIFFS; acceptable |
| Cross-session confusion (familiarity from prior boot) | M | M | -25% session boundary decay; stale memories fade in ~4 boots |
| TD-011 (mood timestamp dual-purpose) | H | M | Mood age queries may be inaccurate — note for Sprint 3 |
