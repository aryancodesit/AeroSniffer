# V2.4 Companion Intelligence — Architecture Document

> **Status**: Planning  
> **Target**: Feature branch `feature/v2.4-companion-intelligence`  
> **Systems frozen (do not modify)**: Security Sentinel, Threat Intelligence, Home Guard, Aviation Observer, Portal V2, Website V2  

---

## 1. Vision

AeroSniffer V2.4 transforms DeskBuddy 2.0 from a reactive event-display device into a **living desktop companion** — a creature that observes, reacts, and exists independently. The companion maintains internal drives, a circadian rhythm, long-term mood persistence, and idle behaviors that make it feel alive even when the user is away or all external events are quiet.

**Core principle**: Observe + React. The device does not need cloud, Portal, or PC connection to exhibit personality. All intelligence runs locally on the ESP32-S3.

---

## 2. Design Goals

| Goal | Description |
|------|-------------|
| **Offline-first** | Zero cloud dependencies. No PC agent required for personality. |
| **No new hardware** | Works on existing DeskBuddy 2.0 kit — touch sensor + display + ESP32-S3 only. |
| **Preserve all existing systems** | EventBus, EmotionEngine, FaceEngine, Timeline, StorageService unchanged. |
| **Procedural animation** | No BMP assets added. All new behaviors are procedurally generated geometry. |
| **Deterministic + surprising** | Drives are deterministic in decay/growth but behavior selection uses weighted randomness — same inputs never produce identical outputs. |
| **Memory without storage bloat** | Mood history, interaction quality, and habit patterns persist in NVS using ~60 bytes — no SD card or SPIFFS required. |
| **Under 5% CPU overhead** | All new logic runs at 1 Hz on Core 1 with negligible cycle cost. |

## 4. CompanionBrain

`CompanionBrain` is the central intelligence coordinator. It runs at 1 Hz on Core 1 and manages all proactive behavior of the creature.

### Architecture

```
                    ┌──────────────────────────┐
                    │     CompanionBrain        │
                    │  (runs 1 Hz, Core 1)      │
                    └──┬───────────────┬───────┘
                       │               │
              ┌────────▼──────┐  ┌─────▼──────────┐
              │ Circadian     │  │ Drive System    │
              │ Engine        │  │                 │
              │ • energy      │  │ • social        │
              │ • arousal     │  │ • exploration   │
              │ • hour        │  │ • rest          │
              └────────┬──────┘  │ • play          │
                       │         └─────┬──────────┘
              ┌────────▼───────────────▼──────┐
              │   Behavior Selector            │
              │   (weighted random from        │
              │    drive levels + energy)      │
              └────────┬──────────────────────┘
                       │
              ┌────────▼──────────────┐
              │   Mood Drift Engine   │
              │   (gradual mood shift │
              │    independent of     │
              │    external events)   │
              └────────┬──────────────┘
                       │
              ┌────────▼──────────────┐
              │   Animation Modulator │
              │   (blink rate,        │
              │    saccade, bounce,   │
              │    particles)         │
               └───────────────────────┘
```

> **Sibling subsystem**: AttentionEngine (see Section 9) runs independently from CompanionBrain. It handles event-driven attention state and gaze targeting, while CompanionBrain handles drive-driven behavior selection. FaceEngine composites both inputs each frame.

### Tick Cycle (1 Hz)

1. **CircadianEngine.tick()** — Update energy/arousal from internal clock.
2. **Drive decay** — Each drive decays/grows based on elapsed time since last relevant event.
3. **External event check** — If an event arrived since last tick, interrupt drives (reduce social drive, set mood via existing EmotionEngine handler).
4. **Behavior selection** — If no event for ≥5 seconds, select behavior from weighted random (weights from drive levels × energy).
5. **Run behavior** — Set FaceEngine state for behavior duration (1–10 seconds typically).
6. **Mood drift** — Compute gradual mood shift from energy + time + recent event history.
7. **Animation update** — Push blink rate, saccade rate, bounce, particle rate to FaceEngine.

### External Event Interruption

When an external event arrives (touch, PC activity, network discovery), CompanionBrain:
- Resets the "idle timer" to 0
- Reduces `drive_social` by 0.3 (immediate need reduction)
- Does NOT override EmotionEngine's own `handleEvent()` — the existing reactive layer handles emotion/mood/activity
- CompanionBrain's behavior selection is preempted for 5 seconds after any event (lets the reactive layer display the emotion)

## 5. Behavior Engine

### Drive System

Four internal drives (each a float 0.0–1.0):

| Drive | Builds When | Decays When | Triggers Behavior |
|-------|------------|-------------|-------------------|
| **Social** | No interaction for >2 min (0.05/min) | User interacts (-0.3 per event) | BEHAVIOR_WATCH, BEHAVIOR_FIDGET |
| **Exploration** | No network/flight events for >5 min (0.02/min) | Sniffer active, flights detected (-0.2) | BEHAVIOR_IDLE_SCAN, BEHAVIOR_LISTEN |
| **Rest** | Low energy (<0.3) + no interaction (0.1/min) | After sleep behavior runs (-0.8) | BEHAVIOR_SLEEP, BEHAVIOR_GROOM |
| **Play** | Medium energy (0.4–0.7) + idle >3 min (0.03/min) | After play behavior runs (-0.7), touch interaction (-0.2) | BEHAVIOR_PLAY, BEHAVIOR_STRETCH |

### Behavior Catalog

| Behavior | Duration | Visual | Trigger Condition |
|----------|----------|--------|-------------------|
| **BEHAVIOR_IDLE_SCAN** | 3–6 s | Eyes dart in random directions, head-panning simulation, no mouth movement | Social > 0.3, Energy > 0.4, no recent events |
| **BEHAVIOR_SLEEP** | 8–15 s | Eyes closed (blink scale ≈ 0), Zzz particles, energy-colored breathing effect | Rest > 0.6, Energy < 0.3 |
| **BEHAVIOR_STRETCH** | 2–3 s | Wide eye open, mouth open (yawn), eye scale increases 20% for 1 s | Play > 0.3, Energy > 0.5, idle > 5 min |
| **BEHAVIOR_WATCH** | 4–8 s | Fixed gaze in one direction, subtle tracking motion, no blinking | Social > 0.5, Energy > 0.4 |
| **BEHAVIOR_FIDGET** | 2–4 s | Rapid small eye movements, eyebrows twitch, subtle bounce | Social > 0.7, Energy > 0.6 |
| **BEHAVIOR_PANIC** | 3–5 s | Rapid eye darts, sweat particles, wide eyes, high blink rate | Energy > 0.7 + arousal > 0.7 + isolation > 10 min |
| **BEHAVIOR_PLAY** | 5–10 s | Continuous bounce, heart/music particles, eye crinkle (happy shape), mouth smile | Play > 0.5, Energy > 0.4 |
| **BEHAVIOR_GROOM** | 3–6 s | Slow intentional blinks, eye partially closed, no saccade, calming | Rest > 0.3, arousal < 0.3, Energy < 0.5 |
| **BEHAVIOR_LISTEN** | 3–5 s | Eyes squint, head tilt (one eye slightly higher), no bounce | Exploration > 0.4, sniffer currently inactive |
| **BEHAVIOR_YAWN** | 1–2 s | Mouth opens wide, eyes squint, followed by blink reset | Transition between energy states |

### Weighted Selection Algorithm

```
For each behavior candidate:
  baseWeight = lookupTable[behavior][currentMood]
  driveModifier = driveLevel[associatedDrive]
  energyGate = 1.0 if energy in allowedRange else 0.0
  finalWeight = baseWeight × driveModifier × energyGate

Normalize all finalWeights to 0–1
Roll random → select behavior
Apply cooldown (behavior can't repeat for 60 seconds)
```

## 6. Memory Engine

### Mood History Buffer

- Ring of 24 hour-based snapshots (stored as `uint8_t` mood type per hour)
- Saved to NVS every hour via `StorageService.setStat("ci_mh", rawBytes)` — 24 bytes
- On boot: reload last 24 hours of mood history
- Used by Mood Drift Engine to detect patterns (e.g., "user is always away at 2pm" → rest drive)

### Interaction Quality

| Metric | Storage Key | Type | Update Trigger |
|--------|-------------|------|----------------|
| Trust level | `ci_trust` | uint8_t (0–100) | Gentle touches +1, rapid taps -1, max 100 |
| Skittishness | `ci_skitt` | uint8_t (0–100) | Ignored periods +1/hr, long holds -2, max 100 |
| Bond strength | `ci_bond` | uint8_t (0–100) | Friendship/10 + trust/2, recalculated hourly |
| Total wake hours | `ci_whours` | uint16_t | +1 per hour of uptime |
| Interaction slots | `ci_slots_*` | uint8_t (24) | 24-hour ring of interaction count per hour |

Total persistent storage: 24 (mood ring) + 3 (trust/skitt/bond) + 2 (wake hours) + 24 (interaction slots) = **53 bytes NVS**.

### Personality Derivation

After ~7 days of runtime, the companion develops a persistent personality axis:

- **High trust + low skittishness** → "Secure" archetype: approaches interaction, slow to spook
- **Low trust + high skittishness** → "Nervous" archetype: avoids interaction, quick to panic
- **High trust + high skittishness** → "Complex" archetype: craves attention but easily overwhelmed
- **Low trust + low skittishness** → "Aloof" archetype: independent, indifferent to presence

Personality is not explicitly named or exposed to the user. It emerges from behavior weights that shift based on these stored values.

```
                         │    MOOD DRIFT ENGINE          │
                         │  (autonomous, 1 Hz check)     │
                         └──┬────────────────────────┬──┘
                            │                        │

              │  → Mood set to event-appropriate value     │
              │  → Mood drift paused for 5 seconds         │

              │                                            │
              │  If last 6 hours were all VIGILANT/SUSPIC- │
              │  IOUS, drift RELAXED has lower weight      │
              │  (creature stays "on edge" after threats)  │
              │                                            │
              │  If last 6 hours were all RELAXED/BORED,   │
              │  drift FOCUSED has higher weight after     │
              │  coding event (creature "wants to work")   │
              └────────────────────────────────────────────┘
```

### Mood Transition Rules (gradual drift)

| From ↓ / To → | RELAXED | FOCUSED | SUSPICIOUS | EXCITED | VIGILANT | BORED | ANXIOUS |
|---------------|---------|---------|------------|---------|----------|-------|---------|
| RELAXED | — | Energy>0.5 + coding event | — | Energy>0.7 + 10min idle | Energy>0.8 + sniffer | Energy<0.3 + 15min idle | Isolation>30min + low energy |
| FOCUSED | Energy<0.3 + 15min idle | — | Persistent threat | Energy>0.7 + social event | Sniffer event | 30min no event | — |
| SUSPICIOUS | 30min no threat + energy<0.5 | — | — | Energy>0.7 + trust event | Continued threats | — | Low energy + isolation |
| EXCITED | 15min no event | Coding event | — | — | Sniffer event | Energy<0.3 | — |
| VIGILANT | 30min no threat | — | Threat detected | — | — | — | Low energy + no threat |
| BORED | 5min after play | PC event | Network event | User tap | — | — | — |
| ANXIOUS | User interaction | — | — | — | — | — | — |

Rates of drift: mood changes are not instantaneous. Each drift check shifts the mood by 0.1 "toward" the target mood per minute. A full mood transition takes 10 minutes.

## 9. AttentionEngine

The AttentionEngine determines what the creature is paying attention to at any moment. It runs independently from CompanionBrain, driven by events rather than drives, and translates attention state into gaze coordinates and animation modulation parameters consumed by FaceEngine.

### Attention States

| State | Priority | Trigger | Duration | Gaze | Animation Modifiers |
|-------|----------|---------|----------|------|-------------------|
| ATTENTION_SOFT_FOCUS | 1 (default) | Default environment state | Indefinite | Center with micro-saccades (1–3 px every 4–8 s) | Normal blink (3–6 s), relaxed |
| ATTENTION_ACTIVE_SCAN | 2 | 30–90 s of SOFT_FOCUS, or curiosity event (EVENT_NETWORK_DISCOVERED, EVENT_DEVICE_UNKNOWN) | 10–20 s, then back to SOFT_FOCUS | Broader sweeps (6–10 px every 2–4 s) | Elevated blink rate (2–4 s) |
| ATTENTION_AVIATION | 3 | EVENT_FLIGHT_DETECTED, EVENT_FLIGHT_RARE | 12 s, then decay | Center (0, 0), elevated gaze posture | Normal blink, slightly wider eyes |
| ATTENTION_USER | 4 | EVENT_TOUCH_SHORT, EVENT_TOUCH_LONG | 4 s, then decay | Center (0, 0), single slow blink on entry | Reduced saccade, soft deliberate blink |
| ATTENTION_SECURITY | 5 (highest) | EVENT_ATTACK_DEAUTH, EVENT_ATTACK_EVILTWIN | 15 s, then decay | Center (0, 0), fixed stare, zero saccade | 0.3× blink rate, 1.2× eye width, faster shallow breath |
| ATTENTION_NONE | 0 (transitional) | Boot or mid-transition only | N/A | Center (0, 0) | Default |

### Priority and Preemption

Higher-priority attention preempts lower-priority immediately. When a higher-priority event arrives, the current attention state is discarded and replaced. When the higher-priority timer expires, the engine falls back to the next-highest state that still has a valid event timestamp. If no event timestamps are valid, the engine returns to ATTENTION_SOFT_FOCUS (the default ambient state).

Priority stack: SECURITY > USER > AVIATION > ACTIVE_SCAN > SOFT_FOCUS > NONE.

### EventBus Integration

AttentionEngine uses a single subscriber slot for all events:

- On begin(), it subscribes to all EVENT_COUNT event types via a `for (int i = 0; i < EVENT_COUNT; i++)` loop, matching the existing EmotionEngine pattern.
- The subscription callback routes to `AttentionEngine.onEvent()`, which categorizes the incoming event (user, security, aviation, or other) and records it with a timestamp.
- New event types added in the future require zero subscription changes — they are automatically captured by the loop.
- Total EventBus subscriber impact: 1 slot.

### SOFT_FOCUS / ACTIVE_SCAN Substates

The environment attention is split into two substates to prevent the hyperactive continuous scanning that would contradict the Silicon Scout's calm core trait:

**SOFT_FOCUS** (default, ~80 % of environment time):
- Long gaze holds (4–8 s between shifts)
- Micro-saccades only (< 3 px)
- Normal blink interval (3–6 s)
- Gaze returns to center between shifts
- Feel: calm, present but peripheral — the creature is aware but not hunting

**ACTIVE_SCAN** (~20 % of environment time):
- Broader gaze sweeps (6–10 px)
- More frequent shifts (2–4 s)
- Deliberate directional holds, not random darts
- Slightly elevated blink rate (2–4 s)
- Feel: purposeful searching — the creature is actively inspecting its invisible habitat

**Transitions**: SOFT_FOCUS → ACTIVE_SCAN after 30–90 s of uninterrupted SOFT_FOCUS, or immediately on curiosity-triggering events (EVENT_NETWORK_DISCOVERED, EVENT_DEVICE_UNKNOWN). Return after 10–20 s or when no scan-triggering events remain.

### Gaze Smoothing

Gaze targets are not applied immediately. FaceEngine lerps toward the target at 0.1 factor per frame (~300 ms to settle at 30 FPS):

- `currentX += (targetX - currentX) × 0.1`
- `currentY += (targetY - currentY) × 0.1`

Micro-saccades within SOFT_FOCUS add small perturbations (±1–3 px) around the current target to prevent the "frozen screen" look during long holds. These are not random darts — they are subtle drifts that preserve the illusion of life without conveying agitation.

### Animation Modulation Outputs

AttentionEngine exposes modulation values read by FaceEngine each frame:

| Output | Range | Purpose |
|--------|-------|---------|
| gazeX, gazeY | −12 to +12 px | Current lerp position toward attention target |
| blinkRateMultiplier | 0.3–1.0 | 0.3 for SECURITY (unblinking stare), 1.0 otherwise |
| eyeWidthMultiplier | 0.8–1.2 | 1.2 for SECURITY (wider alert eyes), 1.0 otherwise |
| breathRateMultiplier | 0.5–1.5 | 1.5 for SECURITY (faster shallow breath), 1.0 otherwise |

These multipliers are applied on top of FaceEngine's existing animation parameters. The behavior-defined parameters from CompanionBrain set the base; attention state overrides specific channels by multiplying the base value.

This is a key design principle: **attention does not replace behavior animation — it modulates it**. A BEHAVIOR_SLEEP with ATTENTION_SECURITY would still show closed eyes but at 0.3× blink rate and 1.2× eye width. In practice, security events are rare enough that this overlap is unlikely, but the architecture handles it correctly.

## 10. Animation Strategy

### Modulation Parameters (new on FaceEngine)

| Parameter | Range | Default | Effect |
|-----------|-------|---------|--------|
| `blinkRate` | 2–10 s interval | 3–6 s random | Lower = more frequent blinks |
| `blinkSpeed` | 0.2–1.0 closure rate | 0.4 decrement/frame | High = snap blink, low = slow droop |
| `saccadeRate` | 0.5–4 s interval | 1–4 s random | How often eyes shift gaze |
| `saccadeDistance` | 0–12 px | 6 px max | How far eyes roam from center |
| `bounceAmplitude` | 0–6 px | 0–4 px | Vertical body oscillation |
| `particleRate` | 0–2 per second | 0.5 avg | Particle spawn frequency |
| `breathAmplitude` | 0–4 px | 0 px | Subtle chest area oscillation |

### Energy-to-Animation Mapping

```
Energy 0.0 → 0.3: (Sleep/Rest)
  blinkRate = 6–10 s       (slow blinks)
  blinkSpeed = 0.2         (slow close)
  saccadeRate = 0          (no gaze movement)
  saccadeDistance = 0
  bounceAmplitude = 0
  particleRate = 0
  breathAmplitude = 2–4    (visible breathing)

Energy 0.3 → 0.6: (Calm/Default)
  blinkRate = 4–7 s
  blinkSpeed = 0.4
  saccadeRate = 2–4 s
  saccadeDistance = 4
  bounceAmplitude = 0
  particleRate = 0.2
  breathAmplitude = 0

Energy 0.6 → 0.8: (Alert/Engaged)
  blinkRate = 2–4 s
  blinkSpeed = 0.6
  saccadeRate = 1–2 s
  saccadeDistance = 8
  bounceAmplitude = 2
  particleRate = 0.5
  breathAmplitude = 0

Energy 0.8 → 1.0: (Hyper/Excited)
  blinkRate = 1–2 s
  blinkSpeed = 1.0
  saccadeRate = 0.5–1 s
  saccadeDistance = 12
  bounceAmplitude = 4–6
  particleRate = 1–2
  breathAmplitude = 0
```

### Attention State Override

AttentionEngine multipliers (blinkRateMultiplier, eyeWidthMultiplier, breathRateMultiplier) are applied on top of the energy-to-animation mapping below. For example, at Energy 0.3–0.6 with ATTENTION_SECURITY, blinkRate becomes `(4–7 s) × 0.3 = 10.5–23.3 s` and eyeWidth becomes `normal × 1.2`. Attention state can also override saccadeRate to 0 (SECURITY) regardless of energy level.

### Arousal Modifier

Arousal (0–1) acts as a multiplier on blink rate and saccade rate when energy is medium:
- High arousal + medium energy → vigilance animation (rapid micro-saccades, fast shallow blinks)
- Low arousal + medium energy → relaxed animation (slow blinks, drifting gaze)

This is the key mechanism that makes the creature look "alert" vs "calm" at the same energy level.

### Behavior Visual Signatures

Each behavior sets specific animation parameters for its duration:

| Behavior | blinkRate | saccadeRate | saccadeDist | bounce | particles | special |
|----------|-----------|-------------|-------------|--------|-----------|---------|
| IDLE_SCAN | 3s | 0.5s | 10 | 0 | 0 | Eyes use full roam range |
| SLEEP | 10s | 0 | 0 | 0 | Zzz (type 4) | Eye scale ≈ 0 |
| STRETCH | 2s (then 8s) | 0 | 0 | 0 | 0 | Eye scale 1.2x for 1s |
| WATCH | 6s | 4s pull | 2 | 0 | 0 | Constant gaze direction |
| FIDGET | 1.5s | 0.3s | 6 | 2 | 0 | Saccade pattern: quick return |
| PANIC | 0.5s | 0.2s | 12 | 4 | Sweat (type 2) | Wide eyes, full eye scale |
| PLAY | 3s | 2s | 8 | 5 | Heart (type 3) | Happy eye shape |
| GROOM | 5s | 0 | 0 | 0 | 0 | Slow blink with 0.5s hold closed |
| LISTEN | 4s | 1s | 4 (one eye) | 0 | 0 | One eye slightly higher |
| YAWN | 8s (then 3s) | 0 | 0 | 0 | 0 | Mouth open, eye squint 0.5s |

### Core 1 Timing Analysis

| Task | Frequency | Per-tick cost | Total per second |

### Idle Behavior Cost

When no external events are active and CompanionBrain runs an idle behavior, the cost is the same as any other frame — FaceEngine renders the same way regardless of what drives the input. The only difference is which animation parameters are set, which is already computed in the AnimationState update.

## 13. Future Expansion Points

The V2.4 architecture is designed for incremental expansion without refactoring.

### V2.5 — Audio Awareness (when HAS_MIC = 1)

- **I2S microphone** reads ambient audio
- `CompanionBrain` gets `EVENT_SOUND_DETECTED` with volume/spectrum data
- Loud sounds → startle behavior (PANIC variant)
- Music → drive_play increases, rhythm-synchronized bounce
- Silence → drive_social increases faster (creature feels isolated)
- Voice detection → future: bond with specific voice patterns

### V2.6 — IMU Awareness (when HAS_IMU = 1)

- **MPU-6050** detects physical orientation
- Pickup event → `EVENT_PICKED_UP` → curious emotion, then stabilization behavior
- Vibration detection (desk bump) → alert behavior
- Movement patterns → creature learns typical desk activity hours

### V2.7 — Multi-Creature Networking

- BLE advertisement broadcasts companion mood/energy
- Nearby DeskBuddy companions discover each other
- Mood sync: companions near each other converge toward similar moods
- "Pack" behavior: in Security mode, coordinated channel scanning

### V2.8 — Learning & Adaptation (personality 2.0)

- After 30 days of runtime, companion develops unique behavior frequency signature
- User may never notice, but companion has "quirks":
  - Always does STRETCH at 10am (if user always arrives at 10)
  - Gets BORED faster after typing sessions (habituation)
  - Reacts more to flights if Aviation mode was frequently used
- These emerge from the mood history + interaction quality without explicit training

### Non-goals (explicitly excluded)

- Natural language chat or speech synthesis
- Facial recognition or camera
- Cloud sync of personality
- Companion app rewrite (Website V2 is frozen)
- Bluetooth speaker / media playback
- Remote control via internet
