# V2.4 Companion Sprint Plan — FaceEngine Gaze + AttentionEngine Validation

**Sprint**: V2.4 Phase 3B–3C
**Target branch**: `feature/v2.4-companion-intelligence`
**Base tag**: `v2.4-transition-stable`

---

## Assessment

The AttentionEngine skeleton (Phase 1–3A) is implemented and OS-wired. Mode transitions are stable with the pause() spinlock removed. Three issues remain gated behind this sprint: the `udp_new_ip_type` assertion (B004), the Aviation HTTPS failure (B007), and the `netstack` error (B006). None of these block the core Phase 3B objective — wiring AttentionEngine state into FaceEngine gaze — because they only manifest during HTTP fetch or Security→Aviation netif transitions. By keeping weather fetch and Aviation HTTPS disabled during this sprint, we decouple gaze integration from networking risk and validate the complete Observe→Render pipeline with touch events alone.

**Key architectural principle — Device = Observe, Portal = Act, Cloud = Analyze:**
- AttentionEngine and FaceEngine both live in the Device layer (ESP32 firmware)
- AttentionEngine *observes* events (touch, WiFi, security, flights) to decide gaze direction
- FaceEngine *renders* the creature face, consuming gaze targets from AttentionEngine
- Portal (companion web UI at `aerosniffer.html`) handles user-facing controls and telemetry display
- Cloud layer is not in scope for V2.4
- **Do not** push attention state or face render data to Portal during this sprint
- **Do not** add cloud ingestion or analytics endpoints
- All gaze integration stays on-device

## 3. Phase 3B Objectives

### 3B.1 — FaceEngine Gaze API

**Add to `FaceEngineClass` in `AeroSnifferOS.h`:**

```cpp
void setGazeTarget(int x, int y);   // -6..+6, -4..+4 pixel offset from centre
int  getGazeX() const;
int  getGazeY() const;
```

- `setGazeTarget()` writes `anim_look_x`, `anim_look_y`
- `getGazeX()` / `getGazeY()` expose current offset for logging/debug
- No mutex — gaze is written only from Core 1, read only from Core 1 render path

**Gaze override semantics:**
- When `setGazeTarget()` is called, the manual target persists for a configurable duration (default 3000 ms)
- After expiry, fall back to random gaze behaviour (existing `random()` logic in `updateAnimations()`)
- Store `anim_look_target_x`, `anim_look_target_y`, `anim_look_target_deadline` as new private members
- `updateAnimations()` checks deadline: if `now > deadline`, resume random gaze

**Update `updateAnimations()` in `AeroSnifferOS.cpp`:**
```
before:  if (now > anim_look_next) { set random, reset timer }
after:   if (now > anim_look_target_deadline) { (fall through to random) }
         if (now > anim_look_next && no active target) { set random, reset timer }
```

**Emotion override:**
- Gaze target is respected regardless of emotion type
- Exception: SURPRISED forced centre (no gaze offset, pupils fixed in large circles)
- HAPPY/SLEEPY have no pupils to offset, but `anim_look_x/y` are still set for future transitions

### 3B.2 — Wire AttentionEngine → FaceEngine Gaze

**In `AttentionEngineClass` context API (new public methods in `AttentionEngine.h`):**

```cpp
// Called by Core 1 tick() after processing events
int  recommendedGazeX() const;   // gaze target based on current state
int  recommendedGazeY() const;
```

Gaze mapping from attention state:

| Attention State | Gaze X | Gaze Y | Rationale |
|----------------|--------|--------|-----------|
| `SOFT_FOCUS` | 0 | 0 | Centre — relaxed, no focus |
| `WATCHING` | 0 | -2 | Slightly up — alert, curious |
| `THREAT_LOCK` | 0 | 0 | Centre dead ahead — intense focus |

**In `AeroSniffer.ino` task_core1(), uncomment and extend the tick block:**

```cpp
uint32_t ae_delta = now - last_ae_tick;
last_ae_tick = now;
AttentionEngine.tick(ae_delta);
// Drive gaze from attention state
FaceEngine.setGazeTarget(
  AttentionEngine.recommendedGazeX(),
  AttentionEngine.recommendedGazeY()
);
```

This runs at ~60 Hz (16 ms vTaskDelay), same as frame rendering. Gaze target is computed fresh every tick.

### 3B.3 — Render Changes

**In `FaceEngineClass::renderEmotionLayer()` (`AeroSnifferOS.cpp` ~line 653):**

- Default eye branch: `anim_look_x/y` already used as pupil offset. No changes needed.
- SURPRISED branch: pupils are at fixed centre. Leave as-is (gaze offset not rendered).
- HAPPY, SLEEPY branches: no pupils. Leave as-is.
- **Result**: only the default eye shape (CALM, SAD, ANGRY, CURIOUS, LOVE, EXCITED, ALERT) reflects gaze. This is correct — gaze attention is most expressive on these emotions.

**Clamp bounds in `setGazeTarget()`:**

```cpp
anim_look_x = constrain(x, -6, 6);
anim_look_y = constrain(y, -4, 4);
```

### 3B.4 — Acceptance Criteria

1. FaceEngine exposes `setGazeTarget(x, y)`, `getGazeX()`, `getGazeY()`
2. Gaze target persists for 3000 ms then decays to random
3. AttentionEngine `SOFT_FOCUS` → centre (0,0)
4. AttentionEngine `WATCHING` → up-centre (0,-2)
5. AttentionEngine `THREAT_LOCK` → centre (0,0)
6. Gaze updates at ~60 Hz from Core 1 render loop
7. No crashes, WDTs, or assertion failures during gaze switching
8. SURPRISED emotion renders centre pupils regardless of gaze target
9. HAPPY, SLEEPY emotions render without pupils (unchanged)

## 4. AttentionEngine Validation Tests (Phase 3C)

**Objective**: Enable `AttentionEngine.tick()`, inject touch events, and verify state transitions on serial.

### 4.2 — Verify Subscriptions

Currently 7 subscriptions in `AeroSniffer.ino:665-671`:
- `EVENT_ATTACK_DEAUTH` (P1 — threat)
- `EVENT_ATTACK_EVILTWIN` (P1 — threat)
- `EVENT_FLIGHT_DETECTED` (P3 — watch)
- `EVENT_WIFI_CONNECTING` (P4 — background)
- `EVENT_WIFI_CONNECTED` (P4 — background)
- `EVENT_USER_TAP` (P2 — attention via `ae_event_callback`)
- `EVENT_WIFI_DISCONNECTED` (P4 — background)

**Need to add** (touch events are published from `poll_touch_input()`):
- `EVENT_TOUCH_SHORT` (P2 — matches priority in `eventPriority()`)
- `EVENT_TOUCH_LONG` (P2 — matches priority in `eventPriority()`)
- `EVENT_FLIGHT_RARE` (P3 — watch, higher priority than regular flight)

Note: `EVENT_USER_TAP` is separate from `EVENT_TOUCH_SHORT`. Check which events `poll_touch_input()` actually publishes, and subscribe to the correct ones.

### 4.3 — Touch-Driven State Test

```
1. Boot into Pet mode (SOFT_FOCUS)
2. Single tap → queue EVENT_TOUCH_SHORT (P2)
3. Next tick() → state transition: SOFT_FOCUS → WATCHING
4. Serial confirms: [ATTN] SOFT_FOCUS -> WATCHING (TOUCH_SHORT)
5. Wait 3 seconds → decay fires: [ATTN] WATCHING -> SOFT_FOCUS (decay)
6. Repeat 10 times, verify no missed transitions or stale state
```

### 4.4 — Priority Preemption Test

```
1. Boot into Pet mode (SOFT_FOCUS)
2. Tap → P2 → WATCHING
3. Immediately tap again → P2 → stays WATCHING (same priority, no change)
4. Wait for WATCHING→SOFT_FOCUS decay
5. Simulate deauth event (P1) → THREAT_LOCK
6. Tap (P2) while in THREAT_LOCK → stays THREAT_LOCK (P2 > P1, no preemption)
7. Wait for THREAT_LOCK decay (8s) → SOFT_FOCUS
8. Serial confirms full chain: SOFT_FOCUS → THREAT_LOCK → SOFT_FOCUS
```

### 4.5 — Event Overflow Test

```
1. Queue 17+ events rapidly (overflow QUEUE_SIZE=16)
2. Verify [ATTN] transitions fire for the highest-priority event
3. Verify no crash, no infinite loop
4. Check overflow stats (Serial command if implemented)
```

### 4.6 — Mode Switch + Pause/Resume

```
1. Mode switch Pet→Security (triggers pause)
2. While paused, tap repeatedly (events discarded)
3. Mode switch completes (triggers resume, resetState)
4. Verify state is SOFT_FOCUS after resume
5. Verify no stale events from pre-pause queue
```

### 4.7 — Acceptance Criteria

1. All state transitions log to serial with `[ATTN]` prefix
2. Decay timings match spec: P1=8000ms, P2=3000ms, P3=5000ms, P4=2500ms
3. THREAT_LOCK preempts all lower priorities
4. Overflow does not crash
5. Pause/resume resets state cleanly
6. No WDT during any test (interrupt or task)
7. Gaze updates correctly per attention state (visible on face)

## 5. FaceEngine Integration Strategy

### Layer Boundaries

```
Device Layer (Observe):
  ┌─────────────────────────────────────────────────────────┐
  │  Event Sources               → AttentionEngine          │
  │  (touch, WiFi, security,     (observes, decides gaze)   │
  │   aviation, flight)                                     │
  │                              ↓                           │
  │                         FaceEngine                      │
  │                         (renders gaze via pupils)       │
  │                              ↓                           │
  │                         DisplayService                  │
  │                         (commits to TFT)                │
  └─────────────────────────────────────────────────────────┘
                                                           
Portal Layer (Act):
  ┌─────────────────────────────────────────────────────────┐
  │  Companion Web UI (aerosniffer.html)                    │
  │  Displays telemetry, user controls                      │
  │  Reads creature state via serial JSON protocol          │
  └─────────────────────────────────────────────────────────┘

Cloud Layer (Analyze):
  (Not in scope for V2.4)
```

### Data Flow

```
poll_touch_input()
  └─→ EventBus.publish(EVENT_TOUCH_SHORT)
        └─→ ae_event_callback()
              └─→ AttentionEngine.queueEvent(EVENT_TOUCH_SHORT)
                    └─→ [_queue ring buffer, Core 0 or Core 1]

task_core1() loop [~60 Hz]:
  └─→ AttentionEngine.tick(delta)
  │     └─→ drain queue
  │           └─→ state transition (if priority threshold met)
  │           └─→ decay check
  │
  └─→ FaceEngine.setGazeTarget(
  │     AttentionEngine.recommendedGazeX(),
  │     AttentionEngine.recommendedGazeY()
  │   )
  │     └─→ anim_look_x/y set, timer started
  │
  └─→ EmotionEngine.tick()
  │
  └─→ FaceEngine.updateAnimations(frame)
  │     └─→ if gaze target expired: random look
  │     └─→ else: respect setGazeTarget values
  │
  └─→ FaceEngine.render(spr, frame)
        └─→ renderEmotionLayer → pupils at anim_look_x/y
        └─→ renderActivityLayer → mouth, status
        └─→ renderEffectLayer → particles
```

### Implementation Order

1. **Add gaze API** to FaceEngineClass (header + impl)
2. **Add gaze override logic** to `updateAnimations()` (deadline-based fallback)
3. **Add context getters** to AttentionEngineClass (`recommendedGazeX/Y()`)
4. **Wire tick() → setGazeTarget()** in AeroSniffer.ino
5. **Enable tick()** (uncomment lines 574–576)
6. **Add missing subscriptions** (EVENT_TOUCH_SHORT, EVENT_TOUCH_LONG, EVENT_FLIGHT_RARE)
7. **Validate** — run Phase 3C tests (4.3–4.7)
8. **Hardware test** — mode switch cycles, touch interaction, visual gaze check

### What Not To Do

- Do not push attention/face data to Portal serial protocol
- Do not add cloud endpoints or analytics
- Do not add persistence for gaze state
- Do not add FaceEngine getters for pupil position to Portal protocol
- Do not redesign EmotionEngine, EventBus, or mode switching
- Do not re-enable weather fetch or Aviation HTTPS during this sprint
- Do not change CreatureState struct
