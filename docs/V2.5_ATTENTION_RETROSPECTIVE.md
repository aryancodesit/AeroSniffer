## 3. Bugs Found

### Bug 1 — EventBus Subscriber Exhaustion

| Field | Value |
|-------|-------|
| **File** | `AeroSnifferOS.h:44` |
| **Fix** | `MAX_SUBSCRIBERS 24 → 32` |
| **Root cause** | EmotionEngine subscribed to all 22 event types, leaving only 2 free slots. `AttentionEngine` registered 7 subscriptions — only `ATTACK_DEAUTH` and `ATTACK_EVILTWIN` landed; `EVENT_TOUCH_SHORT` and all others were silently dropped. |
| **Symptoms** | Touch events never reached the AttentionEngine. No `[ATTN]` transitions on tap. Decay never fired. |
| **Lesson** | EventBus capacity is a coupling vector between subsystems. Adding a new subscriber requires auditing total slot usage. Consider a compile-time assertion or dynamic growth for the next bus revision. |

### Bug 2 — Spinlock Initialization (Root Cause of IWDT Reboots)

| Field | Value |
|-------|-------|
| **Files** | `Companion/AttentionEngine.h:54` |
| **Fix** | `portMUX_TYPE _mux = {}` → `portMUX_TYPE _mux = portMUX_INITIALIZER_UNLOCKED` |
| **Root cause** | The brace-initializer `= {}` did not set the correct unlocked bit pattern for the ESP32-S3 spinlock on all ESP-IDF versions. The first `portENTER_CRITICAL(&_mux)` found the lock in a locked/invalid state and spun forever with interrupts disabled. The IWDT fired after ~560ms on Core 1. |
| **Symptoms** | Touch → IWDT reboot. Only in Pet mode (the only mode that routes touch through EventBus). Security and Aviation modes handled touch locally and never hit the spinlock path — this made the bug look like a Pet-mode-specific issue rather than an infrastructure bug. |
| **Lesson** | Always use the canonical initializer macro for ESP-IDF primitives. `= {}` is not guaranteed to produce the correct unlocked state for `portMUX_TYPE`. |

### Bug 3 — Serial Inside Critical Section

| Field | Value |
|-------|-------|
| **File** | `AttentionEngine.cpp:queueEvent()` |
| **Fix** | Removed `Serial.println()` from inside `portENTER_CRITICAL()` |
| **Root cause** | UART TX on Core 1 can block if the TX buffer is full. Inside a critical section with interrupts disabled, this hangs the core. |
| **Lesson** | No I/O inside critical sections. Ever. |

## 4. Key Discoveries

### Touch Routing Divergence (Why Pet Mode Rebooted, Security Didn't)

Critical discovery that isolated Bug 2:

| Mode | Touch handler | Routes through EventBus? |
|------|---------------|------------------------|
| **Pet** | `pet_core1_task()` line 145 | ✅ `EventBus.publish(EVENT_TOUCH_SHORT)` |
| **Security** | `portal_core1_task()` | ❌ Toggles `sec_hud_mode` locally |
| **Aviation** | `aviation_core1_task()` | ❌ Toggles `avi_hud_mode` locally |

Only **Pet mode** published touch events through EventBus, which is the path that triggered the AttentionEngine spinlock. Security and Aviation never hit the spinlock path, so they never crashed — making Bug 2 look like a Pet-mode issue rather than the infrastructure bug it was.

### Three-Bug Co-Dependency

No single bug explained all symptoms in isolation:

1. **Subscriber overflow** (Bug 1) hid the spinlock bug because AE events never reached the lock acquisition.
2. **Spinlock init** (Bug 2) caused the IWDT that made the device reboot before attention transitions could be logged.
3. **Serial in critical section** (Bug 3) could have caused UART deadlocks on top of the spinlock spin.

All three had to be fixed together for the system to stabilize.

## 5. Known Limitations

| Limitation | Impact | Future work |
|------------|--------|-------------|
| Discrete gaze levels (-1, -2, -3) instead of smooth interpolation | Visible step changes during decay on 240×240 display | Replace with lerp-based gaze when Portal-visible coordinates are needed |
| `SOFT_FOCUS → SOFT_FOCUS (decay)` log noise | Spurious transition log when internal events (WiFi, mode switch) decay with `TARGET_NONE` | Guard `resetToIdle()` log to only print when `old != _state` |
| No per-priority habituation | Repeated events at same priority reset strength to full value | Sprint 4+ — habituation counters per priority level |
| No mood/emotion integration | Attention works in isolation — creature gaze is mechanical, not emotional | Sprint 3 — Mood Layer |
| Attention state not persisted across reboot | Creature forgets what it was watching | Future — NVS-backed state |

## 6. Lessons Learned

1. **Validate new architecture before removing the old.** Sprint 2A (FaceEngine migration) ran in parallel with the V2.4 shim for exactly this reason. When the new path passed hardware testing, the old path became dead code with zero risk.

2. **Always use canonical initializer macros on ESP-IDF.** `portMUX_INITIALIZER_UNLOCKED` is the documented way. `= {}` is not equivalent on all versions.

3. **A bug that only reproduces in one mode is often a systemic bug that only that mode's code path triggers.** Security/Aviation not crashing was not proof of robustness — it was proof of a different code path.

4. **Three small bugs can mask each other.** Each fix alone still left a broken system. Only fixing all three produced a stable result. Serial log analysis was essential to untangle which symptom came from which cause.

5. **Embedded debugging is path tracing, not component testing.** The IWDT looked like an EmotionEngine or Timeline logging bug because those ran on the same core tick. Only tracing the exact call chain (touch → EventBus → queueEvent → spinlock) revealed the real root cause.

## 8. Architecture Decisions Preserved

These decisions were made deliberately during V2.5 development. Recording the rationale so future-you doesn't waste time rediscovering them.

| Decision | Rationale | Alternative rejected |
|----------|-----------|---------------------|
| `AttentionSource` is a standalone enum, not derived from `EventType` | EventType is a transport detail (EventBus). AttentionSource is a semantic category. Deriving one from the other creates coupling — adding a new event type would force attention mapping changes. Separate enums let each evolve independently. | Derive attention source from EventType via a lookup table |
| FaceEngine owns gaze coordinates | AttentionEngine decides *where to look* (target + strength), FaceEngine decides *how to render it* (pixel coordinates, blink rate, bounce). Keeping pixel math in the render layer preserves the Device = Observe / React separation. Gaze coordinates are a rendering detail, not part of the attention data model. | Emit `gaze_x`/`gaze_y` from AttentionEngine directly |
| `_acquired_ms` is private to AttentionEngine | The precise timestamp of attention acquisition is an implementation detail of the decay algorithm. External consumers (FaceEngine, Portal) only need the derived `strength` value. Exposing timestamps would create a dependency on millis() semantics outside the AttentionEngine. | Make `acquired_ms` part of the `attention` struct in `CreatureState` |
| Fixed-point integer decay (no floating point) | Floating point on ESP32-S3 is emulated (no hardware FPU). Fixed-point integer math with three decay zones is deterministic, faster, and avoids edge cases with NaN/inf. The three-zone model (fast/medium/slow) produces a visually acceptable decay curve without division or trig. | `float` decay with exponential curve |
| `Device = Observe` / `Portal = Act` / `Cloud = Analyze` preserved | Attention runs entirely on-device. Portal reads state but does not influence attention decisions. Cloud analytics (future) are read-only consumers. Keeps the device operational even when WiFi is disconnected — a core AeroSniffer requirement since V1. | Offload attention decisions to Portal or Cloud |
| Pause/resume lifecycle via `_paused` flag, no event draining | Pausing discards new events but preserves queued ones. On resume, `resetToIdle()` clears state and the queue drains naturally on the next `tick()`. Simpler than drain-on-pause (which would need a spinlock in the pause path — the root cause of B005). | Drain the queue during `pause()` |
| Single-consumer lock-free queue drain | `tick()` is the sole consumer on Core 1. Producers (queueEvent on either core) write under spinlock. Consumer reads without locking because producer and consumer never touch the same index. This design eliminates the IWDT from B005b. | Spinlock in both producer and consumer |
