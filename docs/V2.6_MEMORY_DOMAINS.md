## Salience Normalization

### Principle

All domains share the same 0-100 salience range. Values are **normalized** so that no single domain inherently dominates the memory ring buffer. The range ceilings are:

| Band | Range | Touch Ref | Security Ref | Aviation Ref | Mood Ref |
|------|-------|-----------|-------------|-------------|----------|
| Routine | 15-29 | TAP (22) | DEVICE_APPEARED (25) | AIRCRAFT (22) | RELAXED (25) |
| Notable | 30-44 | DOUBLE (30), HOLD (22-35) | SUSPICIOUS (38) | — | PLAYFUL (28), ANXIOUS (35), TRANSITION (30) |
| Significant | 45-59 | BURST (45) | THREAT (50) | UNUSUAL (42) | — |
| Critical | 60+ | — | — | — | — |

**Touch domain ref** (Sprint 2 certified): TAP=22, DOUBLE=30, HOLD=22-35, LONG_HOLD=30-45, BURST=45.

### Cross-domain rule

No Sprint 3 subtype shall exceed salience 55 without explicit review. THREAT at 50 is the Sprint 3 maximum — it outranks BURST (45) but does not dwarf it. This keeps the ring buffer diverse across domains.

### source_id

Every `MemoryRecord` gains a `uint32_t source_id` field in Sprint 3. This identifies the source entity of the memory without requiring full metadata in the per-domain payload.

| Domain | source_id usage |
|--------|-----------------|
| TOUCH | 0 (entityless — touch is a gesture, no source identity) |
| SECURITY | Hashed device identifier (low-bits of MAC or derived ID) |
| AVIATION | ICAO24 (24-bit identifier, stored in uint32_t) |
| MOOD | 0 (entityless — mood state has no external source) |

Purpose: Enables Sprint 4 cross-domain recall queries like "have I seen this aircraft before?" or "has this device appeared before?" without parsing per-domain payloads.

## Domain 2 — DOMAIN_SECURITY (1)

**Purpose:** Remember meaningful security experiences. Security subtypes represent experiences, not raw events. SecurityEngine decides when an event is noteworthy by publishing events; MemoryEngine maps those events to experiential subtypes.

**Principle:** If it is not meaningful, no memory forms. Security memory has three tiers: device appearances, suspicious patterns, and confirmed threats. Routine ambient activity (single deauth, scan results) does not form memory.

| Subtype | Value | Meaning | Base Salience |
|---------|-------|---------|---------------|
| SEC_DEVICE_APPEARED | 0x10 | A device appeared on the network — new, returning, or switching connectivity | 25 |
| SEC_SUSPICIOUS_ACTIVITY | 0x11 | Unusual pattern detected (multiple deauths, probe scans, elevated rate) | 38 |
| SEC_THREAT_DETECTED | 0x12 | Active attack confirmed (evil twin, deauth burst >= 5 in 60s) | 50 |

**Data payload (16 bytes):**
```cpp
struct {
  uint8_t  threat_level;     // 0-100, from SecurityEngine assessment
  uint8_t  event_count;      // count since last dedup reset
  uint8_t  _pad[14];
} security;
```

**source_id:** `MemoryRecord.source_id` is the single source of truth for device identity. No duplicate hash in payload.

**Dedup window:** 300s (5 min) — security events are episodic. A burst is one incident, not 30 separate memories. Resets after window expires.

**Half-life:** 12h — threats persist. A deauth burst from this morning is still relevant this evening.

**Event sources:**
- `EVENT_ATTACK_DEAUTH` → 2-4 in 60s: SUSPICIOUS_ACTIVITY, >= 5: THREAT_DETECTED. Single deauth in isolation → no memory (routine, not an experience).
- `EVENT_ATTACK_EVILTWIN` → THREAT_DETECTED (immediate, bypasses window)
- `EVENT_DEVICE_TRUSTED` / `EVENT_DEVICE_FAMILIAR` → DEVICE_APPEARED
- `EVENT_DEVICE_UNKNOWN` → DEVICE_APPEARED
- `EVENT_NETWORK_DISCOVERED` → no memory (routine scan result, not an experience)

**Not memory-worthy:** Every beacon frame, every probe request, a single deauth in isolation, scan cycle results, a known device reconnecting within its normal pattern.

## Domain 3 — DOMAIN_AVIATION (2)

**Purpose:** Remember meaningful aviation observations — what the creature has seen, whether the sky was busy or quiet. Not every OpenSky update.

**Note:** AVI_HIGH_TRAFFIC_WINDOW is deferred to Sprint 4. A hardcoded threshold (e.g., 8 flights in 10 min) would be wrong in airport vs rural areas. Sprint 4 adds baseline statistics for relative comparison.

| Subtype | Value | Condition | Base Salience |
|---------|-------|-----------|---------------|
| AVI_AIRCRAFT_SPOTTED | 0x20 | Standard aircraft detected via OpenSky | 22 |
| AVI_QUIET_SKY_PERIOD | 0x21 | No aircraft seen for >= 30 min | 16 |
| AVI_UNUSUAL_TRAFFIC_EVENT | 0x22 | Rare flight (`is_rare==true`) or extreme altitude (< 1000 ft or > 45000 ft) | 42 |

**Data payload (16 bytes):**
```cpp
struct {
  uint32_t icao24;          // ICAO 24-bit aircraft identifier (0 if N/A)
  int16_t  altitude_ft;     // -1 = unknown, valid range 0-60000
  uint8_t  is_rare;         // 0/1
  uint8_t  _pad[9];
} aviation;
```

Total: 4 + 2 + 1 + 9 = 16 bytes.

**Dedup window:** 180s (3 min) — prevents duplicate records for the same aircraft (same ICAO24) while allowing distinct flights to form separate records.

**Half-life:** 4h — aviation observations are transient. Yesterday's flights are rarely relevant today.

**Event sources:**
- `EVENT_FLIGHT_DETECTED` → AVI_AIRCRAFT_SPOTTED (or AVI_UNUSUAL if extreme altitude)
- `EVENT_FLIGHT_RARE` → AVI_UNUSUAL_TRAFFIC_EVENT
- No flight events in 30+ min → AVI_QUIET_SKY_PERIOD (checked in observe(), not event-driven)

**Not memory-worthy:** Every aircraft update (position, velocity, heading). Only the first detection matters.

## Domain 4 — DOMAIN_MOOD (3)

**Purpose:** Remember emotional history, not current mood. The mood engine knows the present; memory knows the past. No changes to MoodEngine.

| Subtype | Value | Condition | Base Salience |
|---------|-------|-----------|---------------|
| MOOD_LONG_RELAXED_PERIOD | 0x30 | Same mood was MOOD_RELAXED for >= 30 min | 25 |
| MOOD_LONG_PLAYFUL_PERIOD | 0x31 | Same mood was MOOD_PLAYFUL for >= 30 min | 28 |
| MOOD_LONG_ANXIOUS_PERIOD | 0x32 | Same mood was MOOD_ANXIOUS for >= 30 min | 35 |
| MOOD_TRANSITION | 0x33 | Mood type changed (any direction) | 30 |

**Data payload (16 bytes):**
```cpp
struct {
  uint8_t  mood;             // current MoodType (0=RELAXED, 1=PLAYFUL, 2=ANXIOUS)
  uint8_t  prev_mood;        // previous MoodType before transition (0xFF if N/A)
  uint16_t duration_min;     // how long the previous mood lasted (minutes)
  uint8_t  _pad[12];
} mood_event;
```

**Dedup window for MOOD_TRANSITION:** None. Transitions are always meaningful — RELAXED→PLAYFUL→RELAXED within 15 min is two distinct episodes, not duplicates.

**Dedup window for MOOD_LONG_*:** 6 hours (safety net). Prolonged mood subtypes are primarily gated by the per-mood period lock. The 6-hour dedup window is a second line of defense: if a bug causes `mood_last_period_type_` to reset while the creature is still in the same mood, duplicate formation is caught.

**Half-life:** 8h — mood history matters for a full waking day. Yesterday's anxiety is today's context.

**Event sources:**
- MoodEngine writes `g_creature.mood` — MemoryEngine observes it in `tick()` by comparing current vs last-known mood
- MOOD_LONG_RELAXED/PLAYFUL/ANXIOUS_PERIOD: checked in `observe()` — if mood has been unchanged for >= 30 min, form the corresponding period record
- MOOD_TRANSITION: formed on the tick where mood changes

**Not memory-worthy:** Every mood tick (100ms). Every emotion change. Mood is the slow observer — memory of mood should be equally slow.

## MemoryRecord Layout (Sprint 3)

```
Offset  Size  Field
─────────────────────────────────────────
 0       4    id                (monotonic, per-session)
 4       4    source_id         (ICAO24, device hash, or 0)
 8       4    formed_at_ms
12       1    category          (MEM_CAT_EPISODIC only in Sprint 3)
13       1    domain            (DOMAIN_TOUCH / SECURITY / AVIATION / MOOD)
14       1    subtype           (domain-specific enum value)
15       1    salience          (0-100)
16       1    strength          (0-100, decays over time)
17       1    recall_count
18       1    mood_at_formation
19       1    attention_at_form
20       1    mode_at_formation
21       1    padding
22       2    alignment padding (to 4-byte boundary for union)
24      16    data union        (touch / security / aviation / mood_event)
─────────────────────────────────────────
40      total bytes per record
```

64 records × 40 bytes = 2560 bytes on BSS.

Verify with `static_assert(sizeof(MemoryRecord) == 40)` before implementation.

## Formation Pipeline (Sprint 3)

```
tick()
  → snapshot g_creature state
  → observe():
      TOUCH domain     → drain PendingTouch buffer (unchanged)
      SECURITY domain  → check EventBus flags, deauth window
      AVIATION domain  → check ICAO24 dedup, quiet sky timer
      MOOD domain      → check mood vs last_known_mood
  → decay()
  → prune()
```

Memory observes. It does not control. No MoodEngine changes. No AttentionEngine changes. No FaceEngine changes.
