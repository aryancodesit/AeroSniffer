# V2.7.3 — Behavioral Calibration Plan (Reduced Scope)

## Calibration Philosophy

Calibration exists to validate and refine existing behavioral heuristics, not redesign behavior. Constants are changed only when repeated hardware measurements demonstrate stable, reproducible deviation from the intended design. Behavioral consistency is prioritized over numerical optimization.

## 3. Macro Interface

### 3.1 Design

Single header, two macros. Zero code when `CALIBRATION` undefined.

```cpp
// Companion/Calibration.h
#pragma once

// ── Calibration Macros ────────────────────────────────────────────
// Define CALIBRATION to enable. Compiles to nothing otherwise.
//
// CALIB(tag, value)
//   Logs a measurement point unconditionally.
//   Output: C,<tag>,<value>\n
//
// CALIB_RATE(tag, value, rate_ms)
//   Logs at most once per rate_ms interval. Tag must be unique per
//   call site (uses __LINE__ to generate static throttle state).
//   Output: C,<tag>,<value>\n
//
// value is cast to int. Float: use (int)(val * 1000) and divide in post.

#ifdef CALIBRATION
  #include <Arduino.h>
  #define CALIB(tag, val)           Serial.printf("C,%s,%d\n", tag, (int)(val))
  #define CALIB_RATE(tag, val, r)   do { \
    static uint32_t _cl ## __LINE__ = 0; \
    uint32_t _cn = millis(); \
    if (_cn - _cl ## __LINE__ >= (r)) { \
      _cl ## __LINE__ = _cn; \
      Serial.printf("C,%s,%d\n", tag, (int)(val)); \
    } \
  } while(0)
#else
  #define CALIB(tag, val)
  #define CALIB_RATE(tag, val, r)
#endif
```

### 3.2 Instrumentation Points

Clock domains:
  • Latency events use micros() — sub-ms resolution for cross-event deltas.
  • Periodic/rate-limited metrics use millis() — behavior-over-time values.
  • Never subtract micros() from millis() or vice versa.

```
Boot (AeroSniffer.ino setup()):
    CALIB_STR("boot", "fw=" FW_VERSION " git=" GIT_HASH " board=" BOARD_NAME)

Main render loop (AeroSniffer.ino):
    uint32_t _t0 = micros();
    // ... all tick() calls ...
    CALIB_RATE("loop_us", (int)(micros() - _t0), 1000)  // 1 Hz

BehaviorEngine::tick():
    CALIB_RATE("engage_lvl", (int)(_engagement_level * 10), 500)   // 2 Hz, millis()-based
    CALIB_RATE("modifier",   _mood_modifier, 1000)                  // 1 Hz, millis()-based
    CALIB_RATE("engage_floor", _engagement_floor, 1000)             // 1 Hz, millis()-based
    CALIB("ts_touch_beh", micros())     // on engagement reset (latency endpoint)
    CALIB("ts_engage_write", micros())  // after canonical write-back, line 67

MoodEngine::tick():
    CALIB_RATE("mood_str", _strength, 1000)     // 1 Hz, millis()-based
    CALIB("ts_touch_mood", micros())   // on SOURCE_TOUCH rising edge (latency start)

AttentionEngine::tick():
    CALIB("ts_threat_attn", micros())  // on transition to THREAT_LOCK (latency endpoint)

MemoryEngine::onSecurityEvent():
    CALIB("ts_attack", micros())       // on EVENT_ATTACK_DEAUTH/EVILTWIN (latency start)

MemoryEngine::tick():
    CALIB_RATE("rec_count", record_count_, 60000)            // 1/min, millis()-based

MemoryEngine::decay():
    CALIB_RATE("dom_touch", recall().domain_strength[DOMAIN_TOUCH], 60000)  // 1/min
    CALIB_RATE("dom_sec",   recall().domain_strength[DOMAIN_SECURITY], 60000)
```

### 3.3 Observer Effect

- 2 Hz `CALIB_RATE` calls + 1 Hz loop_us: ~40 μs/tick at 30 fps = 0.13% overhead
- `CALIB` calls are event-triggered (not per-tick): negligible
- `CALIB_RATE(..., 60000)`: 1/min = unmeasurable
- Format strings avoid `%f` — no printf float library pulled in

## 4. Latency Measurements

All latency timestamps use `micros()` (single clock domain). Periodic/rate-limited metrics in §3 use `millis()`. Never subtract values from different clocks.

### 4.1 Touch → Behavior

| Stage | Instrument | What |
|-------|--------|------|
| Start | MoodEngine rising edge detection | `CALIB("ts_touch_mood", micros())` at `recordTouch()` call |
| End | BehaviorEngine engagement reset | `CALIB("ts_touch_beh", micros())` when `_engagement_level = 100.0f` |

**Decision**: Report P50/P95. No adjustment — latency is bound by frame rate.

### 4.2 Threat → Attention

| Stage | Instrument | What |
|-------|--------|------|
| Start | MemoryEngine::onSecurityEvent() | `CALIB("ts_attack", micros())` on EVENT_ATTACK_DEAUTH/EVILTWIN |
| End | AttentionEngine::tick() | `CALIB("ts_threat_attn", micros())` on state transition to THREAT_LOCK |

**Decision**: Report P50/P95. No adjustment — cross-core delivery time is a scheduler property.

### 4.3 Behavior → Face

Architecture constraint: FaceEngine must remain presentation-only. No instrumentation inside render().

| Stage | Instrument | What |
|-------|--------|------|
| Start | BehaviorEngine canonical write-back | `CALIB("ts_engage_write", micros())` after line 67 |
| End | FaceEngine reads g_creature.engagement_drive | Delta = frame-end micros minus ts_engage_write. Stamped in AeroSniffer.ino after FaceEngine.render() returns. |

**Decision**: Report P50/P95. Bound by frame rate (~33 ms at 30 fps). The measurement occurs at the behavior/presentation interface (g_creature), not inside FaceEngine. Derive delta from loop_us epoch stamps. Documentation only.

### 4.4 Loop Execution Time

| Measurement | Instrument | What |
|-------------|--------|------|
| Per-tick render loop duration | Main loop in AeroSniffer.ino | `CALIB_RATE("loop_us", micros() - t0, 1000)` wrapping all engine tick() calls |

**Decision**: Report avg/max over 10 min soak. If max > 30 ms (90% of frame budget), flag for V2.8 optimization. Not a calibration target — diagnostics only.

### 9.1 Assessment

**Scope is appropriate for V2.7.3.** The original plan proposed 18 measured candidates and 32 UX tuning constants — far too broad for a calibration-only release. This reduced plan:

- **Freezes 52/65 constants** (80%) — no change, no risk
- **Measures only 3** — each gated by repeated-run variance (range/mean < 0.10)
- **Observes 10** — passive data collection for V2.8 planning
- **Adds 4 latency/performance measurements** — fills gaps in telemetry
- **2 macros only** — `CALIB` and `CALIB_RATE`, minimal surface area
- **6-phase implementation** — smoke → infrastructure → instrumentation → soak → adjustment → freeze

| `MAX_EVENTS_PER_TICK (A2, 8)` | WDT guard | Core 1 watchdog reset during event storms |
| `QUEUE_SIZE (A1, 16)` | Hardware constraint | Event queue overflow → lost events |
| `Mood transition strength (M1, 50)` | Design invariant | Unequal rise/decay headroom |

### 9.4 Serial Logging and Timing Distortion

| Concern | Analysis | Verdict |
|---------|----------|---------|
| `Serial.printf` in ISR context | **Not used**. All CALIB calls in tick() context (Core 1 loop, not Core 0 ISRs). | Safe |
| `Serial.printf` causing WDT | Max 2 Hz × ~15 μs = 30 μs/tick = 0.09%. WDT threshold is typically 1-10 s. | Safe |
| UART TX buffer full blocking | ESP32 hardware UART has 128-byte TX FIFO + software buffer. At 2 lines/s (avg 40 bytes) = 80 B/s. 115200 baud = 11.5 KB/s capacity. | Safe — 0.7% utilization |
| Timing jitter from `millis()` call | `millis()` is a register read on ESP32 (FreeRTOS tick count). ~0.2 μs. | Negligible |
| Float formatting pulling in `%f` | Not used. `CALIB` casts to `int`. `engagement_level` logged as `(int)(val * 10)`. | No printf float dependency |

**Conclusion**: Serial logging at this rate cannot distort behavioral timing. The overhead is below the noise floor of FreeRTOS task scheduling jitter (±1 ms on ESP32).

### 9.8 Final Go / No-Go

**Go**, unconditionally.

The reduced scope is:
- **Surgical**: 3 constants measured, at most 3 may change (B1, M8, M9)
- **Guarded by variance**: No constant changes unless repeated-run variance < 10% and mean excludes current value
- **Reversible**: Each adjustment is its own commit
- **Observable**: 4 new telemetry metrics (3 latencies + loop time)
- **Smoke-tested**: Phase 0 gate catches infrastructure failures before any soak
- **Traceable**: All evidence stored in `docs/CALIBRATION/raw/` + `docs/CALIBRATION/reports/`
- **Safe**: 0.13% timing overhead, no ISR usage, no `%f`, no heap
- **Minimal**: 2 macros, 1 new file, < 25 lines of instrumentation across all engines
