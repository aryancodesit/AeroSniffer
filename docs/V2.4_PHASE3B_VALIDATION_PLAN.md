# Phase 3B — Attention Validation Plan

**Goal**: Prove AttentionEngine state machine produces correct transitions on hardware.
**Architecture freeze**: Queue implementation is frozen. Infrastructure sprint is complete.

| Event | Priority | Maps To State | Source | Frequency |
|-------|----------|---------------|--------|-----------|
| `EVENT_ATTACK_DEAUTH` | P1 | THREAT_LOCK | Security Sniffer | Burst |
| `EVENT_ATTACK_EVILTWIN` | P1 | THREAT_LOCK | Security EvilTwin | Burst |
| `EVENT_TOUCH_SHORT` | P2 | WATCHING | Mode1_Pet (tap) | On tap |

## 2. State Transition Matrix

### From SOFT_FOCUS (default, no active priority)

| Incoming Event | Priority | Transition | Decay |
|----------------|----------|------------|-------|
| P1 (deauth/evil-twin) | 1 | THREAT_LOCK | 8000 ms |
| P2 (touch) | 2 | WATCHING | 3000 ms |
| P3 (flight) | 3 | WATCHING | 5000 ms |
| P4 (wifi) | 4 | WATCHING | 2500 ms |

### From WATCHING (active priority 2–4)

| Incoming Event | Priority | Transition | Condition |
|----------------|----------|------------|-----------|
| P1 (deauth) | 1 | THREAT_LOCK | `pri(1) <= active(2)` → **preempts** |
| P2 (touch) | 2 | stays WATCHING | `pri(2) <= active(2)` → same priority, no state change but extends deadline |
| P3 (flight) | 3 | stays WATCHING | `pri(3) > active(2)` → **ignored** |
| P4 (wifi) | 4 | stays WATCHING | `pri(4) > active(2)` → **ignored** |
| Decay timeout | — | SOFT_FOCUS | `now >= _decay_deadline` |

### From THREAT_LOCK (active priority 1)

| Incoming Event | Priority | Transition | Condition |
|----------------|----------|------------|-----------|
| P1 (deauth) | 1 | stays THREAT_LOCK | `pri(1) <= active(1)` → extends deadline |
| P2 (touch) | 2 | stays THREAT_LOCK | `pri(2) > active(1)` → **ignored** |
| P3 (flight) | 3 | stays THREAT_LOCK | `pri(3) > active(1)` → **ignored** |
| P4 (wifi) | 4 | stays THREAT_LOCK | `pri(4) > active(1)` → **ignored** |
| Decay timeout | — | SOFT_FOCUS | 8000 ms after last P1 event |

### Full Transition Diagram

```
                         P1 (preempt)
  SOFT_FOCUS ──────────────────────────────> THREAT_LOCK
      │                                          │
      │ P2/P3/P4                                 │ decay (8000ms)
      │                                          │
      v                                          v
  WATCHING ── P1 (preempt) ──> THREAT_LOCK    SOFT_FOCUS
      │
      │ decay (3000–5000ms)
      v
  SOFT_FOCUS
```

## 3. Decay Timer Table

| Active Priority | Decay Duration | Triggering Events |
|----------------|----------------|-------------------|
| 1 (THREAT) | 8000 ms | deauth, evil-twin |

## 4. Hardware Test Plan

### Setup
- Flash current `v2.4-stable-runtime`
- Open serial monitor at 115200 baud
- Confirm boot log: `[ATTN] begin -> SOFT_FOCUS`

### Test 1 — Touch → WATCHING (P2)

| Step | Action | Expected Serial Output |
|------|--------|----------------------|
| 1.1 | Single tap | `[ATTN] SOFT_FOCUS -> WATCHING (TOUCH_SHORT)` |
| 1.2 | Wait 4 seconds | `[ATTN] WATCHING -> SOFT_FOCUS (decay)` |
| 1.3 | Repeat 5 times | Same output each time |

**Pass**: All 5 cycles produce correct transition + decay.
**Fail**: No transition logged, wrong state, WDT, or hang.

### Test 2 — Priority Preemption (P1 > P2)

| Step | Action | Expected Serial Output |
|------|--------|----------------------|
| 2.1 | Tap | `SOFT_FOCUS -> WATCHING (TOUCH_SHORT)` |
| 2.2 | Trigger deauth* | `WATCHING -> THREAT_LOCK (ATTACK_DEAUTH)` |
| 2.3 | Tap again | No transition (P2 ignored while THREAT_LOCK) |
| 2.4 | Wait 10 seconds | `THREAT_LOCK -> SOFT_FOCUS (decay)` |

*\*Deauth can be triggered by running a deauth attack nearby, or via Security mode scanning. If no deauth source available, verify with evil-twin toggle in Security mode.*

**Pass**: P1 preempts P2. P2 ignored during THREAT_LOCK. Decay returns to SOFT_FOCUS.
**Fail**: P2 overrides THREAT_LOCK, or THREAT_LOCK persists beyond 10s.

### Test 3 — Priority Cascade (P4 → P2 → P1 → P3 ignored)

| Step | Action | Expected Serial Output |
|------|--------|----------------------|
| 3.1 | Turn WiFi off/on | `SOFT_FOCUS -> WATCHING (WIFI_DISCONNECTED or WIFI_CONNECTED)` |
| 3.2 | Tap | `WATCHING -> WATCHING` (same state, no log, but deadline extended) |
| 3.3 | Trigger deauth | `WATCHING -> THREAT_LOCK (ATTACK_DEAUTH)` |
| 3.4 | Trigger flight (if in Aviation) | No transition (P3 > P1, ignored) |

**Pass**: Cascade follows priority correctly. Lower-priority events during higher state are silently ignored.
**Fail**: Any event overrides a higher-priority state.

### Test 4 — Queue Overflow + Burst

| Step | Action | Expected Behavior |
|------|--------|------------------|
| 4.1 | Tap rapidly 20 times in 2 seconds | No crash. At most 8 events processed per frame. State becomes WATCHING. |
| 4.2 | Wait 5 seconds | Decays to SOFT_FOCUS |
| 4.3 | Verify serial | No WDT, no assert, no hang |

**Pass**: System survives burst without crash. State reaches correct final state.
**Fail**: WDT, hang, assert, or state stuck in wrong value.

### Test 5 — Pause/Resume Isolation

| Step | Action | Expected Serial Output |
|------|--------|----------------------|
| 5.1 | Long press → mode switch | `[ATTN] pause (was SOFT_FOCUS)` |
| 5.2 | Tap during splash screen | No transition logged (events discarded) |
| 5.3 | Mode setup completes | `[ATTN] resume -> SOFT_FOCUS` |
| 5.4 | Tap in new mode | `SOFT_FOCUS -> WATCHING (TOUCH_SHORT)` |

**Pass**: Events during pause are discarded. State is SOFT_FOCUS after resume.
**Fail**: Stale event processed after resume, or state not reset.

### Test 6 — Multi-Mode Transition (5 cycles)

| Step | Action | Expected Serial Output |
|------|--------|----------------------|
| 6.1 | Cycle Pet→Security→Aviation→Pet | Each mode boots with `[ATTN] begin -> SOFT_FOCUS` (first time) or `[ATTN] resume -> SOFT_FOCUS` |
| 6.2 | Tap in each mode | `SOFT_FOCUS -> WATCHING (TOUCH_SHORT)` |
| 6.3 | Wait for decay | `WATCHING -> SOFT_FOCUS (decay)` |
| 6.4 | Repeat 5 times | Same pattern each cycle |

**Pass**: No WDT, no stale state, no missed transitions across 5 full mode cycles.
**Fail**: Any crash, stuck state, or incorrect transition.

## 5. Risks

| Risk | Impact | Likelihood | Mitigation |
|------|--------|------------|------------|
| No deauth source for Test 2 | Can't verify P1 preemption | Medium | Use evil-twin toggle in Security mode as P1 alternative |
| `EVENT_TOUCH_LONG` never published | P2 only from short tap | Always | Not a blocker — touch short is sufficient for P2 validation |
| WDT from undiscovered contention | Crash during testing | Low | Already fixed — queue audit confirmed safe |
| Gaze not visible without Phase 3C | Can't see attention on face | Always | Validate via serial only; Phase 3C enables visual feedback |
| P3/P4 events don't fire in Pet mode | Can't test flight/wifi priority | Medium | Initiate WiFi connect/disconnect manually; or switch to Aviation mode for flight events |

- Test 6: Multi-mode transitions (5 cycles)
