## 3. Bugs Found

### Bug 1 — EventBus Subscriber Exhaustion

| Field | Value |
|-------|-------|
| **File** | `AeroSnifferOS.h:44` |
| **Fix** | `MAX_SUBSCRIBERS 24 → 32` |
| **Root cause** | EmotionEngine subscribed to all 22 event types, leaving only 2 free slots. `AttentionEngine` registered 7 subscriptions — only `ATTACK_DEAUTH` and `ATTACK_EVILTWIN` landed; `EVENT_TOUCH_SHORT` and all others were silently dropped. |
| **Symptoms** | Touch events never reached the AttentionEngine. No `[ATTN]` transitions on tap. Decay never fired. |
| **Lesson** | EventBus capacity is a coupling vector between subsystems. Adding a new subscriber requires auditing total slot usage. Consider a compile-time assertion or dynamic growth for the next bus revision. |

### Bug 2 — Spinlock Initialization (Root Cause of IWDT Reboots)

| Field | Value |
|-------|-------|
| **File** | `Companion/AttentionEngine.h:54` |
| **Fix** | `portMUX_TYPE _mux = {}` → `portMUX_TYPE _mux = portMUX_INITIALIZER_UNLOCKED` |
| **Root cause** | The brace-initializer `= {}` did not set the correct unlocked bit pattern for the ESP32-S3 spinlock on all ESP-IDF versions. The first `portENTER_CRITICAL(&_mux)` found the lock in a locked/invalid state and spun forever with interrupts disabled. The IWDT fired after ~560ms on Core 1. |
| **Symptoms** | Touch → IWDT reboot. Only in Pet mode (the only mode that routes touch through EventBus). Security and Aviation modes handled touch locally and never hit the spinlock path — this made the bug look like a Pet-mode-specific issue rather than an infrastructure bug. |
| **Lesson** | Always use the canonical initializer macro for ESP-IDF primitives. `= {}` is not guaranteed to produce the correct unlocked state for `portMUX_TYPE`. |

### Bug 3 — Serial Inside Critical Section

| Field | Value |
|-------|-------|
| **File** | `AttentionEngine.cpp:queueEvent()` |
| **Fix** | Removed `Serial.println()` from inside `portENTER_CRITICAL()` |
| **Root cause** | UART TX on Core 1 can block if the TX buffer is full. Inside a critical section with interrupts disabled, this hangs the core. |
| **Lesson** | No I/O inside critical sections. Ever. |

### Bug 4 — Interrupt WDT During Mode Transition (B005)

| Field | Value |
|-------|-------|
| **File** | `Companion/AttentionEngine.h` / `AttentionEngine.cpp` |
| **Fix** | Removed spinlock from `pause()`. `_paused` flag alone is sufficient — `queueEvent()` discards events while paused, `tick()` returns early. |
| **Root cause** | `AttentionEngine.pause()` called `portENTER_CRITICAL(&_mux)` on Core 1 while Core 0 held the same spinlock in `queueEvent()`. Core 1 spun with interrupts masked, tripping the 300ms Interrupt WDT. |
| **Lesson** | A pause/resume path should never acquire a lock that a concurrent producer may hold. If the consumer must stop, the producer can be told to discard via a flag. |

### Bug 5 — `MoodEngine.cpp` not compiled (B003 pattern repeat)

| Field | Value |
|-------|-------|
| **File** | `MoodEngine.cpp` in `Companion/` |
| **Fix** | Moved to sketch root |
| **Root cause** | Arduino IDE only compiles `.cpp` files in sketch root and `src/`, not arbitrary subdirectories |
| **Lesson** | Same as B003 — keep implementation files in sketch root or `src/` for Arduino IDE compatibility |

### Bug 6 — `MoodEngine::moodName()` syntax error

| Field | Value |
|-------|-------|
| **File** | `AeroSniffer.ino:340` |
| **Fix** | `MoodEngine::moodName()` → `MoodEngine.moodName()` (dot notation on global instance) |
| **Root cause** | `::` requires a class/namespace; dot notation on the extern global instance is correct. |
| **Lesson** | Verify instance vs. static call syntax after refactoring from inline to class-based. |

### Bug 7 — `pruneOldTouches()` unsigned underflow

| Field | Value |
|-------|-------|
| **File** | `MoodEngine.cpp` |
| **Fix** | `now - 300000` → `(now - _touch_timestamps[i]) <= 300000` |
| **Root cause** | When uptime < 5 minutes, `now - 300000` wraps under uint32 (~4.29B), deleting all touches. |
| **Lesson** | Rollover-safe comparisons for all timer-based window operations. |

### Bug 8 — PLAYFUL emotion condition too strict

| Field | Value |
|-------|-------|
| **File** | `MoodEngine.cpp` |
| **Fix** | Added `_last_positive_emotion` timestamp, 60s recency window |
| **Root cause** | Required continuous HAPPY/EXCITED for 30s, but emotions last ~5s before decaying to IDLE. The hold-off would never complete. |
| **Lesson** | Emotion lifetimes (~5s) and mood hold-off (30s) operate on different timescales. Entry conditions must use recency windows, not instantaneous state. |

### Bug 9 — Mood strength decay cumulative

| Field | Value |
|-------|-------|
| **File** | `MoodEngine.cpp` |
| **Fix** | `_last_mood_change += steps * interval` instead of `_strength -= elapsed / interval` every tick |
| **Root cause** | Every tick recomputed `elapsed / interval` and subtracted from `_strength`, draining 50 units in ~40 frames instead of ~30 minutes. |
| **Lesson** | Fixed-point decay must advance the reference timestamp by consumed intervals, not recompute from absolute time each frame. |

## 4. Key Discoveries

### Touch Routing Divergence (Why Pet Mode Rebooted, Security Didn't)

Critical discovery that isolated Bug 2:

| Mode | Touch handler | Routes through EventBus? |
|------|---------------|------------------------|
| **Pet** | `pet_core1_task()` line 145 | ✅ `EventBus.publish(EVENT_TOUCH_SHORT)` |
| **Security** | `portal_core1_task()` | ❌ Toggles `sec_hud_mode` locally |
| **Aviation** | `aviation_core1_task()` | ❌ Toggles `avi_hud_mode` locally |

Only **Pet mode** published touch events through EventBus, which is the path that triggered the AttentionEngine spinlock. Security and Aviation never hit the spinlock path, so they never crashed — making Bug 2 look like a Pet-mode issue rather than the infrastructure bug it was.

### Three-Bug Co-Dependency (Attention Layer)

No single bug explained all symptoms in isolation:

1. **Subscriber overflow** hid the spinlock bug because AE events never reached the lock acquisition.
2. **Spinlock init** caused the IWDT that made the device reboot before attention transitions could be logged.
3. **Serial in critical section** could have caused UART deadlocks on top of the spinlock spin.

All three had to be fixed together for the system to stabilize.

### PLAYFUL Entry Triple-Bug Co-Dependency (Mood Layer)

Similar to the Attention Layer co-dependency, three bugs had to be fixed together before PLAYFUL would ever trigger:

1. **Touch underflow** (Bug 7) — all touches pruned immediately, so `_touch_count >= 2` was never true.
2. **Emotion strictness** (Bug 8) — 30s of continuous HAPPY/EXCITED was impossible with 5s emotion lifetimes.
3. **Decay accumulation** (Bug 9) — even if PLAYFUL entered, strength drained to 0 in ~40 frames.

Fixing any one in isolation still left PLAYFUL non-functional.

### Mood is Subtle on 240×240 Display

Sprint 3B confirmed that blink interval, bounce amplitude, and eye wander changes are technically correct but perceptually subtle on a small procedural face. The pipeline is correct; the visual payoff belongs to future behavioral layers (Memory, Companion Behaviors).

## 7. Lessons Learned

1. **Validate new architecture before removing the old.** Sprint 2A (FaceEngine migration) ran in parallel with the V2.4 shim for exactly this reason. When the new path passed hardware testing, the old path became dead code with zero risk.

2. **Always use canonical initializer macros on ESP-IDF.** `portMUX_INITIALIZER_UNLOCKED` is the documented way. `= {}` is not equivalent on all versions.

3. **A bug that only reproduces in one mode is often a systemic bug that only that mode's code path triggers.** Security/Aviation not crashing was not proof of robustness — it was proof of a different code path.

4. **Three small bugs can mask each other.** The Attention Layer had a triple-bug co-dependency. The Mood Layer had its own triple-bug co-dependency. In both cases, each fix alone still left a broken system. Only fixing all three produced a stable result.

5. **Embedded debugging is path tracing, not component testing.** The IWDT looked like an EmotionEngine or Timeline logging bug because those ran on the same core tick. Only tracing the exact call chain (touch → EventBus → queueEvent → spinlock) revealed the real root cause.

6. **Emotion and Mood operate on different timescales.** Emotion lives seconds; Mood lives hours. Entry conditions that cross timescales must use recency windows, not instantaneous state — otherwise the slower layer can never meet the faster layer's persistence requirement.

7. **Fixed-point decay must advance the reference timestamp by consumed intervals, not recompute from absolute time.** Recomputing `elapsed / interval` every tick produces cumulative subtraction that drains in seconds instead of minutes.

8. **Mood consumption on a 240×240 display is inherently subtle.** The architecture is correct, but the perceptual payoff requires behavioral layers (Memory, Companion Behaviors) that change what the creature *does*, not just how it *animates*.

## 8. Architecture Decisions Preserved

| Decision | Rationale | Alternative Rejected |
|----------|-----------|---------------------|
| `AttentionSource` is a standalone enum, not derived from `EventType` | EventType is a transport detail (EventBus). AttentionSource is a semantic category. Deriving one from the other creates coupling. | Derive attention source from EventType via a lookup table |
| FaceEngine owns gaze coordinates | AttentionEngine decides *where to look* (target + strength), FaceEngine decides *how to render it*. Keeping pixel math in the render layer preserves the Observe/React separation. | Emit `gaze_x`/`gaze_y` from AttentionEngine directly |
| `_acquired_ms` is private to AttentionEngine | External consumers only need the derived `strength` value. Exposing timestamps creates a dependency on `millis()` semantics outside the AttentionEngine. | Make `acquired_ms` part of the `attention` struct |
| Fixed-point integer decay (no floating point) | ESP32-S3 has no hardware FPU. Fixed-point is deterministic, faster, avoids NaN/inf. | `float` decay with exponential curve |
| Device = Observe / Portal = Act / Cloud = Analyze | Attention runs entirely on-device. Portal reads state but does not influence decisions. Keeps device operational without WiFi. | Offload attention decisions to Portal or Cloud |
| Pause/resume via `_paused` flag, no event draining | Simpler than drain-on-pause (which caused B005). Pre-pause events drain naturally on next `tick()`. | Drain the queue during `pause()` |
| Single-consumer lock-free queue drain | `tick()` is sole consumer. Producer writes with spinlock. Consumer reads without locking — producer and consumer never touch the same index. | Spinlock in both producer and consumer |
| Mood observes, does not control | MoodEngine reads CreatureState after Attention+Emotion publish. No EventBus access, no spinlocks, no cross-core writes. | MoodEngine writes attention or emotion fields |
| One-way data flow: Attention → Emotion → Mood → Face | No feedback loops. Mood cannot change attention or emotion. Emotion cannot change attention. Each layer depends only on the layer above it. | Mood → Emotion feedback, Mood → attention feedback |
| `eye_intensity` applies to idle wander only | Attention-driven gaze (THREAT/USER/FLIGHT) is reactive behavior triggered by external stimuli — should produce the same response regardless of mood. Mood colors internal/expressive behavior only. | Apply eye_intensity to all gaze including attention targets |
| Switch-based `profileFor(MoodType)` instead of indexed arrays | Adding a new mood requires one new `case`, not parallel array maintenance. Unknown/future moods degrade gracefully to RELAXED. | Indexed `BLINK_MS[m]`, `AMP[m]` arrays |
