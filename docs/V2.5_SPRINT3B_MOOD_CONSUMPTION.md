# V2.5 Sprint 3B — Mood Consumption Specification

## Purpose

Mood affects visual presentation **only**. MoodEngine remains the sole writer of `g_creature.mood` and `g_creature.mood_strength`. FaceEngine reads mood state to modulate blink timing, idle animation, and eye movement intensity. No mood generation, no persistence, no portal telemetry, no AI behavior, no memory integration.

## Dependency Order (Locked)

```
Attention
    ↓
Emotion
    ↓
Mood
    ↓
Face
```

One-way data flow. No feedback loops. No cross-layer writes.

## Inputs

| Field | Source | Units |
|-------|--------|-------|
| `g_creature.mood` | MoodEngine (write) | `MoodType` enum |
| `g_creature.mood_strength` | MoodEngine (write) | `uint8_t` (0–50) |

## Outputs (FaceEngine Internal)

| Parameter | Effect | Per-Mood Default |
|-----------|--------|------------------|
| `blink_interval_ms` | Time between blinks | 4000 (RELAXED), 3000 (PLAYFUL), 2200 (ANXIOUS) |
| `idle_amplitude` | Sway/bounce magnitude | 1.0 (RELAXED), 1.5 (PLAYFUL), 0.5 (ANXIOUS) |
| `idle_speed` | Animation speed multiplier | 1.0 (RELAXED), 1.3 (PLAYFUL), 0.8 (ANXIOUS) |
| `eye_intensity` | Gaze movement range | 1.0 (RELAXED), 1.4 (PLAYFUL), 0.6 (ANXIOUS) |

### Strength Scaling

All parameters interpolate from mood_strength=0 (baseline=RELAXED defaults) to mood_strength=50 (full mood expression) using **smoothstep** for perceptually even transitions:

```
t = strength / 50.0f
eased = t × t × (3.0 - 2.0 × t)
value = relaxed_default + (mood_delta × eased)
```

Where `mood_delta` is the difference between the mood's target value and the RELAXED default. Smoothstep prevents the flat mid-range feel of linear interpolation — changes near 0 and 50 are gradual, changes near 25 are most visible.

**Lazy recomputation**: modifiers recompute only when `g_creature.mood` or `g_creature.mood_strength` changes. FaceEngine renders every frame; MoodEngine updates every ~10-20ms tick; mood changes on hour scale. No reason to recompose every frame.

### Mood Profiles

#### RELAXED (Default)
| Parameter | Value |
|-----------|-------|
| blink_interval_ms | 4000 |
| idle_amplitude | 1.0 |
| idle_speed | 1.0 |
| eye_intensity | 1.0 |

Baseline behavior. Strength is not used for RELAXED (no decay).

#### PLAYFUL
| Parameter | Value at str=50 | Delta from RELAXED |
|-----------|-----------------|-------------------|
| blink_interval_ms | 3000 (-1000) | Faster blinks |
| idle_amplitude | 1.5 (+0.5) | Bouncier |
| idle_speed | 1.3 (+0.3) | Quicker animation |
| eye_intensity | 1.4 (+0.4) | Wider gaze range |

#### ANXIOUS
| Parameter | Value at str=50 | Delta from RELAXED |
|-----------|-----------------|-------------------|
| blink_interval_ms | 2200 (-1800) | Noticeably twitchier |
| idle_amplitude | 0.5 (-0.5) | Reduced sway |
| idle_speed | 0.8 (-0.2) | Slower/tighter |
| eye_intensity | 0.6 (-0.4) | Narrower gaze range |

## Implementation Plan

### Phase 1 — FaceEngine Modifier Fields

Add to `FaceEngineClass`:

```cpp
// Mood-derived presentation modifiers
void applyMoodModifiers();
uint32_t moodBlinkInterval() const;
float    moodIdleAmplitude() const;
float    moodIdleSpeed() const;
float    moodEyeIntensity() const;
```

Store computed values as member fields. Recompute only when `g_creature.mood` or `g_creature.mood_strength` changes — not every tick.

### Phase 2 — Consume in Render Loop

Replace hardcoded blink timing and animation parameters with mood-derived values:

```
- blink_interval_ms = moodBlinkInterval()
- idle_amplitude   *= moodIdleAmplitude()
- idle_speed       *= moodIdleSpeed()
- gaze_range       *= moodEyeIntensity()
```

### Phase 3 — Validation

| Test | Expected |
|------|----------|
| RELAXED at str=50 | Default blink, sway, gaze |
| PLAYFUL at str=50 | Faster blinks, bouncier, wider gaze |
| ANXIOUS at str=50 | Rapid blinks, reduced sway, narrow gaze |
| Strength=0 on any mood | Same as RELAXED defaults |
| Strength transition (50→0) | Smoothstep interpolation, no perceptual flat spots |

## Non-goals

| Feature | Defer To |
|---------|----------|
| Mood persistence (NVS) | Future Memory Layer |
| Mood → Emotion feedback | Explicit rejection (V2.5 architecture) |
| Mood portal telemetry | V2.6+ |
| Mood-generated AI behavior | Future behavioral system |
| Mood cloud sync | Future cloud layer |

## Exit Criteria

1. [ ] FaceEngine reads `g_creature.mood` and `g_creature.mood_strength`
2. [ ] Blink, idle amplitude, idle speed, and eye intensity respond to mood
3. [ ] Strength interpolation is smooth (no sudden jumps)
4. [ ] RELAXED mood matches current behavior (no regression)
5. [ ] All three mood profiles visually distinct on hardware
6. [ ] No new EventBus subscriptions
7. [ ] No new spinlocks
8. [ ] No cross-core writes

## Risks

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| Mood profile overlap at low strength | Moderate | Hardware validation must confirm mood readability at str=10, 25, 50. If PLAYFUL at str=10 is indistinguishable from RELAXED, raise baseline deltas. |
| Smoothstep still feels wrong on hardware | Low | Fall back to linear or try cubic bezier |
| Blink interval change feels jarring on transition | Very Low | Cross-fade blink interval over 2-3 cycles |
| ANXIOUS reduced sway conflicts with existing idle logic | Low | Multiply, don't replace — existing logic still runs |
| Scope creep into mood generation or persistence | Moderate | Lock non-goals list. Sprint 3B is consumer-only. |
