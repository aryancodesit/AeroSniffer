# V2.6 Memory Formation Rules

## Overview

Memory formation in V2.6 is a deterministic, rule-based process. Each tick of `MemoryEngine.tick()` evaluates the current `g_creature` state snapshot against a set of domain-specific formation conditions. When a condition is met, a record is formed with a computed salience value. Duplicate events in rapid succession are coalesced to prevent memory flooding.

---

## Formation Pipeline (per tick)

```
1. Snapshot g_creature state → local copy
2. For each domain (TOUCH, SECURITY, AVIATION, MOOD, ATTENTION):
   a. Evaluate formation conditions (see per-domain rules below)
   b. If condition met: compute base_salience
   c. Apply context multipliers (see taxonomy doc)
   d. Check deduplication (see below)
   e. If duplicate found: boost existing record +10 salience, skip formation
   f. If no duplicate: evict LRU if ring buffer full, append new record
3. Update familiarity counters
4. Optionally promote to SIGNIFICANT if salience >= 70
```

## Per-Domain Formation Conditions

### DOMAIN_TOUCH (0)

**Formation triggers:**
- TOUCH_TAP: `EVENT_TOUCH_SHORT` fired (debounced press/release)
- TOUCH_DOUBLE: Two TOUCH_TAP events within 500ms
- TOUCH_HOLD: Press event with duration > 2000ms
- TOUCH_BURST: >= 5 taps detected in sliding 10s window
- TOUCH_LONG_HOLD: Press event with duration > 10000ms

**Sliding window:**
```cpp
// Keeps last 8 tap timestamps. Maintained as a circular buffer in MemoryEngine.
// On each TOUCH_SHORT event:
//   history[history_idx++ % 8] = millis()
//   count = number of entries in [now - 10000, now]
//   if count >= 5: form TOUCH_BURST
```

**Familiarity condition:**
- If total_taps_today (from g_creature.interactions_today) crosses multiples of 10 (10, 20, 30...)
- Form `MEM_CAT_FAMILIARITY` record with salience = 15 + (crossing_number × 5), capped at 60

### DOMAIN_SECURITY (1)

**Formation triggers:**
- SEC_DEAUTH_SINGLE: `EVENT_ATTACK_DEAUTH` fired
- SEC_DEAUTH_BURST: >= 5 deauth events in 60s sliding window
- SEC_EVILTWIN: `EVENT_ATTACK_EVILTWIN` fired
- SEC_WIFI_CONNECT: `EVENT_WIFI_CONNECTED` fired
- SEC_WIFI_DISCONNECT: `EVENT_WIFI_DISCONNECTED` fired (if not user-initiated)

**Burst detection:**
```cpp
// Maintains deauth_count and deauth_window_start (millis).
// On EVENT_ATTACK_DEAUTH:
//   if (millis() - deauth_window_start > 60000):
//     reset window
//   deauth_count++
//   if deauth_count >= 5: form SEC_DEAUTH_BURST, reset counter
```

**Familiarity condition:**
- If deauth_burst_count this session crosses 3, 6, 10...
- Form `MEM_CAT_FAMILIARITY` record with salience = 20 + (crossing × 5), capped at 70

### DOMAIN_AVIATION (2)

**Formation triggers:**
- AVI_FLIGHT_DETECTED: `EVENT_FLIGHT_DETECTED` fired
- AVI_RARE_FLIGHT: `EVENT_FLIGHT_RARE` fired
- AVI_HIGH_ALTITUDE: Flight detected with altitude > 35000 ft
- AVI_LOW_ALTITUDE: Flight detected with altitude < 5000 ft
- AVI_DENSE_TRAFFIC: >= 10 flights detected in 5min sliding window

**Dense traffic detection:**
```cpp
// Maintains flight_count and flight_window_start (millis).
// On EVENT_FLIGHT_DETECTED:
//   if (millis() - flight_window_start > 300000):
//     reset window
//   flight_count++
//   if flight_count >= 10: form AVI_DENSE_TRAFFIC, reset counter
```

**Familiarity condition:**
- If flights_today (from g_creature.flights_seen_today) crosses 10, 25, 50...
- Form `MEM_CAT_FAMILIARITY` record with salience = 10 + (crossing × 5), capped at 50

### DOMAIN_MOOD (3)

**Formation triggers:**
- MOOD_TRANSITION: `g_creature.mood` changed since last tick
- MOOD_PROLONGED: `g_creature.mood` unchanged for > 30 minutes (checked every 60s)
- MOOD_RAPID_CYCLE: Mood changed twice within 600s window
- MOOD_EXTREME: `g_creature.mood_strength > 80` on any tick

**Rapid cycle detection:**
```cpp
// Maintains mood_change_count and cycle_window_start (millis).
// On mood change:
//   if (millis() - cycle_window_start > 600000):
//     reset window, count = 0
//   mood_change_count++
//   if mood_change_count >= 2:
//     form MOOD_RAPID_CYCLE, reset
```

**Familiarity condition:**
- If mood transitions this session (accumulated count) crosses 5, 10, 20...
- Form `MEM_CAT_FAMILIARITY` record with salience = 15 + (crossing × 3), capped at 45

### DOMAIN_ATTENTION (4)

**Formation triggers:**
- ATTN_SHIFT: `g_creature.attention.target` changed since last tick
- ATTN_LOCK: Same target for > 60s (checked every 60s)
- ATTN_RAPID: Target changed >= 3 times within 30s window
- ATTN_DISENGAGE: Target changed to NONE from any non-NONE value

**Rapid shift detection:**
```cpp
// Maintains shift_count and shift_window_start (millis).
// On attention target change:
//   if (millis() - shift_window_start > 30000):
//     reset window, count = 0
//   shift_count++
//   if shift_count >= 3:
//     form ATTN_RAPID, reset
```

**Familiarity condition:**
- If total attention shifts this session crosses 10, 25, 50...
- Form `MEM_CAT_FAMILIARITY` record with salience = 10 + (crossing × 3), capped at 40

## Deduplication Rules

Two records are considered "duplicates" when:

```
same_domain && same_subtype && formed within same 60s window
```

Handling:
- **If duplicate found:** increment existing record's `salience` by +10 (capped at 100) and extend its `formed_at_ms` to current time. Do NOT create a new record.
- **If NOT duplicate:** create new record as normal.

**Exception — Significant records:**
- A record already labeled `MEM_CAT_SIGNIFICANT` is never overwritten by a non-significant duplicate.
- If the new event's salience >= 70, it replaces the old significant record (salience = new value, formed_at = now).

**Exception — Familiarity records:**
- Familiarity records are never deduplicated (each crossing threshold is unique).
- Instead, the existing familiarity record for a domain is updated in-place with the new salience value and timestamp.

---

## Eviction Policy

When the ring buffer is full (256 records):

**Eviction order (first match wins):**
1. Zero-strength records (strength == 0)
2. Oldest MEM_CAT_FAMILIARITY record (by formed_at_ms)
3. Lowest-strength MEM_CAT_EPISODIC record
4. Oldest MEM_CAT_EPISODIC record

**Protected — never evicted:**
- MEM_CAT_SIGNIFICANT records (evicted only via decay to zero strength)

## Familiarity Counter Maintenance

```cpp
struct FamiliarityCounters {
  uint16_t touch_taps_today;        // from g_creature.interactions_today
  uint16_t security_bursts_session; // accumulated deauth bursts
  uint16_t aviation_flights_today;  // from g_creature.flights_seen_today
  uint16_t mood_transitions_session;
  uint16_t attention_shifts_session;
};
```

Counters persist only for the current power cycle (reset on boot). They are separate from the `CreatureProfile` NVS counters. Familiarity records themselves persist across boots (LittleFS Sprint 2).

Crossing thresholds are checked every 60 seconds against the accumulated counters. When a crossing is detected, a `MEM_CAT_FAMILIARITY` record is formed.

## Salience Computation (deterministic)

```cpp
uint8_t compute_salience(uint8_t base, uint8_t mood_strength, MoodType mood,
                         uint8_t current_mode, uint32_t uptime_min) {
  float ctx = 1.0f;

  // Nighttime boost (approximated: if uptime > 12h since last known boot)
  if (uptime_min > 720) ctx *= 1.3f;

  // Mood context
  if (mood == MOOD_ANXIOUS)  ctx *= 1.2f;
  if (mood == MOOD_PLAYFUL)  ctx *= 0.8f;

  // Mood intensity
  if (mood_strength > 70) ctx *= 1.2f;
  if (mood_strength < 20) ctx *= 0.7f;

  // Mode context
  if (current_mode == MODE_COMPANION) ctx *= 1.2f;
  if (current_mode == MODE_SECURITY)  ctx *= 1.3f;
  if (current_mode == MODE_AVIATION)  ctx *= 1.2f;

  // Clamp to valid range
  uint8_t result = (uint8_t)(base * ctx + 0.5f);
  if (result > 100) result = 100;
  if (result < 1)   result = 1;
  return result;
}
```

## Decay Parameters (summary)

| Domain | Half-Life (hours) | Decay per 60s tick | Notes |
|--------|-------------------|--------------------|-------|
| TOUCH | 6.0 | ~0.028 strength/tick | Fades over a waking day |
| SECURITY | 12.0 | ~0.014 strength/tick | Longer retention for threats |
| AVIATION | 4.0 | ~0.042 strength/tick | Quicker fade (transient events) |
| MOOD | 8.0 | ~0.021 strength/tick | Moderate retention |
| ATTENTION | 3.0 | ~0.056 strength/tick | Fastest fade (attention shifts rapidly) |

**Decay formula (every 60s):**
```cpp
float half_life_ticks = half_life_hours * 60.0f;
float decay = 100.0f / half_life_ticks;          // linear approximation
rec.strength = max(0, rec.strength - (uint8_t)(decay + 0.5f));
```

**Session boundary decay (on boot):**
```cpp
rec.strength = (rec.strength * 3) / 4;   // -25% across power cycles
```

This ensures memories fade naturally across ~4 boot cycles without reinforcement.
