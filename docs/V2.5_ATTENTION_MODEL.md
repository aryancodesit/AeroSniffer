# V2.5 Attention Model

> **Status**: Design — Approved. See `docs/V2.5_SPRINT1_SPEC.md` for final implementation specification.  
> **Branch**: `feature/v2.5-creature-brain`  
> **Preserves**: V2.4 queue, EventBus, spinlock, priority system, state machine internals  
> **Changes are additive**: AttentionEngine publishes structured data. CreatureState gains richer fields. FaceEngine reads the combination.

---

## 1. Design Goals

| Goal | Why |
|------|-----|
| Continuous strength, not binary state | Creature gradually relaxes instead of snapping SOFT_FOCUS |
| Structured output (target, source, strength) | FaceEngine and EmotionLayer can reason about *what* and *how much* |
| Preserve V2.4 preemption | Priority system works, proven on hardware |
| No new infrastructure | Same queue, same EventBus, same spinlock, same tick() call site |
| Emotion/Mood compatible | Future layers read the same CreatureState fields without changes |

## 2. Data Model

### 2a. Enums

```cpp
enum AttentionTarget : uint8_t {
    TARGET_NONE    = 0,  // Idle, no focus
    TARGET_USER    = 1,  // User interaction (touch)
    TARGET_THREAT  = 2,  // Security threat (deauth, evil twin)
    TARGET_FLIGHT  = 3   // Aircraft detected
};

// Conceptual domain source — NOT a mirror of EventType.
// Multiple EventTypes map to the same source.
// This abstraction exists so EmotionLayer (Sprint 2) can reason
// about domains (TOUCH → happy, SECURITY → anxious) without
// knowing about specific events.
enum AttentionSource : uint8_t {
    SOURCE_INTERNAL  = 0,  // Infrastructure: WiFi, mode switch, idle
    SOURCE_TOUCH     = 1,  // Physical user interaction (touch sensor)
    SOURCE_SECURITY  = 2,  // Security threat: deauth, evil twin
    SOURCE_AVIATION  = 3,  // Aircraft observation (OpenSky)
    SOURCE_PORTAL    = 4   // Reserved — future Portal-triggered attention
};
```

### 2b. CreatureState Addition

Replace the V2.4 single field:

```cpp
// V2.4 — remove:
uint8_t attention_state;  // 0=SOFT_FOCUS, 1=WATCHING, 2=THREAT_LOCK

// V2.5 — replace with:
struct {
    AttentionTarget target;    // What the creature is focused on
    AttentionSource source;    // What triggered the focus
    uint8_t         strength;  // 0–100, 0 = idle, 100 = locked
} attention;
```

Total ROM cost: 3 bytes. Zero RAM growth (replaces 1 byte with 3).

### 2c. FaceEngine Reads

```cpp
// In updateAnimations():

if (g_creature.attention.target == TARGET_USER) {
    anim_look_x = 0;
    anim_look_y = -2;  // Look upward toward user
}
if (g_creature.attention.target == TARGET_THREAT) {
    anim_look_x = 0;
    anim_look_y = 0;   // Centre lock — intense
}
if (g_creature.attention.target == TARGET_FLIGHT) {
    anim_look_x = 4;   // Look toward sky icon area
    anim_look_y = -3;
}
if (g_creature.attention.strength > 80) {
    // Intense — suppress wandering, narrower eyes
    blink_rate = slow;
}
if (g_creature.attention.strength < 20 && g_creature.attention.strength > 0) {
    // Almost idle — eyes begin to soften
}
if (g_creature.attention.strength == 0) {
    // Full SOFT_FOCUS — random wandering resumes
}
```

These are additive modifiers. SOFT_FOCUS behaviour (random saccades) is the default below all checks.

## 3. Event Mappings

Source is conceptual domain, not event type. See `docs/V2.5_SPRINT1_SPEC.md` for full mapping rationale.

| EventBus Event | Priority | Source | Target | Initial Strength |
|---------------|----------|--------|--------|-----------------|
| `EVENT_ATTACK_DEAUTH` | 1 | SECURITY | THREAT | 100 |
| `EVENT_ATTACK_EVILTWIN` | 1 | SECURITY | THREAT | 100 |
| `EVENT_TOUCH_SHORT` | 2 | TOUCH | USER | 55 |
| `EVENT_TOUCH_LONG` | 2 | TOUCH | USER | 55 |
| `EVENT_FLIGHT_DETECTED` | 3 | AVIATION | FLIGHT | 45 |
| `EVENT_FLIGHT_RARE` | 3 | AVIATION | FLIGHT | 55 |
| `EVENT_WIFI_CONNECTING` | 4 | INTERNAL | NONE | 30 |
| `EVENT_WIFI_CONNECTED` | 4 | INTERNAL | NONE | 25 |
| `EVENT_WIFI_DISCONNECTED` | 4 | INTERNAL | NONE | 30 |
| `EVENT_MODE_SWITCHED` | 4 | INTERNAL | NONE | 20 |

### Mapping rationale

- **Source is conceptual, not event-mirrored.** Multiple EventTypes map to the same source. This abstraction exists so EmotionLayer (Sprint 2) can reason about domains without knowing about specific events. See `docs/V2.5_SPRINT1_SPEC.md` §3.
- **P1 SECURITY** gets full strength (100) — maximum urgency, longest decay
- **P2 TOUCH** gets moderate strength (55) — user interaction, ~3.5s visible gaze then relaxes
- **P3 AVIATION rare** higher than AVIATION detected — novelty gets more attention
- **P3 AVIATION detected** lower — routine event
- **P4 INTERNAL** events have target=NONE — no specific focus, just ambient distraction. FaceEngine shows no visible reaction (documented in Sprint 1 spec §7d).
- **INTERNAL** covers WiFi events and mode switches — they are device infrastructure, not observations about the world.

## 4. Priority Resolution

### 4a. Rules (unchanged from V2.4)

```
P1 (SECURITY)  > P2 (TOUCH) > P3 (AVIATION) > P4 (INTERNAL)
```

1. **Lower number = higher priority**
2. **Preemption**: higher priority event overrides current target/source/strength
3. **Refresh**: same priority event resets strength to initial value, extends decay
4. **Block**: lower priority event is ignored while higher priority is active

### 4b. Decision matrix

```
Current Priority | Incoming Priority | Action
-----------------|-------------------|-------
none (0)         | any               | Accept — set target/source/strength
P1               | P1                | Refresh — reset strength, same target/source
P1               | P2, P3, P4        | Block — ignored
P2               | P1                | Preempt — override target/source/strength
P2               | P2                | Refresh — reset strength, same target/source
P2               | P3, P4            | Block — ignored
P3               | P1, P2            | Preempt — override target/source/strength
P3               | P3                | Refresh — reset strength, same target/source
P3               | P4                | Block — ignored
P4               | P1, P2, P3        | Preempt — override target/source/strength
P4               | P4                | Refresh — reset strength, same target/source
```

### 4c. Source conflict at same priority

When two different sources arrive at the same priority (unlikely but possible with P4), the *last* event to be processed wins. This matches V2.4 behaviour.

## 5. Strength Model

### 5a. Decay curve

```
strength decays per tick:

  if (strength > 50):
    strength -= 25 * dt      // rapid initial drop
  else if (strength > 20):
    strength -= 10 * dt      // moderate decay
  else:
    strength -= 5 * dt       // slow tail — lingering attention

clamp(strength, 0, 100)
```

`dt` = seconds since last tick (delta_ms / 1000.0f).

### 5b. Duration by initial strength

| Initial | Above 50 | 50→20 | 20→0 | Total (approx) | Visible active (~strength > 30) |
|---------|----------|-------|------|----------------|-------------------------------|
| 100 (P1) | 2.0s | 3.0s | 4.0s | **9.0s** | ~5.5s |
| 55 (P2) | 0.2s | 3.0s | 4.0s | **7.2s** | ~3.5s |
| 55 (P3 rare) | 0.2s | 3.0s | 4.0s | **7.2s** | ~3.5s |
| 45 (P3) | — | 2.5s | 4.0s | **6.5s** | ~2.5s |
| 30 (P4) | — | 1.0s | 4.0s | **5.0s** | ~1.5s |
| 25 (P4) | — | 0.5s | 4.0s | **4.5s** | ~1.0s |
| 20 (P4) | — | — | 4.0s | **4.0s** | ~0.5s |

### 5c. Behavioural zones

| Strength | Behaviour | FaceEngine effect |
|----------|-----------|------------------|
| 80–100 | Locked | Centre gaze, suppressed blink, no wander |
| 50–80 | Watching | Gaze toward target, normal blink |
| 20–50 | Relaxing | Same target, softer gaze, occasional micro-saccades |
| 1–20 | Nearly idle | Target still set but gaze softening, idle animations creep in |
| 0 | Idle | Full SOFT_FOCUS — random wandering, idle behaviour |

### 5d. Why three zones

The two-stage curve produces natural attention behaviour: a creature that *immediately* notices something, watches it intently for a moment, then gradually loses interest and lets its gaze drift. The third zone (< 20) adds a "lingering" tail so the transition back to idle is never abrupt.

## 6. Internal Architecture (AttentionEngine Changes)

### 6a. New private fields

```cpp
// In AttentionEngineClass — add:
AttentionTarget   _target   = TARGET_NONE;
AttentionSource   _source   = SOURCE_INTERNAL;
uint8_t           _strength = 0;

// Event timestamp for continuous decay (replaces binary deadline):
struct {
    EventType type;
    uint32_t  arrived_ms;   // millis() when this event was processed
    uint8_t   initial_strength;
} _active_event;
```

### 6b. Tick() algorithm (V2.5)

```
tick(delta_ms):
  1. Drain queue (same as V2.4 — lock-free, priority preemption)
     - On preemption/refresh: record event type, arrived_ms, initial_strength
     - Set _target, _source from event mapping

  2. If in active state (target != NONE):
     - elapsed = now - _active_event.arrived_ms
     - _strength = compute_strength(_active_event.initial_strength, elapsed)
     - If _strength == 0:
         reset to idle (target=NONE, source=INTERNAL, strength=0)

  3. Publish to CreatureState:
     g_creature.attention.target    = _target
     g_creature.attention.source    = _source
     g_creature.attention.strength  = _strength
```

### 6c. State machine preserved internally

The internal `_state` (SOFT_FOCUS / WATCHING / THREAT_LOCK) is retained but derived from target/strength instead of driving them. This preserves V2.4's preemption logic.

```
Internal mapping (for transition logging only):
  target=NONE             → STATE_SOFT_FOCUS
  target=THREAT           → STATE_THREAT_LOCK
  target=USER/FLIGHT  → STATE_WATCHING
```

## 8. Migration Path from V2.4

### Phase 1 (Sprint 1 — this sprint)

1. Add enums `AttentionTarget`, `AttentionSource` to `V2.5_AttentionModel.h` (new header)
2. Add `attention` struct to `CreatureState` (replaces `attention_state`)
3. Add private fields to AttentionEngineClass (`_target`, `_source`, `_strength`, `_active_event`)
4. Update `tick()`:
   - On queue drain: map event → target/source/set initial strength
   - Compute continuous strength from elapsed time instead of binary deadline
   - Publish to `g_creature.attention`
5. Update `AeroSniffer.ino`: call `AttentionEngine.publish()` after `tick()` (or integrate into tick())
6. Update `FaceEngine::updateAnimations()`: read `g_creature.attention` instead of `g_creature.attention_state`
7. Remove `g_creature.attention_state` field

### Phase 2 (Sprint 2)

EmotionLayer reads `g_creature.attention.source` and `g_creature.attention.strength` to compute emotional response.

### Phase 3 (Sprint 3)

MoodLayer reads attention + emotion history to set persistent mood.

## 9. Compatibility with Future Layers

The attention model is designed so that:

- **EmotionLayer** reads `attention.source` + `attention.strength` + `attention.target` as inputs to its emotional response calculation. TOUCH → happy, SECURITY → anxious, AVIATION → curious, INTERNAL → neutral.
- **MoodLayer** reads accumulated attention patterns (how often threats vs interactions) to bias mood over longer timescales.
- **Curiosity** (future) reads target novelty — has the creature seen this source recently?
- **FaceEngine** is the only consumer in Sprint 1. It reads the structured data and produces additive visual effects.

No future layer requires changes to the attention model. The published data is the contract.

## 10. Validation

### Unit-testable properties

| Property | Test |
|----------|------|
| Priority preemption | P1 preempts P2; P2 blocks P3; P4 ignored during P1 |
| Decay monotonic | strength never increases without a new event |
| Strength clamp | strength ∈ [0, 100] after any tick |
| Source preservation | Same-priority refresh keeps same source |
| Idle reset | strength=0 → target=NONE, source=INTERNAL |
| Event mapping | All 10 subscribed events map to valid source/target |

### Hardware validation

1. **Tap → gaze up**: strength starts at 55, decays over ~7s. Creature looks up, gradually relaxes.
2. **Deauth → threat lock**: strength starts at 100. Creature centres gaze, intense. ~9s total.
3. **Priority cascade**: During P1, tap is ignored. After P1 decays, tap is accepted.
4. **Rapid tap spam**: Each tap refreshes strength to 55, extends decay. No crash.
5. **Strength soft idle**: At strength < 20, creature looks nearly idle but hasn't snapped to SOFT_FOCUS.

## 11. Design Decisions

| Decision | Choice | Alternative considered |
|----------|--------|----------------------|
| Strength decay curve | 3-zone linear | Single rate, exponential |
| Initial strength per event | Fixed constants | Dynamic from elapsed idle time |
| State machine preserved | Yes, internally | Full replacement by strength |
| Source separate from target | Yes | Combined into single enum |
| P4 target | NONE | SKY |
| Source model | Conceptual (TOUCH, SECURITY, AVIATION, PORTAL, INTERNAL) | Event-mirrored (DEAUTH, EVIL_TWIN, FLIGHT, WIFI) |
| `acquired_ms` in CreatureState | No — private to AttentionEngine | Yes — for Portal analytics |
| Gaze coordinate ownership | FaceEngine | AttentionEngine (rejected — breaches renderer boundary) |

## 12. Risks and Mitigations

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| Strength calibration wrong | Medium | Constants in one place, tune after hardware test |
| FaceEngine complexity | Low | Reads are additive — can render with just target |
| Tick CPU cost | Very low | One strength computation per tick (~5 ops) |
| Emotion/Mood incompatible | Very low | They read attention data, don't modify it |
