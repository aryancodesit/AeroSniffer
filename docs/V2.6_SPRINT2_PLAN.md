# V2.6 Sprint 2 — Touch Duration Expansion

**Goal:** Expand memory formation quality by adding duration-aware touch types without adding new memory domains.

**Foundation:** V2.6 Sprint 1 certified — Memory Layer Foundation stable on hardware.

---

## Current State

### Touch Pipeline (today)

```
finger down → poll_touch_input() measures duration
                  ↓
            <20ms → ignored (chatter)
          20–1499ms → g_touch_tap = true (boolean, no duration)
          ≥1500ms → g_mode_dirty = true (mode switch, no EventBus event)
                  ↓
           Mode task reads g_touch_tap
                  ↓
           EventBus.publish(EVENT_TOUCH_SHORT, nullptr)
                  ↓
           MemoryEngine.onTouchEvent() — counter only
                  ↓
           observe(): always forms TOUCH_TAP (touch_duration_ms = 0)
```

**Key finding:** Duration IS measured in `poll_touch_input()` (AeroSniffer.ino:186–201) but is **discarded before reaching EventBus or MemoryEngine**. The `touch_duration_ms` field in `MemoryRecord.data.touch` exists but is hardcoded to 0.

## Design Review Findings

### Finding 1 — Dangling Pointer in AttentionEngine Queue (BLOCKING)

`AttentionEngine::queueEvent(event, data)` stores `void* data` in a ring buffer (`QueueEntry{event, data}`). The current publish path always passes `nullptr`, so the stored pointer is always null.

Sprint 2 would pass `&TouchEventData` (stack-local) through `EventBus.publish()`:

```
poll_touch_input()
    ↓
TouchEventData (stack)
    ↓
EventBus.publish(EVENT_TOUCH_SHORT, &td)
    ↓
ae_event_callback(event, data)    ← data = &td (stack address)
    ↓
AttentionEngine.queueEvent(event, data)    ← stores pointer in ring buffer
```

The queue is asynchronous — `data` is read on a later tick. By then the calling stack frame is gone. Result: a dangling pointer in the ring buffer. Currently never dereferenced, but undefined behavior waiting to happen.

**Fix:** `ae_event_callback` must suppress the data pointer before forwarding:
```cpp
static void ae_event_callback(EventType event, void* data) {
    (void)data;
    AttentionEngine.queueEvent(event, nullptr);
}
```

AttentionEngine does not need duration. MemoryEngine does. Clean separation.

### Finding 2 — Counter Insufficient for Duration Metadata (BLOCKING)

Current `onTouchEvent()` uses `touch_events_++` — a simple counter. In Sprint 1 (TAP only), all touches are identical so a counter is sufficient.

Sprint 2 requires per-event duration:
```
Touch 1: duration=150ms  → TOUCH_TAP
Touch 2: duration=600ms  → TOUCH_HOLD
Touch 3: duration=100ms  → TOUCH_TAP  (third in burst → TOUCH_BURST)
```

A counter cannot carry per-event metadata. Must be replaced with a pending touch buffer.

**Fix:** `PendingTouch` ring buffer inside MemoryEngine.

### Finding 3 — Portal.h Missing from Scope (DOCUMENTATION)

`Security/Portal.h:1219-1222` also consumes `g_touch_tap`. Must be included in the modified files list.

## Architecture Impact

### Minimal. Two blocking fixes, zero structural changes.

### 1. EventBus Payload

**Change:** Define a `TouchEventData` struct and pass it via the existing `void* eventData` parameter.

The EventBus already supports arbitrary data:
```cpp
void publish(EventType event, void* eventData = nullptr);
```

No change to `EventBusClass`, `Subscription`, `MAX_SUBSCRIBERS`, or `EventCallback` signature. Existing subscribers that ignore `eventData` are unaffected — they continue to receive `nullptr` for non-touch events.

### 2. ae_event_callback Safety Fix

**Change:** Add `(void)data;` and pass `nullptr` to `AttentionEngine.queueEvent()`.

One line. Removes the only path where a stack-allocated `TouchEventData` pointer could leak into an asynchronous queue.

### 3. Global Touch State

**Change:** Replace `g_touch_tap` (boolean) with `g_touch_duration_ms` (uint16_t).

Four consumers update to read `g_touch_duration_ms` instead of `g_touch_tap`. Mode tasks construct a local `TouchEventData` and publish it. `g_mode_dirty` for ≥1500ms is unchanged.

### 4. MemoryEngine Buffer

**Change:** Replace `uint16_t touch_events_` counter with a `PendingTouch` ring buffer:
```cpp
struct PendingTouch {
    uint16_t duration_ms;
};
PendingTouch pending_[8];
uint8_t pending_head_;
uint8_t pending_tail_;
```

`onTouchEvent(duration_ms)` writes one entry. `observe()` drains all entries. Timestamp is taken from `millis()` inside `observe()` — no need to store it per-event since DOUBLE_TAP and BURST detection already use existing timing structures.

**Overflow:** If `pending_head_` wraps past `pending_tail_` (more than 8 pending touches in one frame), increment a `dropped_touch_events_` counter. Exposed in `recall()` output for diagnostics — not for behavior.

### 5. Memory Formation

**Change:** `observe()` classifies each pending touch by duration:

Duration thresholds (compile-time constants, validated on hardware before freezing):

| Range | Classification |
|-------|---------------|
| <20ms | Chatter (ignore) |
| 20–TAP_MAX_MS | TAP |
| TAP_MAX_MS+1–HOLD_MAX_MS | HOLD |
| HOLD_MAX_MS+1–LONG_HOLD_MAX_MS | LONG_HOLD |
| ≥1500ms | Mode switch (existing path, no memory) |

Constants defined in `Config.h`:

```cpp
constexpr uint16_t TAP_MAX_MS     = 300;
constexpr uint16_t HOLD_MAX_MS    = 800;
constexpr uint16_t LONG_HOLD_MS   = 1500;  // same as LONG_PRESS_MS, mode switch
```

Tune these after collecting 20–30 real interaction duration samples from hardware.

### 6. Memory Salience

| Subtype | Base Salience | Note |
|---------|---------------|------|
| TOUCH_TAP | 22 | Unchanged |
| TOUCH_DOUBLE | 30 | New — existing detection promoted to distinct record |
| TOUCH_HOLD | constrain(duration/20, 22, 35) | New — scales with duration, clamped to prevent accidental holds from dominating |
| TOUCH_LONG_HOLD | constrain(duration/30, 30, 45) | New — scales with duration, clamped below BURST priority |
| TOUCH_BURST | 45 | Unchanged |

Existing dedup logic unchanged — same-subtype records within 60s get boosted.
