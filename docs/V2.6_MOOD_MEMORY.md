# V2.6 Sprint 3 — Mood Memory Domain

**Status:** Sprint 3 Design Review — REVISED
**Domain:** DOMAIN_MOOD (3)
**Value:** 3

---

## Purpose

The creature remembers its emotional history — not its current mood (MoodEngine owns that), but what it has felt over time.

What memory should answer:
- How has the creature felt recently?
- Has it been relaxed all day?
- Has it been anxious repeatedly?

What memory should NOT answer:
- What mood is the creature in right now? (MoodEngine, via g_creature.mood)
- Should the creature change mood? (MoodEngine decides)
- Should behavior change based on mood history? (Behavior Layer V2, deferred)

---

## Key Architectural Decision

Mood Memory observes `g_creature.mood` and `g_creature.mood_strength`. It does NOT subscribe to any EventBus events. MoodEngine already publishes mood changes to `g_creature` — MemoryEngine reads that in `tick()`.

This means:
- **No MoodEngine changes.** Zero. MoodEngine does not know MemoryEngine exists.
- **No EventBus events for mood.**
- **MemoryEngine polls mood state** in `observe()` and compares against `last_known_mood_`.
- **Single direction of dependency:** MemoryEngine → reads g_creature. MoodEngine writes g_creature. No cycles.

---

## Subtypes

| Subtype | Value | Condition | Base Salience |
|---------|-------|-----------|---------------|
| MOOD_LONG_RELAXED_PERIOD | 0x30 | Mood has been MOOD_RELAXED for >= 30 min continuously | 25 |
| MOOD_LONG_PLAYFUL_PERIOD | 0x31 | Mood has been MOOD_PLAYFUL for >= 30 min continuously | 28 |
| MOOD_LONG_ANXIOUS_PERIOD | 0x32 | Mood has been MOOD_ANXIOUS for >= 30 min continuously | 35 |
| MOOD_TRANSITION | 0x33 | `g_creature.mood` changed since last tick | 30 |

## Data Payload

```cpp
struct {
  uint8_t  mood;             // current MoodType (0=RELAXED, 1=PLAYFUL, 2=ANXIOUS)
  uint8_t  prev_mood;        // previous MoodType (0xFF if N/A, e.g., first boot)
  uint16_t duration_min;     // how long the previous mood lasted before transition
  uint8_t  _pad[12];
} mood_event;
```

Total: 16 bytes (matches union size).

## Formation Rules

### State Tracking

```cpp
// In MemoryEngine (private):
uint8_t  mood_last_known_;        // last MoodType seen
uint8_t  mood_last_strength_;     // last mood_strength seen
uint32_t mood_current_since_ms_;  // when current mood started
uint8_t  mood_last_period_type_;  // last period subtype formed (to avoid repeats)
uint32_t mood_last_period_ms_;    // when last period was formed
```

**Note:** `mood_last_transition_ms_` is NOT tracked. Transitions are never deduped, so no timestamp is needed.

Initialized in `begin()`:
```
mood_last_known_ = g_creature.mood;
mood_last_strength_ = g_creature.mood_strength;
mood_current_since_ms_ = millis();
mood_last_period_type_ = 0xFF;
mood_last_period_ms_ = 0;
```

### Tick-Based Detection

In `observe()`, after touch/security/aviation:

```cpp
MoodType current_mood = (MoodType)g_creature.mood;
uint32_t now = millis();

// 1. Mood transition check — NEVER deduped. Every transition is an episode.
if (current_mood != mood_last_known_) {
  uint16_t duration = (now - mood_current_since_ms_) / 60000;
  observe_mood(MOOD_TRANSITION, current_mood, mood_last_known_, duration);

  mood_last_known_ = current_mood;
  mood_current_since_ms_ = now;
  mood_last_period_type_ = 0xFF;  // reset period tracking
}

// 2. Prolonged mood check (only when decay/prune timer fires, ~60s)
uint32_t elapsed_min = (now - mood_current_since_ms_) / 60000;
if (elapsed_min >= 30 && mood_last_period_type_ != current_mood) {
  uint8_t new_subtype;
  switch (current_mood) {
    case MOOD_RELAXED: new_subtype = MOOD_LONG_RELAXED_PERIOD; break;
    case MOOD_PLAYFUL: new_subtype = MOOD_LONG_PLAYFUL_PERIOD; break;
    case MOOD_ANXIOUS: new_subtype = MOOD_LONG_ANXIOUS_PERIOD; break;
    default: new_subtype = 0xFF; break;
  }
  if (new_subtype != 0xFF) {
    observe_mood(new_subtype, current_mood, 0xFF, elapsed_min);
    mood_last_period_type_ = current_mood;
    mood_last_period_ms_ = now;
  }
}
```

### Per-Mood Period Lock

Prolonged mood forms at most once per uninterrupted mood episode. RELAXED for 2 hours produces ONE `MOOD_LONG_RELAXED_PERIOD` at the 30-min mark; subsequent ticks see `mood_last_period_type_ == MOOD_RELAXED` and skip.

If the creature transitions to PLAYFUL and back to RELAXED, the 30-min clock resets for the new RELAXED episode.

This is NOT dedup (not time-window-based). It is a formation guard that prevents redundant records from the same continuous mood period.

---

## Salience

| Subtype | Base | Effective Range | Rationale |
|---------|------|-----------------|-----------|
| MOOD_LONG_RELAXED_PERIOD | 25 | 25-30 | Positive, calm — notable but not urgent |
| MOOD_LONG_PLAYFUL_PERIOD | 28 | 28-34 | Engaging — slightly more salient |
| MOOD_LONG_ANXIOUS_PERIOD | 35 | 35-42 | Distress signal — notably higher |
| MOOD_TRANSITION | 30 | 30-36 | Mood shift is always meaningful |

No mood-to-mood context multiplier (would create echo chamber). Mode-based multipliers still apply.

---

## Dedup Window

**MOOD_TRANSITION:** None. Transitions are never deduped. Each is a distinct episode.

**MOOD_LONG_*:** 6 hours (safety net). Prolonged mood subtypes are primarily gated by the per-mood period lock. The 6-hour dedup window is a second line of defense: if a bug causes `mood_last_period_type_` to reset while the creature is still in the same mood, duplicate formation is caught. Under normal operation, the per-mood period lock prevents duplicates before they reach `try_dedup()`.

---

## Decay

**Half-life: 8 hours.** This morning's anxiety is still relevant this evening but fades overnight.

---

## Anti-Flood Safeguards

1. **Per-mood period lock:** one prolonged record per uninterrupted mood episode.
2. **Safety-net dedup (6h):** prevents duplicate MOOD_LONG_* records if the period lock is bypassed by a bug.
3. **No tick-level mood memory:** MemoryEngine polls mood at 60s cadence (tied to decay/prune interval), not every loop.

---

## What Does NOT Change

- MoodEngine — no changes.
- `g_creature.mood` — unchanged. MemoryEngine reads only.
- `g_creature.mood_strength` — unchanged.

| No MoodEngine change | MoodEngine still ticks normally | No new EventBus subs, no new dependencies |
