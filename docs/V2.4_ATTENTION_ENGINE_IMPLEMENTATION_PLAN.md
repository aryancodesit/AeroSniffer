## 1. Files to Create

### 1.1 `AeroSniffer/AttentionEngine.h`

New header declaring `AttentionEngineClass`.

```cpp
#pragma once
#include <cstdint>

enum EventType : int;

class AttentionEngineClass {
public:
  // ── Lifecycle ──
  void begin();
  void tick(uint32_t delta_ms);
  void pause();
  void resume();

  // ── State output (read by EmotionEngine) ──
  enum AttentionState : uint8_t {
    STATE_SOFT_FOCUS = 0,
    STATE_WATCHING,
    STATE_THREAT_LOCK,
    _STATE_COUNT
  };
  AttentionState getActiveState() const;
  uint8_t        getActivePriority() const;   // 1–5
  uint32_t       getTargetDurationMs() const;
  bool           isHabituationSaturated() const;

  // ── Event ingestion ──
  void queueEvent(EventType event, void* data);

private:
  portMUX_TYPE _mux = portMUX_INITIALIZER_UNLOCKED;  // guards queueEvent() writes
  // Internal types, queue, state machine, decay logic
  // Writes gaze_x, gaze_y, blink_request to g_creature each tick
};
```

Key design decisions:
- Gaze output written directly to `g_creature.gaze_x`, `g_creature.gaze_y`, `g_creature.blink_request` each tick — no separate getter path.
- `queueEvent()` is the thread-safe entry point (lock-free single-producer queue).
- `tick(delta_ms)` drains the queue, advances state, and writes gaze to `g_creature`.
- `pause()` preserves all state (queue, targets, habituation, current state). `resume()` continues from paused state.
- No emotion-setting code. AttentionEngine only exposes context via state getters.

### 1.2 `AeroSniffer/AttentionEngine.cpp`

Full implementation containing:

| Concern | Detail |
|---------|--------|
| **Event queue** | 16-entry ring buffer, multi-producer-single-consumer (MPSC). Writers guarded by `portMUX_TYPE` spinlock in `queueEvent()`. Consumer (tick) is lock-free — only accessed from Core 1. `queueEvent()` keeps no flash strings or heap ops for IRAM_ATTR safety. |
| **Queue overflow** | Discard oldest, keep newest. When full: `tail = (tail + 1) % SIZE;` then write at head. Rationale: attention is biased toward recency — a stale WiFi event from 5 seconds ago is less important than a fresh threat. |
| **Dropped events counter** | `uint32_t _dropped_count;` incremented each time the queue discards an entry. No `Serial` output. Exposed via a future debug stats method alongside `events_processed` and `queue_high_water_mark`. |
| **Target table** | Fixed 8-slot array of `{EventType, priority, gaze_x, gaze_y, remaining_ms, active}` |
| **Priority resolver** | Scans target table for highest-priority non-expired entry each tick |
| **State machine** | SOFT_FOCUS ↔ WATCHING ↔ THREAT_LOCK (no TRACKING — Sprint 2) |
| **Decay engine** | `remaining_ms -= delta_ms` on active target; expiry → next target |
| **Micro-saccade generator** | Poisson-distributed interval (200–600 ms), amplitude [0.01, 0.08], additive noise scaled by `delta_ms` — active only in SOFT_FOCUS |
| **Blink rate generator** | ~1 per 4–6 s in SOFT_FOCUS; reduced in WATCHING (~1/6–10s); minimal in THREAT_LOCK (~1/12–20s) |
| **Habituation stubs** | Counter struct + window tracking — per §7 of spec, but only NETWORK + AVIATION + TOUCH + SYSTEM categories; threat sensitisation reserved for Sprint 2 |
| **Stall recovery** | If `delta_ms >= 1000`, apply full delta in one pass (single noise step, no sub-frame interpolation) |
| **g_creature write** | After each tick, write `g_creature.gaze_x`, `g_creature.gaze_y`, `g_creature.blink_request` — FaceEngine reads these each frame |

## 3. Integration Strategy

### 3.1 Render Loop Data Flow (per frame)

```
                    ┌───────────────────────────────────────┐
                    │         g_creature (CreatureState)     │
                    │  { gaze_x, gaze_y, blink_request }     │
                    └──────┬────────────────────┬────────────┘
                           │                    ▲
          ┌────────────────┤   AttentionEngine  │
          │                │   writes each tick │
          ▼                │                    │
  ┌──────────────┐         │                    │
  │  FaceEngine  │         │                    │
  │  .render()   │         │                    │
  │  reads gaze  │         │                    │
  │  from struct │         │                    │
  └──────────────┘         │                    │
                           │                    │
          ┌────────────────┘                    │
          │           context getters           │
          ▼            (state, priority,        │
  ┌──────────────┐      duration, habituated)   │
  │ EmotionEngine│                                │
  │ .tick()      ├────────────────────────────────┘
  │ reads state  │
  │ (not gaze)   │  EmotionEngine is the sole
  └──────────────┘  emotion authority. Never
                     called/set from AttentionEngine.
```

### 3.2 Mode Transition Handling — Pause/Resume

Replaces the old `end()`/`reset()` approach. Habituation and gaze history survive mode changes; active attention targets do not.

```
1. g_mode_dirty = true detected in task_core1()
2. teardown_mode(old_mode):
     AttentionEngine.pause()   // flushes targets + queue, freezes habituation
                               // gaze position frozen in g_creature
3. setup_mode(new_mode):
     // habituation intact, no active targets
4. First tick after mode switch:
     AttentionEngine.resume()  // SOFT_FOCUS, micro-saccades resume
```

`pause()` behaviour:
- Flushes active target table (all targets discarded)
- Flushes event queue (events arriving during pause are silently discarded)
- Freezes habituation counters and windows (windows do not slide during pause)
- Preserves gaze history buffer (circular RAM log)
- Current gaze position frozen in `g_creature.gaze_x/gaze_y` (screen holds last look)
- Sets `_paused = true`; `tick()` returns immediately when paused

`resume()` behaviour:
- Resets state machine to SOFT_FOCUS
- Habituation counters resume from frozen values (windows resume sliding)
- Gaze position keeps last frozen value; micro-saccades begin drifting from there
- Event queue is empty (anything arriving during pause was discarded)

### 3.3 Non-Client Modes

Only **Pet mode** uses FaceEngine rendering. Security mode and Aviation mode have their own UIs. When Pet mode is not active, `AttentionEngine.pause()` is called (via mode transition flow). `g_creature.gaze_x`/`g_creature.gaze_y` hold their last frozen values. `tick()` is a no-op while paused. On return to Pet mode, `resume()` starts fresh in SOFT_FOCUS with habituation intact.

### 3.4 EmotionEngine Wiring (Interface Only — No Prescribed Behaviour)

AttentionEngine exposes context for EmotionEngine to consume if desired:

| Getter | Type | Purpose |
|--------|------|---------|
| `getActiveState()` | `AttentionState` | Current attention state (SOFT_FOCUS, WATCHING, THREAT_LOCK) |
| `getActivePriority()` | `uint8_t` | Priority of current target (1–5) |
| `getTargetDurationMs()` | `uint32_t` | How long the current target has been active |
| `isHabituationSaturated()` | `bool` | Whether the current event category is habituated |

This plan does not prescribe any specific emotion transitions. The mapping between attention context and emotion state is owned by the EmotionEngine personality module and may be implemented in a future Sprint.

What is guaranteed:
- AttentionEngine publishes context via read-only getters
- EmotionEngine never blocks on AttentionEngine (getters return immediately)
- AttentionEngine never calls `setEmotion()`, `forceIdle()`, or any EmotionEngine method

## 4. Runtime Ownership

```
Legend:
  ┌─┐  Object (global instance)
  ═══  Lifetime boundary
  ──►  Write
  ──►  Read
```

```
                     ┌──────────────────┐
                     │   AeroSnifferOS  │
                     │  (owns all)      │
                     └══╤══╤══╤══╤══╤══┘
                        │  │  │  │  │
        ┌───────────────┘  │  │  │  └───────────────┐
        ▼                  ▼  ▼  ▼                  ▼
  ┌──────────┐    ┌────────────┐          ┌───────────┐
  │ EventBus │    │ Attention  │          │   Face    │
  │  (core)  │───►│  Engine    │          │  Engine   │
  └──────────┘    │ (singleton)│          │(singleton) │
                   └─────┬─────┘          └─────▲─────┘
                         │                      │
                         │ writes               │ reads
                         ▼                      │
                   ┌────────────────────┐       │
                   │   g_creature       ├───────┘
                   │  (CreatureState)   │
                   │ gaze_x, gaze_y,    │
                   │ blink_request      │
                   └────────────────────┘
                         │
                         │ context getters (read)
                         ▼
                   ┌────────────┐
                   │  Emotion   │
                   │  Engine    │
                   │(singleton) │
                   └────────────┘
```

**Lifecycle ownership:**
- `EventBus` — core service, initialised first, lives for entire program
- `AttentionEngine` — singleton, `begin()` in `setup()` after EmotionEngine, `pause()`/`resume()` on mode transitions
- `EmotionEngine` — singleton, `begin()` before AttentionEngine, ticked after; reads attention context via getters
- `g_creature` — plain struct, acts as shared gaze state; AttentionEngine writes, FaceEngine reads
- `FaceEngine` — singleton, stateless regarding attention; reads `g_creature.gaze_x`/`gaze_y` each frame

**No dynamic allocation.** All internal buffers (event queue, target table) are fixed-size arrays declared inside the class.

## 5. Risk Assessment

| # | Risk | Likelihood | Impact | Mitigation |
|---|------|-----------|--------|------------|
| R1 | **Tick computation exceeds frame budget** | Low | Medium | Micro-saccade noise is 2 floats. Target scan is 8-entry linear walk. Worst case < 50 µs. Monitor in profiling pass. |
| R2 | **Event queue overflow during burst** | Medium | Low | 16-entry ring. If full, oldest dropped. New event always accepted. Under DoS-level probe rate, queue may cycle but recovers. |
| R3 | **g_creature gaze fields cause stale reads** | Low | Low | FaceEngine reads gaze after AttentionEngine.tick() each frame. If render skips a frame, gaze holds last written value — same as freeze-then-snap behaviour. |
| R4 | **IRAM_ATTR callback calls queueEvent** | Low | Low | `sec_sniffer_cb` is IRAM_ATTR. `queueEvent()` avoids flash strings, heap, and `Serial` output. Spinlock critical section is ~5 instructions — safe from WiFi task context. Mark `IRAM_ATTR` if profiling shows cache-miss latency. |
| R5 | **Float precision on ESP32-S3** | Low | Low | Single-precision FPU native. [-1.0, 1.0] with noise steps of 0.01 → 200 representable steps per axis. More than adequate for 6-pixel pupil range. |
| R6 | **millis() rollover after 49 days** | Low | Low | delta_ms computed via subtraction handles rollover (uint32_t wraparound is safe in unsigned arithmetic). Duration tracking uses `remaining_ms` countdown, not absolute timestamps. |
| R7 | **Stall recovery produces visible glitch** | Medium | Low | Spec accepts freeze-then-snap behaviour. Single noise step per missed interval avoids compounding. No sub-frame interpolation planned for Sprint 1. |
| R8 | **No TRACKING state — state machine feels binary** | Medium | Low | By design (Sprint 1 MVP). WATCHING covers both orient and sustained look. TRACKING adds smooth pursuit in Sprint 2. User may perceive the creature as "snappy" rather than smooth. |
| R9 | **Habituation without threat sensitisation** | Low | Low | Sprint 1 habituation counters track correctly but never reset by P1 events. Creature may appear to "forget" to be alert after repeated threats. Sprint 2 adds sensitisation decay. |

## 6. Implementation Order (Sprint 1)

### Step 1 — Create `AttentionEngine.h` and `AttentionEngine.cpp`
- Class skeleton with lifecycle methods (`begin`, `tick`, `pause`, `resume`)
- Event queue (lock-free ring buffer, 16 entries)
- Target table (8 slots)
- Priority resolver (linear scan)
- Decay engine (delta_ms subtraction)

### Step 2 — Wire into OS layer
- Add `#include "AttentionEngine.h"` to `AeroSnifferOS.h`
- Add `extern AttentionEngineClass AttentionEngine;`
- Add gaze fields to `CreatureState` struct
- Add global instance in `AeroSnifferOS.cpp`
- Call `AttentionEngine.begin()` in `setup()` (after EmotionEngine)
- Call `AttentionEngine.tick(delta_ms)` in `task_core1()` (before EmotionEngine)
- Subscribe 10 specific EventBus events → `AttentionEngine.queueEvent()` in `setup()`

### Step 3 — Implement state machine (3 states)
- SOFT_FOCUS — fallback when no targets
- WATCHING — entry on any P2–P4 target
- THREAT_LOCK — entry on P1 target
- State transitions per spec §3

### Step 4 — Implement gaze features
- Micro-saccade noise generator (SOFT_FOCUS only)
- Target position storage → writes `g_creature.gaze_x`, `g_creature.gaze_y`
- Blink rate generator per state → writes `g_creature.blink_request`

### Step 5 — Implement attention decay
- Decrement active target `remaining_ms` each tick
- Expiry → next-target resolution via priority scan
- Decay renewal on same-type event
- Touch-override decay extension (P1 at 50 %)

### Step 6 — Implement event handlers
- `queueEvent()` dispatch → target creation per priority
- Touch `(EVENT_TOUCH_SHORT, EVENT_TOUCH_LONG)` → P2 target at centre `(0, 0)`
- Security `(EVENT_ATTACK_DEAUTH, EVENT_ATTACK_EVILTWIN)` → P1 target at centre `(0, 0)` — threat-lock stare
- Aviation `(EVENT_FLIGHT_DETECTED, EVENT_FLIGHT_RARE)` → P3 target at `(0, 0.3)` — upward direction
- WiFi `(EVENT_WIFI_CONNECTED, EVENT_WIFI_DISCONNECTED, EVENT_WIFI_CONNECTING)` → P4 curiosity look at `(0, 0)`
- Mode `(EVENT_MODE_SWITCHED)` → P4 curiosity look at `(0, 0)`

### Step 7 — Wire FaceEngine integration
- FaceEngine reads `g_creature.gaze_x`, `g_creature.gaze_y` in `renderEmotionLayer()` instead of random `anim_look_x/y`
- FaceEngine checks `g_creature.blink_request` in `updateAnimations()` to trigger blink
- Remove `setExternalGaze()`, `requestBlink()`, `clearExternalGaze()` from FaceEngineClass
- Remove `_use_external_gaze`, `_external_gaze_x/y`, `_external_blink_request` private members

### Step 8 — Verify EmotionEngine context read interface
- AttentionEngine exposes `getActiveState()`, `getActivePriority()`, `getTargetDurationMs()`, `isHabituationSaturated()`
- No code added to `EmotionEngineClass::tick()` in this Sprint
- EmotionEngine remains sole emotion authority — AttentionEngine never calls `setEmotion()`

### Step 9 — Implement habituation stubs
- NETWORK: 60 s window, max 2
- AVIATION: 120 s window, max 1
- TOUCH: 10 s window, max 3
- SYSTEM: 30 s window, max 2
- Threat sensitisation (halve counters after P1) → Sprint 2

### Step 10 — Testing
| Test | Scenario | Expected |
|------|----------|----------|
| T1 | No events for 30 s | SOFT_FOCUS, micro-saccades active, blink ~1/5 s |
| T2 | Publish EVENT_TOUCH_SHORT | Gaze snaps to centre, WATCHING for 3 s, returns to SOFT_FOCUS |

| T9 | Consecutive P1 events | Second P1 replaces first, decay resets, gaze holds at centre |
| T10 | No FaceEngine render for 10 frames | g_creature.gaze_x/y updated each tick; next render picks up latest value |
