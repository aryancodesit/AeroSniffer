# V2.8 Render Pipeline Specification
## Subsystem Ownership & Boundaries

The AeroSniffer V2.8 render pipeline enforces strict unidirectional data flow and strict ownership boundaries across three distinct stages. Behavioral engines are decoupled and never call animation logic.

```
                  ┌─────────────────────────────┐
                  │      Behavioral Engines     │
                  │  - Reads/Writes: Creature   │
                  │  - NEVER calls FaceEngine   │
                  └──────────────┬──────────────┘
                                 ▼
┌─────────────────────────────────────────────────────────────┐
│ Stage 1: Selection (Presentation Intelligence)              │
│ - Trigger: Event-driven (state change / hold timeout / band) │
│ - Output: PresentationTarget                                │
└──────────────────────────────┬──────────────────────────────┘
                                 ▼
┌─────────────────────────────────────────────────────────────┐
│ Stage 2: Animation (Animation Intelligence)                 │
│ - Trigger: Frame-driven (tick loop at ~61Hz)                │
│ - Input: PresentationTarget                                 │
│ - Operation: Spring-damper integration, breathing, phase    │
│ - Output: AnimationPose Cache                               │
└──────────────────────────────┬──────────────────────────────┘
                                 ▼
┌─────────────────────────────────────────────────────────────┐
│ Stage 3: Rasterization (Stateless Renderer)                 │
│ - Trigger: Screen refresh cycle                             │
│ - Input: AnimationPose Cache (Read-only)                    │
│ - Operation: Draws pixels to TFT_eSprite                    │
└─────────────────────────────────────────────────────────────┘
```

## Data Contracts & Memory Layout

### 1. PresentationTarget (Stage 1 Output)
The output contract of Presentation Intelligence. This struct contains all target parameters selected based on emotion and context.

```cpp
struct PresentationTarget {
  uint8_t  eye_shape;       // PRES_EYE_DEFAULT, etc.
  uint8_t  brow_style;      // PRES_BROW_NORMAL, etc.
  uint8_t  pupil_style;     // PRES_PUPIL_NORMAL, etc.
  uint16_t color;           // Target RGB565 color
  uint8_t  anim_profile_id; // Animation speed/blink multiplier index
  int8_t   gaze_target_x;   // Target horizontal glance coordinate
  int8_t   gaze_target_y;   // Target vertical glance coordinate
};
```

### 2. EyePhysics (Stage 2 Physical State)
Encapsulates all spring-damper state variables for eye movement.

```cpp
struct EyePhysics {
  float current_x;
  float current_y;
  float vel_x;
  float vel_y;
  float target_x;
  float target_y;
};
```

### 3. AnimationPose (Stage 2 Output / Stage 3 Input)
Contains **only renderer-friendly integer values**. All floats and mathematical scaling are resolved in Stage 2.

```cpp
struct EyePose {
  int x;              // Eye center X (screen pixel)
  int y;              // Eye center Y (screen pixel, includes bounce)
  int height;         // Modulated vertical size (blink-resolved)
  int pupil_x;        // Pupil X offset within eye (from look/gaze)
  int pupil_y;        // Pupil Y offset within eye
  uint8_t shape;       // Resolved eye shape index
  uint8_t pupil_style; // Resolved pupil style index
};

struct BrowPose {
  int y_offset;       // Vertical adjustment (bounce + scale-resolved)
  uint8_t style;      // Resolved brow style
};

struct GlobalPose {
  int bounce_y;       // Sub-pixel vertical shift (bounce-resolved)
  uint16_t color;     // Interpolated RGB565 color
};

struct AnimationPose {
  EyePose left_eye;
  EyePose right_eye;
  BrowPose brow;
  GlobalPose global;
};
```

## State Transition Lifecycle

Transitions between variants or emotions are driven by an explicit `TransitionPhase` state machine:

```cpp
enum class TransitionPhase : uint8_t {
  IDLE,        // Steady state (no transition)
  ANTICIPATE,  // Squeeze eyes slightly before movement (0-50ms)
  TRANSITION,  // Shape/color interpolating (50-200ms)
  SETTLE       // Overshoot and elastic bounce back (200-300ms)
};
```

---

## Frame Contract (Event vs Frame Driven)

- **Presentation Target Selection:** Event-driven. Evaluated **only** when an emotion changes, hold timer expires, or engagement/mood crosses a boundary.
- **Animation Tick:** Frame-driven. Executed at loop rate (~30-61Hz). Uses wall-clock `micros()` dt for physics integration, decoupling animation from framerate variance. Translates floating point values into the final integer `AnimationPose` struct.
- **Rasterization:** Pure drawing. Iterates over the cached `AnimationPose` as a read-only View, using simple draw commands with zero logic.

## Animation Execution Order (within FaceEngineClass::updateAnimations)

```
1. Compute wall-clock dt from micros()
2. Update eyelid factor (engagement-based drowsiness lerp)
3. Update mood presentation (if mood or strength changed)
4. Update blink state machine
5. Advance TransitionPhase state machine (IDLE→ANTICIPATE→TRANSITION→SETTLE)
6. Compute biological breathing waveform (phase accumulator + piecewise)
7. Update emotional recovery curve (decay modifier after ALERT/ANGRY exit)
8. Compute attention-driven gaze target (focus-lock hysteresis: lock≥25, unlock<20)
9. Integrate spring-damper physics (EyePhysics: target→velocity→position)
10. Apply sub-pixel micro-drift to EyePhysics steady state
11. Resolve bounce (breathing waveform * mood amplitude)
12. Resolve pulse animation (excited/alert states only)
13. Produce AnimationPose (integer) from EyePhysics + PresentationTarget + blink/eyelid
14. Maintain backward-compat fields (anim_look_x/y, anim_bounce_y)
```

## Minimum Target Hold

The gaze target (`EyePhysics.target_x/y`) is held for a minimum of 1000ms before a new random saccade is generated during idle wander. The hold interval is modulated by engagement_drive: ~3s at 100% engagement, ~30s at 0%. This prevents rapid micro-saccades and ensures the creature appears to visually fixate before glancing elsewhere.

Desktop Observer (future mode) may override the hold interval to follow on-screen content at a faster rate.
