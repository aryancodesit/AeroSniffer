# Phase 3C — FaceEngine Gaze Integration

**Goal**: AttentionEngine state drives eye position on screen. No emotion changes, no personality, no habituation.
**Architecture freeze**: Queue is frozen. AttentionEngine state machine is frozen. Changes are additive to CreatureState and FaceEngine only.

---

## 1. Gaze Mapping

| Attention State | Gaze X | Gaze Y | Visual Effect | Rationale |
|----------------|--------|--------|---------------|-----------|
| `SOFT_FOCUS` | random(-6..6) | random(-4..4) | Idle wandering eyes | No target — creature relaxes, looks around |
| `WATCHING` | 0 | -2 | Slightly upward, alert | Curiosity — looking up at stimulus |
| `THREAT_LOCK` | 0 | 0 | Centre, dead ahead | Intense focus — locked on threat |

### Mapping applied in `AttentionEngineClass::recommendedGazeX()` / `recommendedGazeY()`

```cpp
int recommendedGazeX() const {
    switch (_state) {
        case STATE_WATCHING:    return 0;
        case STATE_THREAT_LOCK: return 0;
        default:                return 0;  // SOFT_FOCUS uses FaceEngine's random
    }
}
int recommendedGazeY() const {
    switch (_state) {
        case STATE_WATCHING:    return -2;
        case STATE_THREAT_LOCK: return 0;
        default:                return 0;  // SOFT_FOCUS uses FaceEngine's random
    }
}
```

SOFT_FOCUS returns (0,0) but FaceEngine ignores external gaze during SOFT_FOCUS and continues its existing random wandering. This preserves natural idle look without adding another timer.

## 4. Risks

### 4.1 — Visual Jitter

**Risk**: gaze_x/y updates every ~16ms (60Hz tick). Between frames, values are stable because attention state only changes on event arrival or decay. But on event arrival, gaze changes instantly.

**Mitigation**: The 60Hz render rate means gaze changes at most once per frame. X/Y delta is 0–2 pixels. This is imperceptible jitter — the eye moves smoothly within a single frame.

### 4.2 — Gaze Conflict with Emotion-Based Random Gaze

**Risk**: When SOFT_FOCUS decays from WATCHING, the existing random gaze logic may produce a jarring snap from centre to a random position.

**Mitigation**: SOFT_FOCUS gaze is already random. The transition from locked (0,0) to random is the same transition that already exists. No new visual artifact.

### 4.3 — Emotion Override

**Risk**: SURPRISED emotion renders centre pupils regardless of gaze offset. If attention is WATCHING (gaze up) while emotion is SURPRISED, the gaze is invisible.

**Mitigation**: This only affects SURPRISED emotion, which is transient (~1–2s). Not a blocker. Can be addressed in V2.5 by adding gaze offset to SURPRISED pupil rendering.

### 4.4 — Pupil-less Emotions

**Risk**: HAPPY and SLEEPY have no pupils. Gaze is invisible.

**Mitigation**: These emotions don't render pupils. Gaze offset is still tracked internally — visible the moment emotion transitions to a pupil-rendering state. Not a blocker.

### 4.5 — Phase 3C Test Interferes with Phase 3B Validation

**Risk**: If gaze integration is applied before Phase 3B validation, a gaze bug could mask an attention state bug.

**Mitigation**: Phase 3B validation is done on serial log only (no gaze). Phase 3C gaze changes are additive and don't affect the state machine. Apply in order: validate (3B) → integrate (3C).

## 5. Validation Plan (ST7789 240x240 Display)

### Visual Test 1 — SOFT_FOCUS Eye Wandering

| Step | Action | Visual Check |
|------|--------|-------------|
| 1.1 | Boot Pet mode | Eyes wander randomly (new random position every 1–4s) |
| 1.2 | Observe for 30s | Pupils move to random positions within eye white |
| 1.3 | Verify no lock | Pupils never stay in one position >4s |

| Step | Action | Visual Check |
|------|--------|-------------|

| Step | Action | Visual Check |

## 6. Recommendation

**Implement in this order:**

1. Phase 3B validation (serial-only, no gaze) — **verify state machine on hardware**
2. Add CreatureState fields (3 lines)
3. Add AttentionEngine gaze getters (12 lines)
4. Wire to CreatureState in task_core1 (4 lines)
5. Update FaceEngine to read CreatureState (8 lines)
6. Visual validation tests 1–5

Do not skip to Step 5 until Phase 3B Tests 1, 5, and 6 pass. If the state machine doesn't produce correct serial output, gaze rendering will also be wrong — and harder to debug.
