# V2.5 Sprint 4A — Creature Persistence Specification

> **Status**: Implemented (pending hardware validation)
> **Prerequisite**: Sprint 3C (Creature Brain frozen: Attention → Emotion → Mood → Face)
> **Branch**: `feature/v2.5-creature-brain`

---

## 1. Purpose

Add a Persistence Layer that gives the creature **cross-session continuity**.

The creature currently starts each boot in a blank state:

- Mood resets to RELAXED
- Touch count resets to 0
- Mood event counters reset
- No name, no history

Sprint 4A fixes this. After 4A, the creature will:

- Remember its name across reboots
- Accumulate touch and mood counters across sessions
- Know how many times it has been booted
- Track total runtime
- Store first-boot and last-seen timestamps

### What Persistence is NOT

| Not this | This is deferred to |
|----------|---------------------|
| Learned preferences | Memory Layer (V2.6+) |
| Memory recall | Memory Layer (V2.6+) |
| Relationship modeling | Behavior Layer (V2.6+) |
| Personality evolution | Memory + Behavior Layers |
| Friendship level | Memory Layer (V2.6+) |

Persistence is **record-keeping, not intelligence**.

## 2. Definitions

### Architecture Position

```
Observe
    ↓
Attention
    ↓
Emotion
    ↓
Mood
    ↓
Face

Persistence
    ↑
    │
    └── observes Attention, Emotion, Mood (counters only)
```

Persistence is an **observer subsystem**, not part of the behavioral pipeline. It executes after Mood in tick order, but it does not sit between Mood and Face — FaceEngine does not consume Persistence data. Persistence reads upstream state (Attention, Emotion, Mood) purely for counter accumulation and writes to NVS. It does not modify any upstream field.

### Tick order (unchanged)

```cpp
AttentionEngine.tick()
EmotionEngine.tick()
MoodEngine.tick()
PersistenceService.tick()   // observer, not pipeline
FaceEngine.render()
```

Persistence ticks after Mood and before Face for ordering discipline, but it is not a consumer of Face nor a provider to Face. It is a side-channel observer that happens to execute on the same tick.

### Future Architecture (post-V2.5)

```
Observe → Attention → Emotion → Mood → Face
                                              Persistence → Memory → Behavior
                                                   ↑
                                                   │
                                              observes upstream state
```

Each layer builds on the one before. Persistence is cross-session data. Memory is structured recall. Behavior is action selection. No layer reads or writes upstream fields.

## 4. CreatureProfile

```cpp
struct CreatureProfile
{
    uint32_t schema_version;

    char name[32];

    uint32_t total_boots;
    uint32_t total_runtime_minutes;
    uint32_t total_touches;

    uint32_t playful_entries;
    uint32_t anxious_entries;

    uint32_t first_boot_unix;
    uint32_t last_seen_unix;
};
```

### Field rationale

| Field | Type | Why |
|-------|------|-----|
| `schema_version` | `uint32_t` | Future migration support. Increment on any struct change. |
| `name[32]` | `char[32]` | Creature identity. Fixed-size for deterministic NVS layout. |
| `total_boots` | `uint32_t` | Incremented on each `load()` at boot. |
| `total_runtime_minutes` | `uint32_t` | Accumulated from uptime. Persisted on each `save()`. |
| `total_touches` | `uint32_t` | Incremented on each SOURCE_TOUCH. |
| `playful_entries` | `uint32_t` | Incremented on `RELAXED → PLAYFUL`. |
| `anxious_entries` | `uint32_t` | Incremented on `→ ANXIOUS`. |
| `first_boot_unix` | `uint32_t` | Set once on first boot. 0 = unknown. |
| `last_seen_unix` | `uint32_t` | Updated on each `save()`. 0 = unknown. |

### Timestamp caveat

AeroSniffer does not currently have authoritative RTC/NTP time. All timestamps default to `0` (unknown). The field types are `uint32_t` for future-proofing, but the system does not depend on them being accurate.

## 5. Save Strategy

### Rules

1. **Never save per-event.** Flash wear protection.
2. **5-minute periodic save** is the primary persistence mechanism.
3. **Mode transition save** as secondary checkpoint.
4. **Best-effort shutdown save** — not guaranteed (ESP32 has unreliable shutdown callbacks).
5. **Boot load restores from NVS.**
6. **First boot creates a default profile.**

### Schedule

| Event | Action | Notes |
|-------|--------|-------|
| Boot | `load()` | Restore from NVS. If no profile exists, `factoryReset()` |
| Every 5 min | `save()` | Writes current RAM counters to NVS |
| Mode transition | `save()` | Extra checkpoint on Pet → Security → Aviation |
| Factory reset | `save(default_profile)` | Clears and persists blank profile |
| Unexpected power loss | Accepted risk | 5-min checkpoint is the real protection |

### Boot flow

```
boot():
    _last_runtime_flush_ms = millis()
    _last_save_ms = millis()
    if NVS "creature_profile" exists:
        if !load():            // corrupt profile — start fresh
            factoryReset()
            total_boots = 1
            goto save
        total_boots++
    else:
        factoryReset()         // create default profile
        total_boots = 1
save:
    save()                     // persist incremented boot count
```

### Shutdown

```cpp
void shutdown()
{
    // Best-effort. Do not block.
    flushRuntimeMinutes();
    save();
}
```

## 6. Counter Hooks

PersistenceService increments counters by observing CreatureState. It does not subscribe to EventBus — same discipline as MoodEngine.

### Touch counter

Count from `AttentionSource == SOURCE_TOUCH`, not from raw touch hardware. This avoids the mode-specific touch routing divergence (Pet uses EventBus, Security and Aviation handle locally).

Must use rising-edge detection — `g_creature.attention.source` stays `SOURCE_TOUCH` for the full gaze duration (seconds), so sampling it every tick would overcount. MoodEngine uses the same pattern at `MoodEngine.cpp:34-37`.

```cpp
void onTouch()
{
    // rising edge: detect transition TO source == SOURCE_TOUCH
    bool currently_touch = (g_creature.attention.source == SOURCE_TOUCH);
    if (currently_touch && !_prev_was_touch_source) {
        _profile.total_touches++;
    }
    _prev_was_touch_source = currently_touch;
}
```

### Mood entry counters

Use rising-edge detection on `g_creature.mood` inside `PersistenceService::tick()`. This preserves the observer architecture — no direct calls from MoodEngine, no coupling.

```cpp
void detectMoodTransition()
{
    if (g_creature.mood != _last_seen_mood) {
        switch (g_creature.mood) {
            case MOOD_PLAYFUL: _profile.playful_entries++; break;
            case MOOD_ANXIOUS: _profile.anxious_entries++; break;
            default: break;
        }
        _last_seen_mood = g_creature.mood;
    }
}
```

Called from `tick()` before the save timer check.

### Runtime counter

Accumulate delta from last flush, not from boot. This prevents double-counting when saves accumulate overlapping intervals.

Cap the delta to guard against `millis()` overflow (~50 days). If delta exceeds a sane maximum (60 min), reset the flush marker instead of accumulating a garbage value.

```cpp
void flushRuntimeMinutes()
{
    uint32_t now_ms = millis();
    uint32_t elapsed_ms = now_ms - _last_runtime_flush_ms;
    // Guard against millis() overflow: if delta > 1 hour, assume wrap or
    // long idle and reset flush marker without accumulating.
    if (elapsed_ms > 3600000) {
        _last_runtime_flush_ms = now_ms;
        return;
    }
    uint32_t delta_minutes = elapsed_ms / 60000;
    if (delta_minutes > 0) {
        _profile.total_runtime_minutes += delta_minutes;
        _last_runtime_flush_ms += delta_minutes * 60000;
    }
}
```

### Hook placement

The hooks are called from the existing tick order:

```
AttentionEngine.tick() → EmotionEngine.tick() → MoodEngine.tick() → PersistenceService.tick() → FaceEngine.render()
```

`PersistenceService.tick()` handles the 5-minute save timer, runtime accumulation, and rising-edge mood transition detection. Touch is detected via `onTouch()` using rising-edge on `g_creature.attention.source` — no direct calls from MoodEngine, no EventBus subscription.

## 7. API

```cpp
class PersistenceService
{
public:
    void begin();          // load from Preferences or factory reset
    void tick();           // handle periodic save, runtime + mood accumulation
    void save();           // write current profile to Preferences
    void factoryReset();   // clear profile and persist defaults

    const CreatureProfile& profile() const;

    // Touch counter hook (rising-edge detection inside)
    void onTouch();

private:
    CreatureProfile _profile;
    uint32_t _last_save_ms;          // millis() of last save
    uint32_t _last_runtime_flush_ms; // millis() of last runtime flush
    MoodType _last_seen_mood;        // for rising-edge mood detection
    bool     _prev_was_touch_source; // for rising-edge touch detection

    void flushRuntimeMinutes();
    void detectMoodTransition();
};
```

### `save()` implementation

IMPORTANT: `save()` must write BOTH `"profile"` (blob) and `"schema"` (u32) keys. If `"schema"` is omitted, the next boot's `load()` will read schema_version=0 and trigger a spurious migration path.

```cpp
void PersistenceService::save() {
    Preferences p;
    if (!p.begin("creature", false)) return;
    _profile.schema_version = SCHEMA_VERSION;
    p.putBytes("profile", &_profile, sizeof(CreatureProfile));
    p.putUInt("schema", SCHEMA_VERSION);
    p.end();
}
```

### `factoryReset()` implementation

Must reset internal rising-edge detection state alongside the NVS profile to prevent stale state from causing missed or double-counted transitions after a mid-session reset.

```cpp
void PersistenceService::factoryReset() {
    _profile = CreatureProfile{};
    _profile.schema_version = SCHEMA_VERSION;
    _last_seen_mood = g_creature.mood;
    _prev_was_touch_source = false;
    save();
}
```

## 8. Schema Migration

### Rule

```text
If schema_version matches current:
    load as-is

If schema_version is unknown but migration is supported:
    migrate fields, set new version, save

Otherwise:
    factoryReset()
```

### V2.5 behavior

```text
schema_version = 1
```

No migration paths needed yet — this is the first version. The version field exists so that when V2.6 adds `focused_entries`, the migration from version 1 → 2 is deterministic.

### Migration implementation

```cpp
void migrate(uint32_t from_version)
{
    switch (from_version) {
        case 1:
            // V2.5 → V2.6 example:
            // _profile.focused_entries = 0;
            // _profile.lonely_entries = 0;
            // _profile.schema_version = 2;
            break;
        default:
            factoryReset();
            break;
    }
}
```

## 9. NVS Layout

| Key | Type | Size | Description |
|-----|------|------|-------------|
| `profile` | blob | sizeof(CreatureProfile) | Full serialized profile |
| `schema` | u32 | 4 | Schema version (redundant with struct field, but allows NVS-level check before deserialization) |

### Namespace

```
namespace: "creature"
```

### Read/write via Preferences

Use `Preferences` (the established NVS wrapper used by the entire codebase), not raw `nvs_*` API. `Preferences` provides `getBytes`/`putBytes` for blob storage.

```cpp
static constexpr uint32_t SCHEMA_VERSION = 1;

bool load(CreatureProfile& out)
{
    Preferences p;
    if (!p.begin("creature", true)) return false;

    uint32_t stored_version = p.getUInt("schema", 0);
    size_t stored_size = p.getBytesLength("profile");

    if (stored_version != SCHEMA_VERSION) {
        p.end();
        migrateWithOldData(stored_version);
        // After migration, reload
        if (!p.begin("creature", true)) return false;
        stored_version = p.getUInt("schema", 0);
        if (stored_version != SCHEMA_VERSION) {
            p.end();
            return false;
        }
        stored_size = p.getBytesLength("profile");
    }

    // Validate blob size matches expected struct size
    if (stored_size != sizeof(CreatureProfile)) {
        p.end();
        return false;
    }

    size_t actual = p.getBytes("profile", &out, sizeof(CreatureProfile));
    p.end();
    return actual == sizeof(CreatureProfile);
}
```

Note: `migrateWithOldData()` opens Preferences in read-write mode, reads the old blob, converts, writes the new blob, and updates `schema`. The `load()` function reopens after migration to verify and load the migrated data. This ensures migration has access to old data before writing the new format.

## 10. File Structure

```
AeroSniffer/
└── Persistence/
    ├── PersistenceService.h
    └── PersistenceService.cpp
```

### Why a separate directory?

Same ownership discipline that made Sprint 1–3 successful:

```
Companion/    →  AttentionEngine, MoodEngine
Persistence/  →  PersistenceService
```

Each subsystem owns its directory. No coupling.

### Arduino IDE compatibility

`PersistenceService.cpp` must be in sketch root or a recognized subdirectory. Arduino IDE compiles `.cpp` files in sketch root and `src/`. If `Persistence/` is not compiled, either:
- Place the `.cpp` in sketch root (like `MoodEngine.cpp`)
- Or configure Arduino IDE to include `Persistence/`

Recommendation: place `.cpp` in sketch root for reliability.

## 12. Counter Hook Placement

The hooks must be called from the existing tick order. The cleanest approach:

### Touch counter

Call `PersistenceService.onTouch()` from `PersistenceService::tick()` — it uses rising-edge detection on `g_creature.attention.source == SOURCE_TOUCH`, no external hook needed. Do not hook into raw touch hardware or `ae_event_callback()` — those paths differ by mode (Pet uses EventBus, Security and Aviation handle locally). Counting from `SOURCE_TOUCH` keeps PersistenceService coupled to the Creature Brain layer, not to UI input plumbing.

### Mood entry counter

Detected by rising-edge on `g_creature.mood` inside `PersistenceService::tick()`. No callbacks or external hooks. MoodEngine does not need to know PersistenceService exists.

### Runtime counter

Accumulated inside `PersistenceService::tick()` using delta from `_last_runtime_flush_ms` (same formula as §6), with a 1-hour overflow guard. Do not use `millis() - _boot_ms` — that accumulates the full uptime on every save and double-counts.

## 15. Risk Review

### Low Risk

| Item | Rationale |
|------|-----------|
| Boot counter | Deterministic increment on load |
| Runtime counter | Derived from uptime, accumulated on save |
| Touch counter | Increment-only, no interpretation |
| Mood counters | Increment-only on transition, no interpretation |
| Name storage | Fixed 32-char buffer, no formatting |

### Medium Risk

| Item | Rationale | Mitigation |
|------|-----------|------------|
| Timestamps (first/last seen) | No authoritative RTC/NTP | `0` = valid unknown value |
| Schema migration | Untested until first struct change | migration switch with factoryReset fallback |
| NVS flash wear | ESP32 NVS has ~100k write cycles | 5-min saves = ~105k writes over 1yr continuous; mode transitions add margin. Acceptable for V2.5. |

### Non-Risks

| Item | Why not a risk |
|------|----------------|
| EventBus exhaustion | PersistenceService does not subscribe |
| Spinlock contention | PersistenceService runs on Core 1 tick only, no locks |
| Cross-core writes | PersistenceService reads CreatureState, writes only its own profile memory |
| Boot delay | NVS read of ~40 bytes is sub-millisecond |
| Mood corruption | PersistenceService does not write mood or mood_strength |

## 18. Three-Bug Review

Before merging Sprint 4A:

- [ ] **Subscriber audit**: PersistenceService does NOT subscribe to EventBus. Confirm zero EventBus usage.
- [ ] **Spinlock audit**: PersistenceService runs on Core 1 tick only. No spinlock needed. Confirm no `portMUX_TYPE`.
- [ ] **Cross-core audit**: PersistenceService reads CreatureState (written by Core 0 and Core 1) — counters only. Confirm read-only access to upstream fields, no writes from interrupt context.
