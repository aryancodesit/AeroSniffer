## 1. Final Enum Definitions

### 1a. AttentionTarget

```cpp
enum AttentionTarget : uint8_t {
    TARGET_NONE    = 0,  // Idle — no focus target
    TARGET_USER    = 1,  // User interaction (touch)
    TARGET_THREAT  = 2,  // Security threat
    TARGET_FLIGHT  = 3   // Aircraft detected
};
```

**What target means**: the *thing in the world* the creature is looking at. FaceEngine maps this to pixel coordinates.

### 1b. AttentionSource — Conceptual, not event-mirrored

```cpp
enum AttentionSource : uint8_t {
    SOURCE_INTERNAL  = 0,  // Infrastructure: WiFi, mode switch, idle
    SOURCE_TOUCH     = 1,  // Physical user interaction
    SOURCE_SECURITY  = 2,  // Threat detection: deauth, evil twin
    SOURCE_AVIATION  = 3,  // Aircraft observation
    SOURCE_PORTAL    = 4   // Reserved — future Portal-triggered attention
};
```

**What source means**: the *domain* that triggered the attention. This is a conceptual category, not an event type. EmotionLayer (Sprint 2) will use source to determine emotional response (SECURITY → anxious, TOUCH → happy). Sources do NOT mirror EventType values — multiple EventTypes can map to the same source.

**Why `INTERNAL` for WiFi events**: WiFi connect/disconnect/connecting are device infrastructure events, not observations about the world. They have no external target (`TARGET_NONE`). They exist in the attention model so that future Emotion and Mood layers can sense connectivity patterns.

**Why `PORTAL` is reserved**: Future Portal interactions (user changing settings via web UI) should map to PORTAL, not TOUCH, even though both are user-initiated. They represent different domains of interaction.

### Mapping function

```cpp
static void mapEvent(EventType e, AttentionTarget& target,
                     AttentionSource& source, uint8_t& strength) {
    switch (e) {
        case EVENT_ATTACK_DEAUTH:
        case EVENT_ATTACK_EVILTWIN:
            target = TARGET_THREAT; source = SOURCE_SECURITY; strength = 100; break;
        case EVENT_TOUCH_SHORT:
        case EVENT_TOUCH_LONG:
            target = TARGET_USER; source = SOURCE_TOUCH; strength = 55; break;
        case EVENT_FLIGHT_DETECTED:
            target = TARGET_FLIGHT; source = SOURCE_AVIATION; strength = 45; break;
        case EVENT_FLIGHT_RARE:
            target = TARGET_FLIGHT; source = SOURCE_AVIATION; strength = 55; break;
        case EVENT_WIFI_CONNECTING:
        case EVENT_WIFI_DISCONNECTED:
            target = TARGET_NONE; source = SOURCE_INTERNAL; strength = 30; break;
        case EVENT_WIFI_CONNECTED:
            target = TARGET_NONE; source = SOURCE_INTERNAL; strength = 25; break;
        case EVENT_MODE_SWITCHED:
            target = TARGET_NONE; source = SOURCE_INTERNAL; strength = 20; break;
        default:
            target = TARGET_NONE; source = SOURCE_INTERNAL; strength = 0; break;
    }
}
```

## 4. Priority System (Unchanged from V2.4)

### 4a. Priority levels

```
P1 (SECURITY)  > P2 (TOUCH) > P3 (AVIATION) > P4 (INTERNAL)
```

Lower number = higher priority. Preserved verbatim from V2.4.

### 4b. Priority assignment (unchanged from V2.4)

```cpp
static uint8_t eventPriority(EventType e) {
    switch (e) {
        case EVENT_ATTACK_DEAUTH:
        case EVENT_ATTACK_EVILTWIN:    return 1;
        case EVENT_TOUCH_SHORT:
        case EVENT_TOUCH_LONG:         return 2;
        case EVENT_FLIGHT_DETECTED:
        case EVENT_FLIGHT_RARE:        return 3;
        case EVENT_WIFI_CONNECTING:
        case EVENT_WIFI_CONNECTED:
        case EVENT_WIFI_DISCONNECTED:
        case EVENT_MODE_SWITCHED:      return 4;
        default:                       return 0;
    }
}
```

### 4c. Decision matrix

```
Current Priority | Incoming Priority | Action
-----------------|-------------------|-------
none (0)         | any               | Accept — set target/source/strength
P1               | P1                | Refresh — reset strength, extend decay
P1               | P2, P3, P4        | Block — ignored
P2               | P1                | Preempt — override target/source/strength
P2               | P2                | Refresh — reset strength, extend decay
P2               | P3, P4            | Block — ignored
P3               | P1, P2            | Preempt — override target/source/strength
P3               | P3                | Refresh — reset strength, extend decay
P3               | P4                | Block — ignored
P4               | P1, P2, P3        | Preempt — override target/source/strength
P4               | P4                | Refresh — reset strength, extend decay
```

Same-priority source conflict: the last event processed wins (matches V2.4 behaviour).

## 5. Decay Implementation

### 5a. Model

Three-zone fixed-point decay. Zero floating point operations.

```
Above 50:  -25/s   (rapid initial — intensity drops as creature settles)
20–50:     -10/s   (normal watching)
Below 20:   -5/s    (slow tail — lingering before idle)
```

### 5b. Implementation

```cpp
static uint8_t computeStrength(uint8_t initial, uint32_t elapsed_ms) {
    int s = (int)initial;
    uint32_t t = elapsed_ms;

    // Zone 1: above 50, decays at 25/s
    if (s > 50) {
        uint32_t zone_ms = (s - 50) * 40;  // 1000/25 = 40ms per unit
        if (t < zone_ms) {
            s -= (int)((25 * t + 500) / 1000);
            return (uint8_t)(s < 0 ? 0 : (s > 100 ? 100 : s));
        }
        t -= zone_ms;
        s = 50;
    }

    // Zone 2: 20–50, decays at 10/s
    if (s > 20) {
        uint32_t zone_ms = (s - 20) * 100;  // 1000/10 = 100ms per unit
        if (t < zone_ms) {
            s -= (int)((10 * t + 500) / 1000);
            return (uint8_t)(s < 0 ? 0 : (s > 100 ? 100 : s));
        }
        t -= zone_ms;
        s = 20;
    }

    // Zone 3: below 20, decays at 5/s
    {
        uint32_t zone_ms = s * 200;  // 1000/5 = 200ms per unit
        if (t < zone_ms) {
            s -= (int)((5 * t + 500) / 1000);
        } else {
            s = 0;
        }
    }

    return (uint8_t)(s < 0 ? 0 : (s > 100 ? 100 : s));
}
```

### 5c. Duration table

| Initial | Priority | Total duration | Visible active (>30) |
|---------|----------|----------------|---------------------|
| 100 (SECURITY) | P1 | ~9.0s | ~5.5s |
| 55 (TOUCH) | P2 | ~7.2s | ~3.5s |
| 55 (AVIATION rare) | P3 | ~7.2s | ~3.5s |
| 45 (AVIATION) | P3 | ~6.5s | ~2.5s |
| 30 (INTERNAL) | P4 | ~5.0s | ~1.5s |
| 25 (INTERNAL) | P4 | ~4.5s | ~1.0s |
| 20 (INTERNAL) | P4 | ~4.0s | ~0.5s |

### 5d. Edge cases

- **`dt` larger than zone duration**: the function naturally handles arbitrary elapsed time because it subtracts full zone durations sequentially. If `t` exceeds the total, `s` is clamped to 0.
- **`millis()` rollover**: `elapsed_ms` is capped at 30,000 before calling `computeStrength`. Rollover produces `elapsed_ms > 30000`, triggering idle reset.
- **Zone boundary continuity**: the function returns mid-zone when `t < zone_ms`. When `t == zone_ms`, it falls through to the next zone with `s` at the boundary value. Strength is continuous — only the derivative changes.
- **Negative strength**: the final clamp handles cases where rounding causes `s < 0`.

### 6b. Tick() algorithm

**File**: `AttentionEngine.cpp:25-78`

Replace the current tick() with:

```
tick(delta_ms):
  1. Guard: if !_begun || _paused, return

  2. Drain queue (lock-free, MAX_EVENTS_PER_TICK cap preserved)
     For each event:
       - pri = eventPriority(ev)
       - if pri == 0: continue
       - if _active_priority == 0 || pri <= _active_priority:
           - mapEvent(ev, _target, _source, _initial_strength)
           - _acquired_ms = now
           - _active_priority = pri
           - if state changed: log transition

  3. Compute decay:
     if _target != TARGET_NONE:
       elapsed = now - _acquired_ms
       if elapsed > 30000:
         resetToIdle()
       else:
         _strength = computeStrength(_initial_strength, elapsed)
         if _strength == 0:
           resetToIdle()

  4. Update _state for logging:
     Derive from _target (same mapping as V2.4)
```

### 6c. New methods

void AttentionEngineClass::resetToIdle() {

## 7. FaceEngine Integration

### 7a. Principle

FaceEngine reads `g_creature.attention` but never writes to it.

AttentionEngine publishes → CreatureState stores → FaceEngine reads and renders.

### 7b. Gaze coordinate mapping (FaceEngine-owned)

```cpp
// In FaceEngineClass — new private helper:
void applyAttentionGaze() {
    if (g_creature.attention.strength == 0) {
        // SOFT_FOCUS — existing random wandering (unchanged)
        return;
    }

    // Target determines direction
    switch (g_creature.attention.target) {
        case TARGET_USER:
            anim_look_x = 0; anim_look_y = -2;  // upward toward user
            break;
        case TARGET_THREAT:
            anim_look_x = 0; anim_look_y = 0;   // centre lock
            break;
        case TARGET_FLIGHT:
            anim_look_x = 4; anim_look_y = -3;  // sky icon area
            break;
        default:
            // TARGET_NONE (P4 events) — no gaze change
            // Creature shows no visible reaction to ambient events
            return;
    }

    // Strength determines intensity
    if (g_creature.attention.strength > 80) {
        // Intense — suppress random wandering timer
        anim_look_next = millis() + 5000;
    }
}
```

### 7c. Call site

Replace lines 571–591 in `updateAnimations()` (`AeroSnifferOS.cpp`):

```cpp
// ── Attention-driven gaze ──────────────────────────────────
// FaceEngine reads target for direction, strength for intensity
if (g_creature.attention.strength > 0) {
    applyAttentionGaze();
} else {
    // SOFT_FOCUS — existing random wandering (unchanged)
    if (now > anim_look_next) {
        if (g_creature.emotion == EMOTION_CALM || g_creature.emotion == EMOTION_CURIOUS) {
            anim_look_x = random(-6, 7);
            anim_look_y = random(-4, 5);
        } else {
            anim_look_x = 0;
            anim_look_y = 0;
        }
        anim_look_next = now + random(1000, 4000);
    }
}
```

### 7d. P4 edge case — documented

When `g_creature.attention.source == SOURCE_INTERNAL` and `g_creature.attention.target == TARGET_NONE` but `strength > 0` (WiFi events, mode switches):

- **No visible gaze change.** The creature does not look toward anything because there is no target.
- The `default` case in `applyAttentionGaze()` returns without modifying `anim_look_x/y`.
- The `strength > 0` guard in `updateAnimations()` prevents SOFT_FOCUS from running, so the creature's eyes hold their current position.
- This is intentional — ambient infrastructure events should not produce visible reactions.
- Future Sprint 2 (EmotionLayer) may add a subtle micro-expression (blink rate change, ear twitch) for P4 events, but Sprint 1 explicitly does not.

- Blink animation: **unchanged**
- Bounce animation: **unchanged**
- Pulse animation: **unchanged**
- Emotion rendering (eye shapes, colours): **unchanged**
- Particle effects: **unchanged**

1. Touch (P2) → creature looks up
2. Within 2s, trigger deauth (P1)

4. Touch events during P1 are ignored
5. After P1 decays (~9s), creature returns to SOFT_FOCUS

1. Tap once → creature looks up
2. Wait 2s → strength decaying
3. Tap again
4. **Expected**: strength resets to 55, decay extends from time of second tap
5. **Pass criteria**: no snap to idle between taps, smooth continuation

### Test 5: P4 ambient events (WiFi)

1. Trigger WiFi connect/disconnect events
2. **Expected**: no visible change in creature gaze

### Test 6: Mode switch isolation
