# V2.5 Companion Architecture — Creature Brain

> **Status**: Planning
> **Prerequisite**: V2.4 stable infrastructure + visible gaze (AttentionEngine → FaceEngine)
> **V2.4 delivers**: queue, state machine, EventBus wiring, minimal gaze — frozen, working
> **V2.5 delivers**: layered intelligence where behavior *emerges* from multiple subsystems

---

## 1. Why V2.5 Is Different

### V2.4 Model (Event → State → Face)

```
Touch ──→ AttentionEngine ──→ WATCHING ──→ Face looks up
Threat ─→ AttentionEngine ──→ THREAT_LOCK ─→ Face centre
  ↓
Predictable. Machine-like. State-machine reaction.
```

Every event maps to one state, one gaze. The creature is a deterministic decoder ring. It does not *feel* alive — it responds correctly to a spec.

### V2.5 Model (Event → Brain → Emergent Behavior)

```
Touch ──→ Creature Brain ──→ ┌ AttentionTarget: User
                              ├ AttentionStrength: 80
                              ├ Emotion: Happy
                              ├ Curiosity: +10
                              ├ Energy: High
                              └ Mood: Playful
                                ↓
                              FaceEngine receives:
                                gaze_up = true
                                blink_rate = fast
                                bounce = true
                                smile = true
                                ← Emergent reaction, not a lookup table
```

Touch still resolves to "look at user." But the creature also wiggles, blinks faster, and pulls the *combination* of state into a reaction — not a switch statement.

## 2. Creature Brain Architecture

```
                        ┌──────────────────────────────────────┐
                        │           Creature Brain             │
                        │     (runs 10 Hz, Core 1)            │
                        └──┬───────┬───────┬───────┬──────────┘
                           │       │       │       │
                  ┌────────▼──┐ ┌──▼───┐ ┌──▼───┐ ┌▼────────┐
                  │ Attention │ │Emotion│ │ Mood │ │ Future  │
                  │  Layer    │ │ Layer │ │ Layer │ │ Layers  │
                  └──────┬────┘ └──┬───┘ └──┬───┘ └────┬────┘
                         │         │        │          │
                         └─────────┴────────┴──────────┘
                                           │
                                           ▼
                                  ┌────────────────┐
                                  │  CreatureState  │
                                  │ (single source  │
                                  │  of truth)      │
                                  └────────┬───────┘
                                           │
                    ┌──────────────────────┼──────────────────────┐
                    │                      │                      │
                    ▼                      ▼                      ▼
             ┌───────────┐         ┌──────────────┐       ┌───────────┐
             │ FaceEngine │         │    Portal    │       │   Sound   │
             │ (render)   │         │  (external)  │       │ (future)  │
             └───────────┘         └──────────────┘       └───────────┘
```

### Each layer publishes to CreatureState, not to each other

```
AttentionLayer.publish():
  attention_target:    enum (USER, THREAT, FLIGHT, SKY, NONE)
  attention_strength:  0–100
  attention_source:    enum (TOUCH, DEAUTH, EVIL_TWIN, FLIGHT, WIFI, INTERNAL)

EmotionLayer.publish():
  emotion:             enum (CALM, HAPPY, EXCITED, ALERT, ANXIOUS, TIRED, SAD)
  arousal:             0–100
  valence:             -100–100

MoodLayer.publish():
  mood:                enum (PLAYFUL, FOCUSED, LETHARGIC, IRRITABLE, AFFECTIONATE)
  energy:              0–100
  curiosity:           0–100
```

### FaceEngine reads the combination

```cpp
// In updateAnimations(), approx:
if (g_creature.attention_target == TARGET_USER) {
    // Look toward user (up/centre)
    anim_look_x = 0;
    anim_look_y = -2;
}
if (g_creature.attention_strength > 80) {
    // Intense — suppress blinking, narrower eyes
    anim_blink_rate = 0.5f;  // slower
}
if (g_creature.emotion == EMOTION_HAPPY && g_creature.energy > 60) {
    // Bounce + wide eyes
    anim_bounce_y = sin(frame * 0.4f) * 4;
}

// Not a switch — additive modifiers that layer naturally
```

## 3. Layer Specifications

### 3a. Attention Layer

**Responsibility**: Determine where the creature's attention is directed, how strongly, and why.

**Transitions from V2.4**:
- V2.4: `AttentionEngine` owned a single state (`WATCHING`) and dictated gaze
- V2.5: `AttentionEngine` publishes structured data; FaceEngine interprets it

| Field | Type | Range | Meaning |
|-------|------|-------|---------|
| `attention_target` | enum | `NONE`, `USER`, `THREAT`, `FLIGHT`, `SKY` | What the creature is focused on |
| `attention_strength` | uint8_t | 0–100 | Intensity of focus (0 = idle, 100 = locked) |
| `attention_source` | enum | `TOUCH`, `DEAUTH`, `EVIL_TWIN`, `FLIGHT`, `WIFI`, `INTERNAL` | What triggered the attention |

**Decay**: Strength decays by ~10/s from 100, ~5/s from 50. Steps down naturally rather than jumping from WATCHING → SOFT_FOCUS.

**Preemption preserved**: Source priority still determines which event wins (P1 threat > P2 user > P3 flight > P4 wifi). But the output is richer — FaceEngine can see *what* and *how strongly*, not just *which state*.

### 3b. Emotion Layer

**Responsibility**: Map events and internal state to emotional response.

**Inputs**:
- Attention source/strength (is user petting? is there a threat?)
- Recent interaction history (was user mean? nice?)
- Energy/curiosity levels (tired creature is grumpy)
- Time of day (sleepy at night)

**Outputs**:
- `emotion`: CALM, HAPPY, EXCITED, ALERT, ANXIOUS, TIRED, SAD
- `arousal`: 0–100 (physiological activation)
- `valence`: -100–100 (pleasure–displeasure)

**Example mappings** (not switch statements — weighted suggestions):

| Situation | Emotion | Arousal | Valence |
|-----------|---------|---------|---------|
| User touches | Happy | 60 | +80 |
| Threat detected | Anxious | 90 | -60 |
| Flight seen | Curious/excited | 50 | +40 |
| No events for 5min | Calm → Tired | 20 → 5 | +10 → -20 |
| User left for 2h | Sad | 5 | -40 |

### 3c. Mood Layer

**Responsibility**: Contextual state that persists longer than emotion (minutes to hours). Filters how emotions express.

| Mood | Character | Typical duration |
|------|-----------|-----------------|
| PLAYFUL | Bouncy, fast blinks, curious | 5–30 min after interaction |
| FOCUSED | Still, slow blinks, tracking | During flight/threat events |
| LETHARGIC | Heavy eyes, slow movement, yawns | Late night, low energy |
| IRRITABLE | Narrow eyes, quick to startle | After deauth storms, low friendship |
| AFFECTIONATE | Soft gaze, slow blinks, leans in | High friendship, calm environment |

### 3d. Future Layers (not building yet)

- **Curiosity**: Drives exploration behavior, determines how long creature watches novel stimuli
- **Energy**: Depletes over time, recharges during rest/sleep, gates playfulness
- **Memory**: NVS-backed interaction quality, preferred touch patterns, event familiarity
- **Personality**: Slow-moving traits (shy, bold, curious, lazy) that bias all other layers

## 4. Data Flow

```
Core 0 (Events)                     Core 1 (10 Hz Brain Tick)
────────────                         ──────────────────────────
WiFi deauth ──┐                     AttentionLayer.input(event)
Security      ├─EventBus─────────→   EmotionLayer.input(event)
Aviation     ┘                      MoodLayer.input(event)
Touch                               Brain.resolve()
   ↓                                    ↓
EventBus → queueEvent()           CreatureState updated
                                       ↓
                                  FaceEngine reads CreatureState
                                  Renders frame
```

### Brain.resolve() algorithm (10 Hz)

```
1. AttentionLayer.tick(dt)
   - Decay strength
   - If strength == 0, set target = NONE
   - If new event arrived, assign target + strength from priority

2. EmotionLayer.tick(dt)
   - Decay toward CALM (baseline)
   - If attention target active, compute emotion from target + source
   - Blend toward arousal matching attention_strength

3. MoodLayer.tick(dt)
   - Slow decay/transition
   - Influenced by persistent emotion + energy + time of day

4. Write CreatureState
   - AttentionLayer.publish()
   - EmotionLayer.publish()
   - MoodLayer.publish()
```

No layer reads another layer's output during resolve. Each layer reads only:
- Its own previous state
- Incoming events (consumed once)
- Global context (time of day, energy if available)

This prevents circular dependencies and keeps layers testable in isolation.

## 5. Migration Path from V2.4

### Phase 1 (Minimal — ship fastest visible change)

**Goal**: Tap → creature looks at you with richer response than V2.4 gaze

1. Add `attention_target`, `attention_strength`, `attention_source` to CreatureState
2. Evolve AttentionEngine to publish these fields instead of bare state
3. FaceEngine reads combination of target + strength + emotion

**What changes in FaceEngine**: Instead of 3-case switch on attention_state, it reads:
- `attention_target == USER` → gaze up
- `attention_strength > 50` → suppress random wandering
- `emotion == HAPPY` → bounce + wide eyes

### Phase 2 (Emergent behavior)

1. EmotionLayer resolves from attention source + strength
2. Mood layer activates (PLAYFUL after touch, FOCUSED during threat)
3. FaceEngine bounces when PLAYFUL, narrows eyes when THREAT + ANXIOUS

### Phase 3 (Future)

Curiosity, Energy, Memory layers added incrementally. Each follows the same pattern:
- One struct in CreatureState
- One tick() call in Brain.resolve()
- One FaceEngine read

## 6. Design Constraints

| Constraint | Reason |
|------------|--------|
| **No circular layer reads** | Each layer reads events + own state only at tick time |
| **No FaceEngine callbacks into Brain** | FaceEngine renders what CreatureState says — it does not push decisions back |
| **All state in CreatureState** | Portal can read it, serial can dump it, everything is observable |
| **10 Hz max brain tick** | 100ms budget is generous for a few struct assignments |
| **Attention is not special** | It is the first layer, not the only layer. V2.5 demotes it from center to subsystem |
| **No cloud dependency** | Brain runs entirely on ESP32-S3. Portal reads state but does not influence decisions |
| **Testable per layer** | Each layer accepts events and produces structs — trivial to unit test |

## 7. What NOT to Build

- **No emotion→attention feedback** (angry creature does not look away faster)
- **No memory of faces or users** (no camera, no user recognition)
- **No voice or sound** (future, not V2.5)
- **No gaze coordinates** (gaze_x/gaze_y deferred until Portal needs them)
- **No machine learning** (hand-authored response curves)
- **No personality traits** in V2.5 (future layer)

V2.5 is: Attention as structured data + Emotion from events + Mood from context. That's it.

## 8. Relationship to V2.4

```
V2.4                                      V2.5
────                                      ────
AttentionEngine state machine             AttentionLayer (one of N subsystems)
g_creature.attention_state (uint8_t)      g_creature.attention_target (enum)
                                          g_creature.attention_strength (0–100)
                                          g_creature.attention_source (enum)
EmotionEngine (reactive state machine)    EmotionLayer (tick-based, context-aware)
No mood                                   MoodLayer (persistent context)
FaceEngine: 3-case gaze switch            FaceEngine: additive modifier stack
```

V2.4 = stable foundation. V2.5 = intelligence that feels alive.

## 9. Implementation Priority

| Priority | Layer | Visible Effect | Effort |
|----------|-------|---------------|--------|
| P0 | AttentionLayer (structured data) | Tap → gaze up with intensity | Small |
| P0 | FaceEngine reads strength + target | Creature visibly reacts to intensity | Small |
| P1 | EmotionLayer resolves from attention | Creature smiles on touch, tenses on threat | Medium |
| P1 | MoodLayer | Creature stays playful for minutes after play | Medium |
| P2 | Energy/curiosity gates behavior | Creature gets tired, loses interest | Large |
| P3 | Memory/personality | Creature has preferences | Large |

**P0 + P1 is the V2.5 sprint.** P2/P3 are future.

## 10. Open Questions

- Should AttentionLayer live in a new `Brain/` directory alongside EmotionLayer and MoodLayer, or should each remain where it is (Companion/AttentionEngine.h, Companion/EmotionEngine.h)?
- Does EmotionLayer replace EmotionEngine, or wrap it? (Current EmotionEngine is reactive; V2.5 EmotionLayer would be tick-based)
- How does the MoodLayer persist across mode switches (Pet ↔ Security ↔ Aviation)? Shared CreatureState persists; mood just continues ticking regardless of active mode.

These are design decisions, not blockers. All paths converge on the same architecture.
