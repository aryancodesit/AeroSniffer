# V2.5 Sprint 3 — Mood System Specification

> **Status**: Planning
> **Prerequisite**: Sprint 1–2B (Attention Layer stable, shim removed)
> **Branch**: `feature/v2.5-creature-brain`

---

## 1. Purpose

Add a Mood Layer that sits above Attention and Emotion. Mood answers:

> How does the creature generally feel over time?

Not as a reaction to a single event (that's Emotion), but as a persistent context that filters how the creature expresses itself across minutes to hours.

---

## 2. Definitions

### Timescales

| Layer | Timescale | Example |
|-------|-----------|---------|
| **Attention** | Seconds | "I see a threat" → strength 100, decays in ~15s |
| **Emotion** | Minutes | "I'm excited from that tap" → lasts ~2 minutes |
| **Mood** | Hours/days | "I've been lonely all morning" → persists across modes |

### Mood is derived state, not control

```
Attention → input
Emotion   → input
Mood      → derived state (observes, does not command)
```

Mood must NOT:

- Change gaze direction (FaceEngine owns gaze)
- Change attention targets (AttentionEngine owns target)
- Publish EventBus events (EventBus is for transport, not mood broadcast)
- Override emotion transitions (EmotionEngine owns emotion)

Mood MAY:

- Influence blink rate, bounce magnitude, animation intensity (via FaceEngine read)
- Appear in telemetry (Portal reads `g_creature.mood`)

---

## 3. Ownership Matrix

| Behavior | Owner | Constraint |
|----------|-------|------------|
| Gaze direction | FaceEngine | Reads attention.target, not mood |
| Attention target | AttentionEngine | No mood influence |
| Attention strength | AttentionEngine | Decay driven by time, not mood |
| Emotion transitions | EmotionEngine | Can be biased by mood (rate only) |
| Mood transitions | **MoodEngine** | New — tracks slowly |
| Gaze animation (blink, bounce) | FaceEngine | May read mood as modifier |
| Telemetry/analytics | Portal/Cloud | Read-only |

### What MoodEngine owns

```
CreatureState.mood
CreatureState.mood_strength
CreatureState.mood_since (timestamp, optional)
```

### What MoodEngine does NOT own

- EventBus subscription (it observes via CreatureState, not events)
- Gaze coordinates
- Emotion state machine
- Attention targets

---

## 4. Inputs

Mood reads from CreatureState after Attention and Emotion have published. It does not read raw events.

| Input | Source | Effect on Mood |
|-------|--------|----------------|
| `emotion` | EmotionEngine | Happy → lifts mood. Sad/anxious → lowers mood. |
| `focus_accumulator` | MoodEngine (internal) | Tracks cumulative seconds with attention.strength > 50. Accumulator crosses threshold → FOCUSED mood. Prevents short attention bursts from flickering mood. |
| `attention.source` | AttentionEngine | Threat source → anxious mood. Touch → playful mood. |
| `interactions_today` | CreatureState | Low → lonely. High → social. |
| `friendship_level` | CreatureState | High → affectionate baseline. Low → guarded baseline. |
| `uptime_minutes` | CreatureState | Long uptime → tired.

### Non-inputs (explicitly excluded)

- Raw EventBus events (Mood observes derived state only)
- WiFi RSSI, signal strength (too noisy)
- Touch duration, tap count (Emotion layer responsibility)

---

## 5. Persistence

| Scope | Storage | Behavior |
|-------|---------|----------|
| Current mood | `CreatureState.mood` (RAM) | Volatile — resets on reboot |
| Mood strength | `CreatureState.mood_strength` (RAM) | Volatile — resets on reboot |
| History | NVS (future) | Not in V2.5 |

**Decision**: RAM-only for V2.5. The creature starts each session in a neutral mood and builds from there. NVS-backed mood history is a Memory Layer concern.

**Mode switch**: Mood persists across mode transitions (Pet ↔ Security ↔ Aviation). It is part of CreatureState, which lives outside the mode lifecycle. No pause/resume needed — Mood simply continues ticking regardless of active mode.

---

## 6. Decay Model

Mood drifts toward neutral (CALM/RELAXED) over time. Recovery is slower than emotion decay.

| Mood | Decay to neutral | Trigger to enter |
|------|------------------|-----------------|
| PLAYFUL | ~30 min without interaction | Multiple touches, happy emotion |
| FOCUSED | ~15 min without threat/flight | Prolonged high attention strength |
| ANXIOUS | ~20 min without threats | Threat events, alert emotion |
| LONELY | ~60 min with interaction | Low interactions_today |
| AFFECTIONATE | ~45 min without touch | High friendship + touch events |
| TIRED | Resets on reboot or ~2h idle | Long uptime, sleepy emotion |

Decay algorithm:

```
if (mood_strength > 0) {
    // Fixed-point decay, ~1 strength unit per 2–5 minutes
    // Exact rate depends on mood type
    uint32_t elapsed = now - last_mood_change;
    uint32_t decay_interval = moodDecayInterval(current_mood); // 120000–300000 ms
    uint8_t decay_units = elapsed / decay_interval;
    mood_strength = (decay_units >= mood_strength) ? 0 : mood_strength - decay_units;
}
```

No floating point. Same fixed-point discipline as AttentionEngine's `computeStrength()`.

---

## 7. Event Flow

```
Core 1 (10 Hz Brain Tick)
──────────────────────────

1. AttentionEngine.tick()
   - Drain queue, decay strength, publish to CreatureState

2. EmotionEngine.tick()
   - Decay emotion, process inputs, update CreatureState

3. MoodEngine.tick()
   - Read CreatureState (emotion, attention, metrics)
   - Decay current mood toward neutral
   - If input conditions trigger a mood shift, transition
   - Write CreatureState.mood + mood_strength

4. FaceEngine.render()
   - Read CreatureState (emotion, attention, mood)
   - Render eyes, blink, bounce, etc.
```

### MoodEngine does not process events

Unlike AttentionEngine (which drains an MPSC queue) and EmotionEngine (which subscribes to EventBus), MoodEngine reads **already-published state**. This is by design — Mood is a slow observer, not a real-time responder.

## 8. Mood Types (Initial Set)

| Mood | Character | Entry trigger | Decay to neutral |
|------|-----------|--------------|-----------------|
| `MOOD_RELAXED` | Baseline. Neutral blink, soft gaze. | Default on boot, or no triggers for 30+ min. | N/A (neutral state) |
| `MOOD_PLAYFUL` | Faster blink, bounce amplification. | 2+ touches in 5 min + happy/excited emotion. | 30 min without touch. |
| `MOOD_FOCUSED` | Slow blink, reduced random wandering. | Internal `focus_accumulator` exceeds threshold (>60s cumulative with attention.strength > 50). | 15 min without threat/flight. |
| `MOOD_ANXIOUS` | Faster blink, narrower eyes. | Threat event (ATTACK_DEAUTH/EVIL_TWIN) + alert emotion. | 20 min without threats. |
| `MOOD_LONELY` | Slow, sad blink. Reduced bounce. | No touch for 60+ min + interactions_today < 3. | 5 min after touch interaction. |
| `MOOD_AFFECTIONATE` | Very slow blink, soft gaze. | Touch + love/happy emotion + friendship > 50. | 45 min without touch. |
| `MOOD_TIRED` | Heavy eyes, yawn animation. | Uptime > 4 hours + sleepy emotion + no recent interaction. | Resets on reboot. |

---

## 9. Mood Arbitration Rules

Multiple moods can become simultaneously valid (e.g., high friendship + touches → AFFECTIONATE, but uptime > 4h → TIRED). MoodEngine resolves conflicts via **fixed priority**.

| Priority | Mood | Rationale |
|----------|------|-----------|
| 1 (highest) | `MOOD_ANXIOUS` | Safety-relevant — threat response must not be masked |
| 2 | `MOOD_TIRED` | Physiological — reflects device state, not interaction |
| 3 | `MOOD_AFFECTIONATE` | Bond-driven — requires high friendship + touch history |
| 4 | `MOOD_PLAYFUL` | Interaction-driven — recent touch + happy emotion |
| 5 | `MOOD_FOCUSED` | Attention-driven — cumulative focus, not urgent |
| 6 | `MOOD_LONELY` | Absence-driven — only active when no other trigger fires |
| 7 (lowest) | `MOOD_RELAXED` | Default — active when no other mood qualifies |

### Arbitration logic

```
for each mood (highest priority first):
    if entry_condition is met AND mood_strength > 0:
        adopt this mood
        break
```

This is a simple first-match loop. No scoring, no weighting, no floating point.

### Transition Rule

Mood transitions only go **upward** in priority once a higher-priority mood has been active for ≥30s. If a higher-priority mood's entry condition is met for <30s, it is ignored — preventing brief threat spikes or short uptime crossings from yanking the creature's mood.

Exception: `MOOD_RELAXED` (priority 7) can be displaced by any qualifying mood immediately. It is the absence of any other signal.

## 10. Validation Plan

### Hardware Tests

| Test | Procedure | Expected |
|------|-----------|----------|
| Pet mode idle | Boot, leave untouched for 10 min | Mood drifts from RELAXED toward LONELY after 60 min |
| Pet mode touch | Tap 3 times in 5 min | Mood shifts from RELAXED → PLAYFUL |
| Security threat | Trigger deauth | Mood shifts toward ANXIOUS |
| Mode switch | Pet → Security → Aviation → Pet | Mood persists across transitions, continues decaying |
| Long idle | Leave in Aviation with no flights for 2h | Mood drifts toward TIRED |
| Reboot | Power cycle | Mood resets to RELAXED |

### Three-Bug Review

Before merging Sprint 3:

- [ ] **Subscriber audit**: MoodEngine does NOT subscribe to EventBus. Confirm zero EventBus usage.
- [ ] **Spinlock audit**: MoodEngine runs on Core 1 tick only. No spinlock needed. Confirm no `portMUX_TYPE`.
- [ ] **Cross-core audit**: MoodEngine reads CreatureState (written by Core 0 and Core 1). Confirm read-only access, no writes from interrupt context.
- [ ] **Ownership audit**: Confirm Mood does not write attention.target, attention.strength, or emotion. Confirmed by grep before merge.
- [ ] **Co-dependency check**: If MoodEngine depends on a value that EmotionEngine depends on MoodEngine for → STOP. Circular dependency detected.

## 11. Implementation Plan

### Phase 1 — MoodEngine skeleton (minimal)

1. Add `MoodType` enum to `AeroSnifferOS.h` (7 mood types)
2. Add `mood` and `mood_strength` fields to `CreatureState`
3. Create `MoodEngine.h` / `MoodEngine.cpp` in `Companion/`
4. Implement `tick()`: read CreatureState, decay current mood, write back
5. Wire `MoodEngine.tick()` into `task_core1()` after EmotionEngine

### Phase 2 — FaceEngine reads mood

1. In `FaceEngineClass::updateAnimations()`:
   - `MOOD_PLAYFUL` → amplify bounce
   - `MOOD_TIRED` → slow blink
   - `MOOD_ANXIOUS` → faster blink
   - `MOOD_AFFECTIONATE` → softer gaze
2. Gaze direction remains driven by attention.target — mood modifies animation, not gaze

### Phase 3 — Portal telemetry (read-only)

1. Expose `g_creature.mood` in serial telemetry
2. Portal displays current mood (no control)

### Non-goals (explicitly excluded)

- Mood does not persist across reboots (V2.5)
- Mood does not influence attention priority (V2.5)
- Mood does not change emotion transitions directly (V2.5 — may bias rate in future)
- Mood does not have its own EventBus subscriptions
