**Date:** 2026-07-03
**Status:** Planning
**Theme:** Digital Footprint / Privacy Assistant
**Pipeline Slot:** Observe → Act → Cloud (Privacy = Act/Analyze bridge)

---

## 1. Core Concept

The Privacy Intelligence Layer transforms AeroSniffer from a passive network observer into an interactive privacy advisor. The device already observes WiFi environment (deauth packets, AP beacons, device probes). V2.9 adds a privacy scoring engine that analyzes this raw data and surfaces actionable privacy insights through the Portal and Companion app.

**Preserved architecture triad:**
- **Device = Observe** — Sniffer, deauth detection, probe monitoring (unchanged)
- **Portal = Act** — Privacy dashboard, recommendations, opt-out actions
- **Cloud/App = Analyze** — Companion app privacy timeline, cross-session trends

## 3. Sprint 1 — Privacy Engine

### 3.1 New Files

| File | Purpose |
|------|---------|
| `AeroSniffer/Security/PrivacyEngine.h` | PrivacyEngine class declaration |
| `AeroSniffer/Security/PrivacyEngine.cpp` | Scoring, fingerprint classification, recommendations |

### 3.2 Scoring Model

| Signal | Source | Weight | Privacy Score Impact |
|--------|--------|--------|---------------------|
| **Deauth packets** | WiFi Sniffer | 0.35 | Detected active attack → high severity |
| **Unknown device count** | ThreatEngine | 0.20 | Many unknown devices → medium concern |
| **Evil twin APs** | EvilTwin | 0.25 | Cloned AP detected → critical |
| **Open WEP/WPA networks** | Sniffer beacon scan | 0.10 | Weak encryption nearby → low concern |
| **Probe requests** | Sniffer | 0.10 | Device broadcasting past SSIDs → medium |

All weights sum to 1.0. Privacy score = `100 - weighted_sum × 100` where 100 = pristine, 0 = compromised.

### 3.3 Memory Domain

Extend MemoryEngine domain enum with `DOMAIN_PRIVACY` (domain index 5).

| Subtype | Description |
|---------|-------------|
| `PRIV_SCAN` | Passive scan event |
| `PRIV_DEAUTH` | Deauth detected |
| `PRIV_EVIL_TWIN` | Evil twin AP |
| `PRIV_PROBE` | Probe request observed |
| `PRIV_ADVICE` | Recommendation issued |

### 3.4 Integration Points

| Hook | Location | Behavior |
|------|----------|----------|
| `Sniffer::onPacket()` | After deauth classification | Fire `EVENT_PRIVACY_DEAUTH` on EventBus |
| `ThreatEngine::tick()` | After device classification | Accumulate unknown device count → PrivacyEngine |
| `EvilTwin::tick()` | After twin detection | Fire `EVENT_PRIVACY_EVIL_TWIN` |
| `Mode2_Security::loop()` | After security tick | Call `PrivacyEngine::tick()` |
| `Portal::handleRequest()` | On `/api/privacy` route | Return privacy JSON |

### 3.5 EventBus Additions

| Event | Payload |
|-------|---------|
| `EVENT_PRIVACY_ALERT` | `{score: uint8_t, severity: SEVERITY}` |
| `EVENT_PRIVACY_DEAUTH` | `{mac: uint8_t[6], count: uint16_t}` |
| `EVENT_PRIVACY_EVIL_TWIN` | `{bssid: uint8_t[6], ssid: string}` |

### 3.6 Portal API Routes

| Route | Method | Response |
|-------|--------|----------|
| `/api/privacy/score` | GET | `{score: 87, category: "good", timestamp: 12345}` |
| `/api/privacy/threats` | GET | `[{type: "deauth", severity: 3, ...}]` |
| `/api/privacy/recommendations` | GET | `[{text: "Disable WiFi SSID broadcast", priority: "high"}]` |
| `/api/privacy/settings` | GET/POST | `{notify_on_deauth: true, auto_scan: true}` |

## 9. Architecture Decision Records

### ADR-009: Privacy Intelligence as V2.9 Theme

**Status:** Proposed

**Context:** The Observe→Act→Cloud triad is fully populated at V2.8. The device observes (Sniffer, ThreatEngine), the Portal acts (security dashboard), and the Companion app analyzes (serial data). However, there is no dedicated privacy layer that transforms raw network observations into actionable privacy recommendations.

**Decision:** Implement Privacy Intelligence as a new engine in the Security/ module, with scoring, memory domain, and Portal dashboard. This extends the existing Security mode rather than creating a fourth mode.

**Consequences:** Privacy data is available in all modes (cross-mode persistence). The MemoryEngine gets a 6th domain. Portal API grows by 4 routes. No changes to Aviation or Companion mode internals.

### ADR-010: EventBus Capacity Increase

**Status:** Proposed

**Context:** Current MAX_SUBSCRIBERS=32. Runtime shows 38 subscribers. V2.9 adds 3-4 more (PrivacyEngine, Portal privacy routes).

**Decision:** Increase MAX_SUBSCRIBERS to 48. This is a fixed-array increase with no heap impact (48 × 8 bytes = 384 bytes RAM).

**Consequences:** 384B additional RAM consumption. Headroom for 10 more future subscribers. No API changes.
