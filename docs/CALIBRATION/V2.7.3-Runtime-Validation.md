# V2.7.3 Runtime Validation Protocol

## 1. Test Objective

Determine whether the firmware continues executing after serial logging stops, using only existing observable behavior (display animation, touch response, mode switching). No firmware modifications permitted -- calibration freeze maintained.

**Duration justification:**

| Evidence | Stop Time |
|---|---|
| B1_002 | ~18 min |
| B1_003 | ~10.7 min |
| **45-min target** | **2.5x the observed max** |
| M8/M9 soak | 30 min |

45 min = 2.5x the longest observed serial interruption, providing clear margin for all 30-min calibration soaks.

## 2. Success/Failure Criteria

| Outcome | Condition | Interpretation |
|---|---|---|
| PASS | Serial stops at any point; display animating on return | No evidence of firmware failure during the observation window |
| PASS | Serial logs continuously for full 45 min; display animating | No failure reproduced; platform stable for full duration |
| FAIL | Display frozen (>30s identical pixels) AND touch unresponsive | Runtime appears halted; investigation required |
| PARTIAL | Display frozen but touch responsive | Display subsystem may have stalled; render loop hang suspected |
| FAIL | Serial running but display frozen AND touch unresponsive | Firmware halted despite serial output (unlikely but disqualifying) |
| INCONCLUSIVE | Display state at return cannot be determined | Environmental issue; repeat with corrected setup |

## 3. Observation Hierarchy

If serial stops, check in this order -- each rules out a deeper failure mode:

1. **Display animation** -- Primary indicator. Pet face should blink or change expression. If animating, Core 1 render loop is alive.
2. **Touch response** -- Tap the sensor. If display reacts, interrupt handling and event pipeline are intact.
3. **Mode switching** -- Long-press touch (>=1.5s). If display transitions to mode splash screen, the full state machine is alive.
4. **Serial (if still running)** -- Heartbeat + calibration stamps confirm subsystem health. Secondary indicator only.

## 4. Observation Checklist

### Before departure (t=0)

- [ ] Power board, confirm boot completes
- [ ] Confirm serial monitor is capturing (timestamps advancing, heartbeat visible)
- [ ] Photograph the display (phone photo with timestamp)
- [ ] Note current face expression, eye state, animation (blink rate, color)
- [ ] Interact once (tap) to confirm touch responsiveness visually
- [ ] Do not touch again -- walk away

### On return (t >= 45 min)

- [ ] Photograph the display immediately (before touching anything)
- [ ] Check serial monitor -- still capturing or stopped?
- [ ] If serial stopped, note the last timestamp
- [ ] Is the display animating? (Eyes blinking? Expression changing?)
- [ ] Compare with departure photo -- same or different expression?
- [ ] Tap the touch sensor -- does the display respond?
- [ ] If touch responsive, attempt mode switch (long-press >=1.5s)
- [ ] Save the full serial log immediately (before closing monitor)

## 5. Artifact Naming

```
docs/CALIBRATION/runtime/V2.7.3_RV_001.log
```

Separate directory from calibration artifacts. Run counter: `RV_001`, `RV_002`, etc.

## 6. Decision Matrix

| Serial Log | Display on Return | Touch Response | Verdict |
|---|---|---|---|
| Stopped | Animating | Responsive | **PASS** -- no evidence of firmware failure during observation window |
| Running | Animating | Responsive | **PASS** -- no failure reproduced; platform stable for full duration |
| Stopped | Frozen | Unresponsive | **FAIL** -- runtime appears halted; investigation required |
| Stopped | Frozen | Responsive | **PARTIAL** -- display subsystem stall; further isolation needed |
| Running | Frozen | Unresponsive | **FAIL** -- firmware halted despite serial output |

## 7. Campaign Sequencing

```
[1] B1 complete (all 3 runs collected, variance analysis follows)
[2] RV_001 (45 min)
      -> PASS: proceed to M8, M9
      -> FAIL: halt calibration, investigate USB/power/hardware
      -> PARTIAL: isolate display subsystem before proceeding
[3] M8, M9 (30 min each)
[4] RV_002 (overnight, camera-recorded)
[5] Phase 3.4 memory soak (12 h)
```
